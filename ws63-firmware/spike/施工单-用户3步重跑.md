## 第 1 步（10 秒）：腾出串口 + 让两块板冷启动

1. 关掉 MobaXterm / BurnTool / 任何开着 COM14、COM15 的窗口——串口一次只能被一个程序占用。
2. 两块板各拔插一次 USB（或各按一次复位键）。

自查：下面这条应该列出 **两条** CH340：

```bash
powershell.exe -NoProfile -Command "Get-CimInstance Win32_PnPEntity | Where-Object { \$_.DeviceID -like '*VID_1A86*' } | Select-Object Name,DeviceID | Format-Table -AutoSize"
# → USB-SERIAL CH340 (COM15)  = 板 A（主）
# → USB-SERIAL CH340 (COM14)  = 板 B（从）
```

## 第 2 步（约 1 分钟）：烧两块板

在 WSL 里敲（`tools/ws63flash-port.exe <包> app <端口> <日志路径>`；第 3 个参数才是端口——
仓库里 `ws63-firmware/flasher/ws63flash.exe` 把端口写死成 COM14，用它烧板 A 会去跟板 B 说话）：

```bash
cd /mnt/c/Users/Administrator/Desktop/HMProgram

./tools/ws63flash-port.exe 'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\spike\out\SPIKE_MASTER.fwpkg' app COM15 \
  'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\spike\logs\rerun-flash-master-COM15.txt'

./tools/ws63flash-port.exe 'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\spike\out\SPIKE_SLAVE.fwpkg'  app COM14 \
  'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\spike\logs\rerun-flash-slave-COM14.txt'
```

自查（防烧反，两条都要成立）：退出码 0；且

```bash
grep -c 'SPIKE-ROLE=MASTER' ws63-firmware/spike/logs/rerun-flash-master-COM15.txt   # → 1
grep -c 'SPIKE-ROLE=SLAVE'  ws63-firmware/spike/logs/rerun-flash-slave-COM14.txt    # → 1
```

## 第 3 步（约 2 分钟）：抓 90 秒两端串口原文，然后判读

一条一条跑（`-Reset` 会拉 RTS=EN 让两块板同一秒冷启动；不 -Reset 会踩坑：从端带着上一轮的
连接状态继续跑，永远不重新 `TARGET FOUND`）：

```bash
cd /mnt/c/Users/Administrator/Desktop/HMProgram

powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/serial-capture.ps1 -Port COM15 -Baud 115200 \
  -Seconds 90 -Out 'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\spike\logs\rerun-master-COM15.log' -Reset -Quiet

powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/serial-capture.ps1 -Port COM14 -Baud 115200 \
  -Seconds 90 -Out 'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\spike\logs\rerun-slave-COM14.log' -Reset -Quiet
```

判读（脚本把三条判据算成代码，退出码 0=通过 / 1=不通过）：

```bash
python3 tools/spike-check-notify.py ws63-firmware/spike/logs/rerun-master-COM15.log \
                                   ws63-firmware/spike/logs/rerun-slave-COM14.log --seconds 90
```

自查：把上面这条命令的**完整输出**回传即可，其中要找的是从端最后一行
`[SPIKE-CLI] STAT(...) rx=.. lost=0 dup=0 ...`；出现 `!! GAP` / `!! OUT-OF-ORDER` 一律回传原文。

> 这一版从端还多打了一个 `link=%u` 字段（`alive … link=1` 才代表"固件认为连上了"），
> 正好用来区分「没连上」和「连上了但主端没发」。

## 收工（测完再做）：把两块板恢复原样

```bash
# 板 A ← 仓库里的生产固件（不要用 SDK 输出目录里的那份，冒烟构建会覆盖它）
./tools/ws63flash-port.exe 'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\output\ws63-liteos-app_all.fwpkg' app COM15 \
  'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\spike\logs\rerun-restore-master-COM15.txt'

# 板 B ← 厂家原版 XF AT 救砖包
./tools/ws63flash-port.exe 'C:\Users\Administrator\ws63-tools\fw\xfat-rescue.fwpkg' app COM14 \
  'C:\Users\Administrator\Desktop\HMProgram\ws63-firmware\spike\logs\rerun-restore-slave-COM14.txt'
```

开机自证：板 A 应该打 `[SLE-HUB] registering callbacks`、**全文 0 处 `SPIKE`**；
板 B 应该打 `I (95)-xf_at: >> XF AT <<`。
