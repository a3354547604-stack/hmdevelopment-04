# 界面重做与验证（t150：面向普通用户，手机号登录）

面向读者的界面口径来自 `docs/技术/App界面与文案规范.md`（t147 定稿）。本文只记「改了什么、
怎么验证、哪些还没验证」，不重复规范全文。

> 数字口径（D11）：HAP 记「体积 + 提交号」，**不**用 sha256 当防伪（zip 内嵌构建时间戳，
> 跨次构建哈希必然不同）。自检项数、探针通过数是随代码变化的量，引用时都要带提交号。

## 1. 一句话结果

五个页面全部按规范重做：**三个页签（首页 / 提醒 / 我的）+ 添加设备 4 步向导 + 最近的情况**，
登录改成**手机号 + 密码**，界面上的服务器地址、接口路径、契约条款、事件类型代码全部消失

## 2. 改了什么（按用户看到的顺序）

| 位置 | 之前 | 现在 | 为什么 |
|---|---|---|---|
| 登录页 | 「用户名 / 密码」，示例账号 `daughter01` | 「手机号 / 密码」，11 位数字校验；注册页 = 手机号 + 密码 + 确认密码 | 家属记不住用户名；手机号就是账号（服务器 `username` 字段直接存手机号，服务端零改动） |
| 登录页底部 | 「离线演示模式：daughter01 / P@ssw0rd!」 | 只在离线演示时提示 `13800000000`（演示账号） | 演示账号换成手机号，避免两套口径 |
| 底部页签 | 首页 / 告警 / 报表 / 设置（4 个） | **首页 / 提醒 / 我的**（3 个） | 「报表」不是高频动作，移到首页入口；「设置」对老人家属是黑箱，改成「我的」 |
| 首页第一屏 | 顶部一行小字显示设备名与模式；下面 4 张传感器卡 | **大字卡：「爸妈今天一切都好」**（异常时「有紧急情况」/「爸妈那边有 N 条提醒」）；下面三张房间卡（厨房/卧室/门厅） | 子女打开 App 只想知道「今天有没有事」，技术指标排在后面 |
| 提醒列表 | 「全部 / 待处置 / 已读 / 已处置」四个筛选 | 「全部 / 还没处理」两个；单行显示「谁 + 什么 + 时间」 | 四个筛选里有两个是运营概念，家属只用得上「还有没有没处理的」 |
| 提醒详情 | 底部 4 个动作（已电话联系/已上门查看/这是误报/其它情况），顶部信息行含「重推次数」「设备侧恢复」 | 「我知道了」（关闭）与「已经处理了」→ 四个原因（已联系/已上门/误报/其它）+ 备注选填 | 用户不需要知道重推机制；「我知道了」是已读，「已经处理了」才是处置 |
| 报表页 | 页签内，三个周期（今日/本周/本月），标题带「活动量（本周）」「汇总」、底部有「接口：GET /api/reports/…」 | 首页入口「这段时间的情况」，两个周期（**这周 / 这个月**），只说「在家走动 N 次」「N 条提醒 / 还没处理 / 误报」 | 今日 24 小时分布对家属价值最低；接口路径不该出现在用户界面 |
| 设置页 | 「告警阈值」21 个滑杆 + 「演示与调试」（演示事件、接口自检、健康检查） | **删除**。普通用户不需要调阈值 | 阈值是安装/维护动作，放进「我的 → 关于 → 连点版本号 5 次」的高级区 |
| 我的页（新） | — | 家人 / 添加设备 / 手机提醒 / 账号（改密码、退出）/ 关于（版本连点 5 次出高级：服务器地址、离线演示开关） | 规范 §4：高频项在上，维护项藏起来 |
| 添加设备（新） | 配网页把「网关地址 / IoTDA 三件套 / 步骤 1–5」堆在一页 | **4 步**：① 连小盒子 Wi-Fi（显示热点名 + 连不上三步对策）② 选家里 Wi-Fi（缓存列表下拉，空则手输）③ 正在连接 ④ 完成了（显示将回连的 SSID） | 规范 §5；云凭据移到部署阶段（P1），界面不出现「IoTDA / 密钥」 |

## 3. 界面之外的两处结构调整

1. **服务器地址可配置**：`common/RuntimeConfig.ets`（新）优先读持久化值，否则用
   `AppConfig.SERVER_BASE_URL = http://123.206.99.28/api`；界面上只在高级区可见。
   `ServiceHub` 每次取实例按当前值拼 URL，改地址后 `invalidate()` 作废旧实例。
2. **登录态切换要重建界面**：`SessionStore` 在登录/退出/换绑设备时递增 `authSeq`，
   `Index` 用 `@StorageProp(KEY_AUTH_SEQ) @Watch` 重建——否则退出登录后会停在首页。

## 5. 构建与 HAP（构建窗口内执行）

`tools/build-lock.sh bash harmony-app/tools/build-hap.sh`（槽 1）。**两轮**：

- **第 1 轮：失败（真红，按预期暴露问题）**。自证段正常报红（`hvigor rc=255`、`BUILD FAILED`、
  注入的 `Cannot find name 'NOT_DEFINED_CONST_FOR_GATE_PROBE'`），正式阶段 5 条 ArkTS 错误，原文：
  ```
  ArkTS:ERROR File: .../pages/HomePage.ets:199:52  Property 'PLACEHOLDER' does not exist on type 'typeof AppTheme'.
  （同 212:56 / 236:23 / 356:74）
  ```
  原因：占位符 `'--'` 在 t147 拆分字面量时从 `AppTheme` 移到了 `LiteralConstants`，
  我新写的首页还在引用旧位置。改法：`AppTheme.PLACEHOLDER` → `LiteralConstants.PLACEHOLDER` 并补 import。
- **第 2 轮：通过**。`BUILD SUCCESSFUL in 19 s 460 ms`、`正式构建 hvigor rc=0`、
  产物 **991254 bytes**、`mtime(epoch)=1792506155 ≥ 构建起始 1792506135`（本轮产出，不是旧包）。
  自证段仍为红（`ArkTS 错误=2 处`），说明「失败能被抓住」这条门禁本身是活的。
  唯一 WARN：`RegisterPage.ets:18:1 It's not a recommended way to export struct with @Entry`
  —— 只是 preview 模式的建议，不影响 HAP 构建。


## 6. 未验证边界（诚实清单）

1. **没有真机/模拟器渲染**：本机无 `hdc`、`/dev/kvm` 不可写。所有界面只在编译层与自检层验证过，
   实际字体/间距/深色模式下的观感需要用户在 DevEco 模拟器或真机上确认。
2. **没有连真服务器**：界面默认打 `http://123.206.99.28/api`，本次验证用的是 Mock 传输层；
   真机联网、AGC 推送、跨天数据都没测。演示账号 `13800000000 / demo-pass-123` 由用户在公网
   服务器上验证过登录，本仓库侧未复跑。
3. **手机提醒开关只保存偏好**：没有实现推送（推送需要 AGC + push token，契约 §6.19 已留白），
   所以页面上写的是「有情况时会在 App 里提醒你」，**没有**写「已开启推送」。
4. **修改密码是诚实提示**：服务器 `server/app/routers/auth.py` 只有 register/login/me，没有改密
   接口 → 页面告诉用户「需要在管理员后台改」，不做假成功。
5. **添加设备走的是 Mock**：网关热点 `192.168.2.1` 与 `/api/scan` 缓存列表在 Mock 里是假数据
   （3 个 SSID）；真机配网需按 `deliverables/08-配网四步实现与验证.md` §8 的边界复跑。
6. **阈值页删除后没有替代入口**：普通用户不能再改阈值（这是刻意的），安装/维护要走高级区或
   服务器接口；如果答辩需要现场改阈值，需临时用高级区或直接调 `PUT /api/devices/{id}/settings`。
