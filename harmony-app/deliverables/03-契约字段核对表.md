## 0. 怎么核的（可复现命令）

```bash
cd harmony-app        # 相对仓库根（t77 起不写本机绝对路径，材料匿名要求）

# ① 编译门禁：整个工程能从 entry 走到每一个被核对的模块
source ~/harmony-toolchain/env.sh && export OHOS_BASE_SDK_HOME="$DEVECO_SDK_HOME"
hvigorw --no-daemon assembleHap          # → BUILD SUCCESSFUL

# ② 字段级运行核对：真实 HttpApiService + Mock 传输层，逐个接口解析并断言
bash tools/run-selfcheck.sh              # → 50/50 PASS（t153 后；t150 时 47、t145 时 43、t65 时 34），日志 deliverables/02-无设备自检日志.txt

# ③ 预览图与设计令牌一致性
python3 tools/make-previews.py && python3 tools/check-previews.py   # → 6/6 PASS
```

**关键的核对手法**：`tools/selfcheck-entry.ts` **不是**另写一份解析代码去"对答案"，而是把
`service/HttpApiService.ets` 原样拿来实现 `HttpPort`，让 mock 只替换**传输层**
（`service/MockTransport.ets`），再对解析出来的对象逐字段断言并打印。这样"URL 拼接 / 鉴权头 /
错误码翻译 / 契约字段解析"四条路径都被真实执行过。

> 自证门禁有效的办法：往任一被核对的 `.ets` 里注入一个未定义常量，
> `assembleHap` 必须报 `ArkTS:ERROR ... Cannot find name` 并 BUILD FAILED；否则"编译通过"不算证据。

`presence` `last_motion_ts` `door` `window` `temp` `humi` `smoke` `lpg` `co` `nodes_online`

### §4.3.1 `nodes[].mac`（v1.1，t22 补齐，自检 #25）

`mac` 是 SLE 6 字节地址（形如 `11:22:33:44:55:02`，由 SN 派生，见 §2.7）。`parseNodeItem` 用
**可选键**解析（`optStr(o,'mac')`）：CAL-13 明确 `0x21`/`0x24` 读不到时服务器不下发该字段，
所以「缺省」是正常态而不是错误；界面用 `Formatter.fmtMac()` 显示占位符。mock 数据刻意让 M1/M2 带
`mac`、M4 不带，把这条路径钉在自检里。

## 9. 与设计令牌的一致性
