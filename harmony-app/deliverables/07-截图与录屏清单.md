# 页面截图 / 录屏清单（鸿蒙 App）

- **用途**：现场演示与作品材料（docx / PPT / 视频）取材；每一张都标了**它证明哪个验收项或哪个演示动作**，避免"拍了一堆图但评审看不出在证明什么"
- **本机现状（必须写在材料里）**：本机**无 hdc 设备、无模拟器、`/dev/kvm` 不可写**，因此**没有任何真机/模拟器截图**。`04-页面预览图/` 里的 6 张是**设计预览**（`make-previews.py` 用 HTML 复刻 + 无头浏览器截图，720×1560，非真机截图），它们**不能**用来证明"界面在设备上能跑"
- **待用户实测**：下表 S01–S13 与 V01–V07 全部需要用户在模拟器/真机上实拍（V05–V07 见 §7）
- **数字口径（t47 对齐）**：本清单里的自检计数与 HAP 尺寸都标注了**对应的提交**；用户照单拍摄时，命令行输出应与标注值一致，不一致先按 §7 重跑一次

## 6. 拍摄规范（含匿名检查）

1. **分辨率**：模拟器建议 360×780 竖屏（与预览图 720×1560 @2x 一致）；录屏 1080×1920 竖屏，60 s 内。
2. **命名**：`S01-登录页.png`、`V02-报警处置闭环.mp4`、`E01-构建门禁自证.png`；同一批素材放进 `deliverables/现场素材/`（**该目录不入库**，避免体积膨胀；根 `.gitignore` 已于 t103 加 `harmony-app/deliverables/现场素材/` 规则，`git check-ignore -v` 可验证）。
3. **状态干净**：拍之前重启一次 App（mock 是内存态，会回到 4 条种子告警）；系统状态栏若有真实手机号/通知内容，先清通知再拍。
4. **匿名检查（每张过一遍）**：**不得**出现学校、团队、指导老师、真实姓名、真实手机号、真实住址、真实 Wi-Fi 名称/密码；演示账号 `daughter01` 是 mock 专用假账号，可入镜。
5. **不要出现未验证结论**：图注里不要写「真机可用」「推送正常」这类话；未验证的一律写「待用户实测」。
6. **每张图配一句图注**，格式：`S0x 页面名 — 证明：<验收项/演示动作>`（直接用本清单第 1 节的「证明」列）。
7. **不写未实现的项**：语音播报与 4G 回传按 PM 裁定 D9 只写「**扩展设计，本原型未实现**」，材料里**不得**出现「已实现 / 待实测」；多终端协同只写「后续计划」（见 §4 覆盖矩阵末三行）。

### 7.2 「数字-提交」自检（拍 E02/E03/E04 前跑一次）

```bash
cd harmony-app
bash tools/run-selfcheck.sh                      # 末行应打印「合计 34 项，通过 34 项，失败 0 项」
ls -l entry/build/default/outputs/default/entry-default-unsigned.hap   # 应打印 971362
git log -1 --format='%h %s' -- harmony-app       # 记下提交号，写进材料图注
```

- 判据：自检计数、HAP **体积**、提交号**三者同时记入图注**；与本文 §3 表 C 标注不一致时，**以实跑为准**并回头改本文（本文数字对应 t65 提交 `4424608` + 证据日志 `e0fa17b`）。
- 若门禁重跑后体积变化，属正常（源码/资源变动），不是缺陷；只需同步数字。
- ⚠️ **sha256 不要写进材料当指纹**：HAP 里含构建时间戳，同一份源码两次构建的 sha256 也不同（已实测 `a19c6607…f01d` vs `91b6a2f7…21a7b9`），体积才是稳定的。
