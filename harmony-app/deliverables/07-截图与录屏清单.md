# 页面截图 / 录屏清单（鸿蒙 App）

- **用途**：现场演示与作品材料（docx / PPT / 视频）取材；每一张都标了**它证明哪个验收项或哪个演示动作**，避免"拍了一堆图但评审看不出在证明什么"
- **本机现状（必须写在材料里）**：本机**无 hdc 设备、无模拟器、`/dev/kvm` 不可写**，因此**没有任何真机/模拟器截图**。`04-页面预览图/` 里的 6 张是**设计预览**（`make-previews.py` 用 HTML 复刻 + 无头浏览器截图，720×1560，非真机截图），它们**不能**用来证明"界面在设备上能跑"
- **待用户实测**：下表 S01–S12 与 V01–V04 全部需要用户在模拟器/真机上实拍

## 6. 拍摄规范（含匿名检查）

1. **分辨率**：模拟器建议 360×780 竖屏（与预览图 720×1560 @2x 一致）；录屏 1080×1920 竖屏，60 s 内。
2. **命名**：`S01-登录页.png`、`V02-报警处置闭环.mp4`、`E01-构建门禁自证.png`；同一批素材放进 `deliverables/现场素材/`（**该目录不入库**，避免体积膨胀）。
3. **状态干净**：拍之前重启一次 App（mock 是内存态，会回到 4 条种子告警）；系统状态栏若有真实手机号/通知内容，先清通知再拍。
4. **匿名检查（每张过一遍）**：不出现学校、团队、指导老师、真实姓名、真实手机号、真实住址、真实 Wi-Fi 名称/密码；演示账号 `daughter01` 是 mock 专用假账号，可入镜。
5. **不要出现未验证结论**：图注里不要写「真机可用」「推送正常」这类话；未验证的一律写「待用户实测」。
6. **每张图配一句图注**，格式：`S0x 页面名 — 证明：<验收项/演示动作>`（直接用本清单第 1 节的「证明」列）。
