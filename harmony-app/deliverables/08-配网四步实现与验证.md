## 1. 为什么单独一套配网分层（不复用 `ApiPort` / `ServiceHub`）

| | 云端 §6（已有） | 网关本地 §12（本次） |
|---|---|---|
| 基址 | `AppConfig.SERVER_BASE_URL`（`http://127.0.0.1:80/api`） | `http://192.168.2.1`（用户可改，落盘 `SessionStore.KEY_GATEWAY_URL`） |
| 鉴权 | `Authorization: Bearer <JWT>` | **无**（§12.1：配网时还没有登录态，网关只认 AP 口） |
| 前提 | 服务器可达 | **服务器不可达也要能用**（手机连的是网关热点） |
| 成功码 | `code=0` | `code=0`；t143 的 `/api/scan` 回 **`code=200`**（两种都算成功） |
| 超时 | 5 s | **3 s**（与网关内置 H5 一致，§12.11 第 5 条；弱网下 5 s 会让人以为页面死了） |

所以新增了 `GatewayPort` + `GatewayApiService` + `MockGatewayTransport` + `ProvisionHub`（与 `ApiPort`/`HttpApiService`/`MockTransport`/`ServiceHub` 同构），**页面只依赖端口**。
这样「配网页误调云端」「mock 开关一改网关也跟着变」两类错在编译期/装配期就不可能出现。

```
pages/NetConfigPage.ets
      │ 只依赖
      ▼
service/GatewayPort.ets ──┬─ service/GatewayApiService.ets ── service/HttpClient.ets（NetHttpClient，3 s）
                          └─ service/MockGatewayTransport.ets（假网关：真 SSID 缓存 + 可注入 1600/1602/1603/1605）
      ▲ 装配
service/ProvisionHub.ets（按 AppConfig.MOCK_MODE 三选一；地址来自 SessionStore → AppConfig 兜底）
```

## 2. 页面结构（一页五步，不强行卡步骤）

`pages/NetConfigPage.ets`，入口两处：设置页「设备配网」卡（`SettingsPage.ets`）与登录页底部「设备配网（连网关热点）」（未绑定时登录页是唯一可达页面，顺序应为 配网 → 绑定 → 登录）。

| 步 | 卡面要求 | 实现要点 |
|---|---|---|
| 0 | — | 「网关地址」卡：默认 `http://192.168.2.1`，可改；`normalizeGatewayUrl` 容错（补 `http://`、去尾 `/` 与 `/api`）——用户常把 H5 地址粘进来 |
| ① | F1 配网引导 | 热点名（来自 `/api/provision/status` 的 `ssid`）、窗口剩余秒数、汇聚在线、固件版本、当前家庭 Wi-Fi；**「看不到热点？」「连不上？」各三条对策** |
| ② | F2 家庭 Wi-Fi | 下拉来自 `/api/scan` **缓存**（显示扫描时刻、缓存时长、条数、RSSI/信道）；**空列表 → 直接手输**（网关单射频，开窗前扫不到不是故障）；「隐藏网络」开关告诉网关不做"名字必须在列表里"的预检 |
| ③ | F3 密码提交 | 8–63 位（不足 8 位即时红字）；显隐切换；`busy` 非空时禁用提交；提交中禁用防重复 |
| ④ | F3 结果与重试 | 成功：显示将回连的 SSID、`settle_s` 后网关重启热点消失、下一步「手机切回家 Wi-Fi → 回首页刷新」；失败：服务器文案 + 「重新提交」，并按码给下一步（见 §3） |
| ⑤ | F4 华为云凭据 | 接入地址 / 设备 ID / 设备密钥，**可整段跳过**；三项要么全填、要么全空（`cloudFilled()/cloudComplete()`）；密钥显隐切换、**不落盘** |

## 3. 失败矩阵（文案与「用户下一步」）

| 码 | 来源 | 文案（`model/Result.codeText`） | 页面动作 |
|---|---|---|---|
| 1600 | 409 不在配网模式 | 网关不在配网模式 | 提示长按配对键 3 s 重开窗口 |
| 1601 | 410 窗口超时 | 配网窗口已超时 | 同上 |
| 1602 | 400 预检失败 | Wi-Fi 连接失败（原因=密码不对（认证失败）／没扫到这个 Wi-Fi（名字写错或 5G）…） | **回到第③步**改密码重试（`reason` 已拼进文案） |
| 1603 | 409 忙 | 网关正忙（扫描或连接未结束） | 等，按钮由 `status.busy` 驱动禁用 |
| 1604 | 400 先扫后绑 | 请先扫描再绑定 | 回第②步 |
| 1605 | 409 汇聚离线 | 汇聚离线，网关无法下发 | 先给汇聚上电 |
| 1606 | 409 白名单满 | 节点白名单已满 | 解绑后再绑 |
| 网络 | — | 连不上网关（网络错误码 `-1`） | 检查是否还连着网关热点/地址是否被改 |

## 4. 云密钥隐私（F4 的硬口径）

- 密钥只经 `WifiSubmit.secret` 进**请求体**（`{"host","device_id","secret"}`），`GatewayApiService` 不写日志、不缓存；
- 页面状态里只有用户当前输入，**提交成功后不清空输入但也不持久化**；`SessionStore` 只存网关地址一项；
- 自检 #40 直接断言：`AppStorage`/`SessionStore` 的全部键值里搜不到测试密钥，也无 `secret` 键（`MemStore.keys()` 遍历）。

## 5. Mock 演示（无网关也能演完五步）

`AppConfig.MOCK_MODE = true`（当前默认）时 `ProvisionHub` 用 `MockGatewayTransport`：

- `/api/provision/status` → `mode=ap, remain_s=482, ssid=ElderCare-1A2B, hub_online=true, bound_count=2, slots_free=6`
- `/api/scan` → 3 条缓存（`HOME-2.4G` / `CMCC-老人房` / `TP-LINK_9F2C`，附 RSSI 与信道），成功码刻意用 **200**（验证 App 两种成功码都能吃）
- `/api/provision/wifi` → `saved/connecting, settle_s=90`，带云凭据时回 `iotda.saved=true`
- 故障注入 `setFault('not_in_window'|'auth'|'not_found'|'busy'|'hub_offline'|'empty_scan'|'network')` → 现场演示「失败长什么样」

## 8. 未验证边界（诚实清单）

1. **真机热点与真实网段**：SoftAP 实际网段由板级驱动 `libhardware.a` 的 `dhcpd_*` 决定（官方样例实测 `192.168.2.1`，见 CAL-12），本页默认值取 `192.168.2.1` 并允许用户改；**未上板实测**。
2. **真网关的 1602 reason 文案**：本页文案按契约 §12.4 的 `reason` 枚举映射；真实网关回什么 reason 字符串**待联调**（未知 reason 会原样拼进"原因=…"）。
3. **HAP 体积与构建门禁**：已在 PM 开窗内跑通（见 §6），HAP **1129980 bytes**（2026-10-20 21:09 +08:00，代码提交 `eeb329d`，构建时点 HEAD 同）。注意 HAP 是带构建时间戳的 zip：**体积稳定、sha256 跨次不可复现**（D11 口径），材料只记「体积 + 提交号 + 导出时点」。真机安装/启动**仍未验证**（本机无 hdc/模拟器）。
4. **真机渲染**：本机无 hdc/模拟器、`/dev/kvm` 不可写，页面布局与交互**待用户实测**；`deliverables/04-页面预览图/` 是设计预览，不含本页。
