# 施工单：按键心跳版固件（t141）

**给谁看**：你（会自己刷板、自己开串口）。
**这张单只做一件事**：回答「按键采样到底跑没跑」。整张单 3 步，第 3 步是判读表。

> 背景一句话：上一版里 `keys` 报「正在采基线（0 点已采）」，而串口里配网以后再无 tick 侧日志。
> 光看现有日志分不清是「循环卡住了」还是「采样函数自己早退」。这一版把按键采样挪到 tick 循环
> **最前面**，并每 10 秒打一条心跳，把这两种情况分开。

## 第 0 步（10 秒）：先记下这张单对应的镜像指纹

| 项 | 值 |
|---|---|
| 文件 | `rk2206-gateway\out\gateway-Firmware.img` |
| 体积 | **2097152 字节**（每次构建都恒定） |
| md5（当次） | `77e724ec22a615cdfecd9e6431d0a27e` |
| sha256（当次） | `ff11993f6566ff24e249e6add8b8a754d8f3c1205e1d41ff19c91262097b0fd0` |

自己核一下（Git Bash / WSL 都行）：

```
md5sum rk2206-gateway/out/gateway-Firmware.img
```

> RK2206 的镜像**同一份源码两次构建 md5 会不同**（时间戳进镜像了），所以指纹口径是
> **体积 + 提交号**；md5 只在写「当次」时可引用。这次对应提交见下方回执。

## 第 1 步：刷进去

1. 插**烧录口** → 长按 `MaskRom` → 点一下 `Reset` → 约 5 秒后松开，
   等状态栏出现 **`发现一个MASKROM设备`**（RKDevTool 2.96 就行）。
2. 切 **`下载镜像`** 页，**只留两行**：

   | 行名 | 文件 | 地址 |
   |---|---|---|
   | `LoaderToDDR`（loader） | `rk2206_db_loader.bin`（原厂桌面包里那份） | 不用填 |
   | `firmware` | `<仓库根>\rk2206-gateway\out\gateway-Firmware.img` | `0x00000000` |

3. 点 **`执行`** → 等进度条走完，出现 **`下载完成`**。

> 别多勾 `u-boot.itb` 那行（会盖掉我们镜像里的分区表，理由见
> `施工单-网关上板与上云验证.md` §1.1）。

## 第 2 步：开串口抓 90 秒

板子会重启，**不要按任何键**（这版只在开机安静 2 秒采基线，按了会把基线带偏）。

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/serial-capture.ps1 -Port COM14 -Seconds 90 -Out rk2206-gateway/out/boot-COM14.log
```

COM 号换成你设备管理器里那个（115200 / 8-N-1 / **关数据流控**）。

抓完再敲一次诊断命令并贴回来（**不用按任何键**）：

```
keys
```

## 第 3 步：对着这几行判读

### 3.1 正常应该看到（顺序固定）

```
[gw] tick #1 进入
[gw] tick alive n=1 key(samp=0 base_done=0 last=0 mV)          ← 开机立刻一条
[gw] 板载键基线：ch5 中位 3297 mV（20 点，跨度 3 mV）→ 按下阈值 偏离 ≥300 mV / 持续 ≥50 ms
[gw] tick alive n=2 key(samp=20 base_done=1 last=3297 mV)      ← 约 10 秒
[gw] tick alive n=3 key(samp=120 base_done=1 last=3297 mV)     ← 约 20 秒
...
```

判据只有三条：

1. 有 **`[gw] tick #1 进入`**；
2. 约 2 秒后有 **`[gw] 板载键基线：ch5 中位 …`**（中位数应在 **3200–3400 mV** 之间）；
3. 之后**每 10 秒**一条 **`[gw] tick alive n=… key(samp=… base_done=1 last=… mV)`**，
   且 `samp` 一直在涨（每 tick 涨 1，10 秒约涨 100），`last` 大约 3297 mV。

### 3.2 不对时怎么读（把对应原文贴回来就行）

| 你看到的 | 说明什么 | 回传什么 |
|---|---|---|
| 有 `tick #1 进入`，心跳**停在 n=1**（再也没有 n=2、n=3） | 第一次循环之后卡死了。心跳是在按键采样**之前**打的，所以第 1 条能出来、后面出不来 ⇒ **卡在配网分支**（`gw_prov_tick` / `gw_prov_auto_boot` / `resync` 都在心跳后面） | 从 `tick #1 进入` 到日志末尾的**全部原文**（别删行） |
| 有 `tick #1 进入`，但**连 n=1 都没有** | 卡在心跳之前（`gw_alarm_tick` / `gw_433_poll` 或更早） | 同上，全文 |
| 心跳一直有，但 `samp` 恒为 `0`、`base_done=0` | tick 循环是活的，是**采样函数自己提前 return 了** | 3 条 `tick alive` 原文 + `keys` 全文 |
| 心跳一直有、`samp` 在涨，但**没有基线行** | 基线窗口没采满 2 秒就被打断，或基线判定被拒 | `keys` 全文（里面有「警告」那行） |
| 出现 `[gw] ⚠ 板载键不可用（ADC 初始化失败）` | ADC 打不开（引脚复用/驱动） | 该行 + `keys` 全文 |
| 出现 `[gw] ⚠ 板载键基线不稳（跨度 …）` | 开机那 2 秒有人在按键 | 该行 |
| 连 `tick #1 进入` 都没有 | tick 任务根本没被创建（更早的地方就出问题了） | 开机到最后一行的全部原文 |

> 「心跳停在第 N 条」这个说法对应的就是第 1 行：**N 之后再也没有新的 `tick alive`**，
> 说明循环卡在第 N 次到第 N+1 次之间的某个网络动作上。把 N 的数值和最后几行一起贴回来最有用。

## 这一版**没有**动的东西（免得你担心）

- **没动** ADC 通道、分压、阈值——硬件读数已经和课件电压表逐条吻合，问题不在那儿；
- **没动** 配网状态机语义（`gw_prov.c` 一行没改），只把**采样**挪到了它前面；
- **没动** 网络代码。日志里那条 SDK 自己连上 `192.168.2.10/24` 的现象，
  等心跳结论出来再用 `wifi show` 解释，这版不碰。
