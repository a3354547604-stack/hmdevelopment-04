## 1. 你问的三件事，先答（读完能省半小时）

### 1.1 我们这份 `gateway-Firmware.img` 能直接烧吗？要不要 `rk2206_db_loader.bin`？地址填 0 还是按分区？

**能直接烧；要 loader；地址就是 0，不按分区。** 一手依据：

1. 板级手册（SDK 里 `vendor/lockzhiner/rk2206/README_zh.md` §4.2.2）只让指定**两个**文件，且都取自
   `out/rk2206/lockzhiner-rk2206/images/`：`LoaderToDDR = rk2206_db_loader.bin`、`firmware = Firmware.img`。
   ⇒ 我们的 `gateway-Firmware.img` 就是这一套里的 `Firmware.img`，**同一份东西、只是换了个文件名**。
2. Linux 侧官方烧录脚本（SDK `device/rockchip/tools/linux/flash.py`）把这两步写死了：
   第 37 行 `db <chip>_db_loader.bin`（下载 Boot，即 loader），第 40 行 **`wl 0 Firmware.img`**（写到偏移 **0**）。
   工具的中文串里也有一条兜底错误：`ERROR_BOOT_BEFORE_LBA=写LBA前必须完成下载Boot!` ⇒ **loader 不能省**。
3. 实测指纹佐证是"同一种文件"：我们的 img 与原厂包里的 `Firmware.img` **同为 2097152 字节**；
   我们的 img 与本次构建产物 `out/rk2206/lockzhiner-rk2206/images/Firmware.img` **逐字节相同**（md5 `9cd34e38…`）。
   而 `rk2206_db_loader.bin`（35093 字节）在 **SDK / 我们的构建 / 原厂桌面包** 三处 md5 完全相同（`5f2ea974…`）
   ⇒ loader 不是编译产物，用哪一份都一样。

⚠️ **一个坑（会直接让你"执行失败"）**：原厂桌面包里那份 `config.cfg` 里有一行 `u-boot.itb`，路径是
`<原厂机器>\Downloads\u-boot.itb` —— 这是原厂打包那台机器上的路径，**你这台电脑没有这个文件**。
如果那一行被勾着就点「执行」，会弹 `u-boot.itb下载项不存在,停止执行!`。
**处置**：在「下载镜像」页里**只留两行** —— `LoaderToDDR`（→ `rk2206_db_loader.bin`）和 `firmware`（→ 我们的 `gateway-Firmware.img`），
其余行取消勾选或删掉；地址列不用你填，保持工具带出来的 `0x00000000` 即可。

### 1.2 调试串口会出现在哪个 COM？波特率多少？烧录成功的逐字判据？

1. **COM 号没法预判**（现在 COM14/COM15 被两块 WS63 占着），用"插拔对照法"认它：
   拔掉 RK2206 的串口线 → 看端口列表；插上 → 再看，**新多出来的那个就是它**。
   命令行版（Windows PowerShell）：`[System.IO.Ports.SerialPort]::GetPortNames()`；
   图形版：设备管理器 → `端口(COM 和 LPT)`（板级手册 §4.3.2 就是这么写的）。
   它大概率显示成 `USB-SERIAL CH340 (COMxx)`（板载转串口与那两块 WS63 同款驱动），**不会**抢 COM14/COM15。
   ⚠️ *需实物确认*：若板上没焊转串口芯片而只留 UART 排针，就得外接一根 USB-TTL 线（设备名可能是 CH340/CP210x）
   —— 不管哪种，**以设备管理器里新出现的那个 COM 为准**。
2. **波特率 115200**、8 数据位、无校验、1 停止位、无流控（板级手册 §4.3.3；`device/rockchip/rk2206/README_zh.md:216`）。
3. **烧录成功的判据**（不是"有字就行"）：按一下板子上的 **Reset** 键后，串口出现
   `[gw] ---- RK2206 网关 M0 启动 ELDERCARE-GW-M0-v1.2 (契约 v1.2) ----`。
   出现 ROM/U-Boot 那几行但**没有**这一行 = 烧进去的不是我们的固件。

### 1.3 怎么进烧录模式？什么时候松手？工具上该看到什么原文？

1. USB 线插板子的 **USB-OTG（就是"烧录口"）** —— 不是调试串口那个口（板级手册 §4.2.3）。
2. **长按 `MaskRom` 键不要松** → 点一下 `Reset` 键（按下即松，MaskRom 继续按住）→ **约 5 秒后松开 MaskRom**
   （板级手册 §4.2.3 / §4.2.2.1 原文："按下后松开，但MaskRom按键不要松开，大约5秒后松开"）。
   ⚠️ *需实物确认*：板子丝印上这两个键的确切名字（`MaskRom`/`Reset`，有的批次写 `BOOT`）。
3. 工具该显示的原文（已从工具语言文件里核到模板 `IDS_FOUNDONEDEVICE=发现一个%s设备`）：
   - 进对了：状态栏 **`发现一个MASKROM设备`**（或 `发现一个LOADER设备`，后者是 loader 已经下过一次）
   - 没进对：**`没有发现设备`** → 回第 1 步重来（先换线/换 USB 口，别急着重装驱动）
   - 点「执行」后成功：**`下载完成`**；失败：`下载失败`。中途可能提示 `正在下载 …(%d%%)`。

## 4.5 串口配网（免按键，t136）：现场没有轻触开关时的联网办法

**什么时候看这一节**：串口能敲命令（有 `OHOS #` 提示符），但 `ifconfig` 里 `wlan0 is no connected`、
日志反复打 `[gw] 取时失败：服务器和 NTP 都不可达，暂不连 IoTDA`。这是"家庭 Wi-Fi 还没配"，
板子根本没出网（取时和连云都要先有网）。

**和「长按配网键 3 s」的关系**（重要，别以为是两套）：

- 两条路**写的是同一份 Flash 凭据**（同一个 `gw_store_cred_save`），谁后写谁生效，不会各存一份、
  也不会互相盖掉——配网键那条流程和本地配网 API 的状态机**一点没改**。
- 区别只在入口：配网键那条走 SoftAP + 手机网页（需要 `GPIO0_PA3` 上真接一个轻触开关）；
  这条走调试串口（只需要一根 USB 线）。
- 开机时网关自己就会用这份凭据联网（`[gw] 联网：使用 Flash 里的家庭 Wi-Fi ssid=…`），
  所以配一次以后不用再管。

### 4.5.1 先看现在是什么状态（3 步）

1. 串口敲一下回车，确认能看到 `OHOS #` 提示符（就是抓日志那个 COM，115200 8-N-1）。
2. 敲：

   ```
   wifi show
   ```

3. 对结果：
   - `[wifi] 未配置家庭 Wi-Fi` → 往下做 4.5.2；
   - `[wifi] 已保存 SSID：<路由器名>（口令不回显）` 且 `[wifi] STA：未连接` → 做了 4.5.2 还是连不上，
     把这两行贴回来（说明凭据在，连不上是另一类问题）；
   - `[wifi] STA：已连接 ssid=… ip=…` → 已经好了，直接看 §5 的云侧判据。

> 口令**永远不会被打印**（连长度都不给，只给 N 字节与"不回显"字样）。这是有意的：
> 串口日志会被拍照、贴群、进报告。

### 4.5.2 写进去并当场联网（3 步）

1. 敲（`<路由器名>` 与 `<口令>` 换成你自己的；**口令里不能有空格**）：

   ```
   wifi set ssid=<路由器名> psk=<口令>
   ```

2. 期望依次看到三行：

   ```
   [wifi] 已保存 ssid=<路由器名>（口令 N 字节，不回显），正在连接…
   [wifi] ✓ 已连上 ssid=<路由器名>，IP=192.168.x.y
   [wifi] 取时/连云：取时=未完成（等 /api/time 或 NTP），已连 IoTDA=否
   ```

   第三行此刻是"未完成"**正常**：取时与连云由后台网络任务在这之后几秒到几十秒内推进。

3. 接着看串口有没有依次出现 `[gw] 取时成功…` 与 `[gw] IoTDA 已连接 clientId=…`（判据同 §5）。
   如果 `wifi set` 之后 30 秒还没出现取时成功，把 `wifi show` 与这一段日志一起贴回来。

**失败会说清是哪一种**（不会只写"失败"）：

| 串口那行 | 意思 | 怎么办 |
|---|---|---|
| `[wifi] SSID 不能为空` | `ssid=` 后面是空的 | 补上名字 |
| `[wifi] SSID 太长：33 > 32` | 超过 32 字节（中文一个字算 3 字节） | 用路由器实际名字，别加引号 |
| `[wifi] SSID 含非法字符` | 名字里有空格 / 双引号 | 去掉；带空格的名字请改路由器（命令行按空格切词） |
| `[wifi] 口令太短：7 < 8` | 少于 8 位 | WPA2 最少 8 位 |
| `[wifi] 口令太长：64 > 63` | 超过 63 位 | 换短口令 |
| `[wifi] 口令含非法字符` | 口令里有中文/空格/引号 | WPA2 口令只能是可见 ASCII |
| `[wifi] 不认识的参数` | 打错了名字（例如写成 `passwd=`） | 只认 `ssid=` 与 `psk=`，顺序随意 |
| `[wifi] ⚠ 写 Flash 失败` | 凭证**没保存** | 顺手跑 `gwkv show`：KV 区坏时这里也会失败 |
| `[wifi] ✗ 连接失败：认证失败：口令不对…` | 口令错，或被路由器拉黑/限速 | 核对大小写；看路由器有没有 MAC 白名单 |
| `[wifi] ✗ 连接失败：超时（15 s 内没连上）…` | SSID 拼错 / 信号弱 / 那是 5 GHz 网络 | 先做 4.5.3 对名字与信号 |
| `[wifi] 扫描不可用（SoftAP 已开启时单射频驱动会拒绝扫描）` | 单射频驱动正忙 | 等配网窗口结束（30 s）再扫，或直接按路由器名字 `wifi set` |

### 4.5.3 核对拼写与信号（可选，1 步）

1. 敲 `wifi scan`，会列出 2.4 GHz 热点：`1) <路由器名>   rssi=-42 dBm ch=6`
   （板子的 Wi-Fi 是 2.4 G，列表只列 2.4 G）。
   - 一个都没有 → 路由器可能只开了 5 GHz；
   - `rssi` 差于 `-80 dBm` → 离得太远，先把板子挪近再配。

## 5. 判据（逐条对，别只看"有字就行"）

串口侧（对应 §0 那张表）：

- [ ] 出现 `[gw] ---- RK2206 网关 M0 启动 ELDERCARE-GW-M0-v1.2 (契约 v1.2) ----`
- [ ] 出现 `[gw] 任务已启动：UART0=115200 8N1，等待汇聚帧…`
- [ ] 出现 `[gw] 联网成功：IP=…`（或 `wifi show` 里 `STA：已连接`）——没有就先做 **§4.5**
- [ ] **不出现** `[gw] UART0 初始化失败：与汇聚的链路不可用`
- [ ] 出现 `[gw] 取时成功(HTTP|NTP) epoch=…`
- [ ] 出现 `[gw] IoTDA 已连接 clientId=<设备ID>_0_0_<YYYYMMDDHH>`（小时数应是当前 UTC 小时）
- [ ] 不出现 `[gw] MQTTConnect 失败 rc=…`

云侧（IoTDA 控制台 → 设备 → **消息跟踪**，开着它再看串口）：

- [ ] 每 60 秒一条 `properties/report` 上行（能看到 presence/temp 等字段）
- [ ] 下发 `set_report_interval`（键名 `seconds`，例 `{"seconds": 30}`）→ 串口
      `[gw] 命令响应 set_report_interval(<request_id>) result=0`，之后节拍变 30 秒
- [ ] （可选，最能证明全链路）下发 `demo_trigger`（键名 `event`，取值 `fall`/`gas`/`sos`）→ 串口
      `[gw] 事件 M0-……-fall-… type=fall level=…`，云侧消息跟踪出现对应事件

> 属性上报成功时**串口没有专门一行日志**（设计如此，防刷屏），别因为串口安静就以为没上报。

## 6. 常见失败对照表

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 状态栏 `没有发现设备` | 没进 MaskRom / 线插的是调试口 / 驱动没装 | 换烧录口、按 §1.3 重来、跑一次 `DriverInstall.exe` |
| 执行时报 `u-boot.itb下载项不存在,停止执行!` | 用了原厂 `config.cfg` 里那条指向原厂作者机器的行 | 删掉/取消勾选那一行（§1.1） |
| 执行时报 `没有勾选下载项,停止执行!` | 两行都没勾 | 勾上 `LoaderToDDR` 与 `firmware` |
| 执行报 `写LBA前必须完成下载Boot!` | loader 行没勾/路径不对 | `LoaderToDDR` 指向 `rk2206_db_loader.bin` |
| 串口一片空白 | 插了烧录口 / 波特率不是 115200 / COM 选错 | 换调试口、115200、用插拔对照法认 COM |
| 只有 ROM/U-Boot 几行然后停住 | 板子还在 MaskRom（烧完没重启） | 断电重上电，或按 Reset |
| 反复重启、打印几条就断 | USB 口供电不足 | 换 USB 口 / 带供电的 HUB |
| 有横幅但 `UART0 初始化失败` | UART0 复用/引脚被占 | 贴日志给我，我改 `gw_config.h` 的复用 |
| `取时失败：服务器与 NTP 都不可达` | 板子没出网（家庭 Wi-Fi 没配）/ NTP 123 被墙 / 时间服务器是占位值 | 先敲 `wifi show`：未配置就按 **§4.5** 串口配网；已配置再看时间源 |
| `[gw] 未配置家庭 Wi-Fi：串口敲 wifi set …` | 首次上电，家里 Wi-Fi 还没写进 Flash | 按 **§4.5** 配一次（之后开机自动用） |
| `[gw] ⚠ 联网失败：认证失败/超时` | 口令错、SSID 拼错、5 GHz-only 或信号太弱 | 按 §4.5.2 的失败对照表逐条排；`wifi scan` 先核对拼写与信号 |
| `MQTTConnect 失败 rc=4` | ClientId 里的小时戳与真实时间差太多，或密钥错 | 核对密钥与时间源（`gwkv show`） |
| 连上了但云侧看不到上报 | 主题/设备 ID 不匹配，或 60 秒还没到 | 等满 70 秒；核对设备 ID |

## 8. 现状与已知缺口（老实说在这）

- **凭证现在可以免重编改**：t34 已加了串口命令 `gwkv`（写 Flash KV + 读回校验），步骤见
  `rk2206-gateway/施工单-凭证写入Flash-KV.md`；老办法（改 `gw_config.h` 重编）仍然可用。
- **`set_threshold`（契约 §4.5）已接入**：t33 完成，21 个阈值键逐条校验，合法就下发到汇聚并落生效值
  （未知键回 `result=1`、越界回 `result=2`、汇聚无 ACK 回 `result=12`），主机自测 259 条覆盖。
- WiFi 账号口令**现在可以现场用串口写**（t136）：`wifi show/set/scan`，见本文 **§4.5**。
  它与「长按配网键 3 s → SoftAP + 手机网页」共用同一份 Flash 凭据（`gw_store_cred_save`），
  后者需要 `GPIO0_PA3` 外接轻触开关、现场没有，所以串口这条是当前的主路径。

  开机联网也改了：不再调 SDK 的 `SetWifiModeOn()`（它读 SDK 自己的槽，我们从来没写过），
  改成读同一份凭据 + 失败按 30 s 间隔最多重试 6 次。
- **上板实测部分仍是待实测**：上述联网/配网路径在主机自测里覆盖了参数与边界（t136 用例），
