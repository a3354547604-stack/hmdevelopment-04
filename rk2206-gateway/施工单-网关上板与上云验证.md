（日志 `取时失败：服务器与 NTP 都不可达，暂不连 IoTDA`），这是设计如此，不是 bug。

## 3. 步骤 B：烧录（3 步）

1. 装驱动（只需一次）：跑 `lockzhiner-rk2206-openharmony3.0lts/device/rockchip/tools/windows/DriverAssitant/DriverInstall.exe`，
   然后打开同目录 `RKDevTool.exe`。
2. 接线：USB 线插板子的**烧写口**（不是 USB_UART 口）；**按住 MaskRom 键 → 点一下 Reset → 松开 MaskRom**。
   RKDevTool 下方出现 `发现一个MASKROM设备` 才算连上（没出现就换根线/换个 USB 口重来，别急着重装驱动）。

   （出现 `下载完成` / `重启设备`）。

## 4. 步骤 C：抓 60 秒串口原文（3 步）

1. 把 USB 线改插板子的 **USB_UART 口**（波特率 **115200**，8-N-1，无流控）。找端口：设备管理器里看
   `USB-SERIAL CH340` / `CP210x` 的 COM 号；现在 COM14/COM15 被两块 WS63 占着，**RK2206 会是第三个**。
2. 抓日志（WSL 里跑，把 `COM20` 换成你实际的号）：

   ```bash
   cd /mnt/c/Users/Administrator/Desktop/HMProgram
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/serial-capture.ps1 \
     -Port COM20 -Seconds 70 -Out rk2206-gateway/out/boot-COM20.log
   ```

   这个脚本会一边打印一边落盘（每行带毫秒时间戳），中途 Ctrl-C 也不会丢已抓到的内容。**不要加 `-Reset`**
   （那条 RTS 脉冲是给 WS63 的 EN 脚用的，RK2206 上可能反而把板子按在复位上）；要复位就按板子上的 Reset 键。
3. 抓完后把 `rk2206-gateway/out/boot-COM20.log` 整个贴回来（或告诉我路径，我自己读）。

## 5. 判据（逐条对，别只看「有字就行」）

串口侧：

- [ ] 第 1 行（或复位后不久）出现启动横幅，且**版本串正确**：
      `[gw] ---- RK2206 网关 M0 启动 ELDERCARE-GW-M0-v1.2 (契约 v1.2) ----`
      → 没有这一行 = 烧的不是网关固件（可能是 hello 包或空片）。
- [ ] **不出现** `[gw] UART0 初始化失败：与汇聚的链路不可用`（出现说明 UART0 引脚/复用配错，汇聚链路由它决定）。
- [ ] 出现 `[gw] 取时成功(HTTP) epoch=…` 或 `[gw] 取时成功(NTP) epoch=…`。
- [ ] 出现 `[gw] IoTDA 已连接 clientId=<设备ID>_0_0_<YYYYMMDDHH>`，后面那串小时数应是**当前 UTC 小时**。
- [ ] 不出现 `[gw] MQTTConnect 失败 rc=…`（若出现：rc=2/4 多半是 ClientId 或 HMAC 时间戳，rc=1 是协议版本）。

云侧（华为云 IoTDA 控制台 → 设备 → 「消息跟踪」，开着它再看串口）：

- [ ] 每 60 秒有一条 `properties/report` 上行（`service_id` 里能认出 presence/temp 等字段）。
- [ ] 控制台下发一条 `set_report_interval`（参数键名就是 `seconds`，范围 10..3600，例：`{"seconds": 30}`）→ 串口出现
      `[gw] 命令响应 set_report_interval(<request_id>) result=0`，且之后的属性上报节拍变成 30 秒。
- [ ] （可选，最能证明全链路）下发 `demo_trigger`（参数键名是 `event`，取值 `fall`/`gas`/`sos`，例：`{"event":"fall"}`）
      → 串口 `[gw] 事件 <event_id> type=fall level=…`（`event_id` 以 `M0-3F1A2B-` 开头），云侧消息跟踪里出现对应事件上行。

**注意**：成功上报属性时**串口没有专门一行日志**（设计如此，避免刷屏）。想确认上行只能看云侧消息跟踪或
「设备影子 → 最新上报」，别因为串口安静就以为没上报。

## 6. 常见失败对照表

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 串口一片空白 | 插错口（插了烧写口）/ 波特率不是 115200 / 端口选错 | 换 USB_UART 口、确认 COM 号、按一下 Reset |
| 只有 ROM 的 `Download` 之类字样，然后停住 | 板子还在 MaskRom 模式（烧完没重启） | 断电重上电，或按 Reset |
| 反复重启、打印几条就断 | 供电不足（USB 口电流不够） | 换 USB 口/带供电的 HUB |
| 有横幅，但 `UART0 初始化失败` | UART0 复用/引脚被别处占用 | 把日志贴给我，我改 `gw_config.h` 的引脚复用 |
| `取时失败：服务器与 NTP 都不可达` | 网络没通 / NTP 123 被墙 / 服务器地址是占位值 | 先确认板子能上网，再给一个可达的时间源 |
| `MQTTConnect 失败 rc=4` | ClientId 里的小时戳与真实时间差太多，或设备密钥错 | 核对 `GW_MQTT_DEVICE_SECRET` 与时间源 |
| 连上了但云侧看不到上报 | 主题/设备 ID 不匹配，或 60 s 还没到 | 等满 70 秒；核对 `GW_MQTT_DEVICE_ID` 与控制台设备 ID |
| 命令下发后无回应 | 设备侧没订阅下行主题 / QoS 配错 | 把命令名与串口原文贴回来 |
