# 演示环境搭建执行单（一张纸：三块 WS63 + 网关 + 服务器 + App + 433）

> **给谁看**：演示/录屏当天要亲手把整套硬件与软件开起来的人。假设你**没碰过嵌入式板子**。
> **目标**：从零走到「节点有日志 → 汇聚有日志 → 网关有日志 → 服务器有数据 → App 能打开五页 → 433 能按响」。
> **读法**：五节（板子 → 服务器 → App → 433 → 检查），**每节只有 3 步**，每步都写了
> 「**做什么** / **成功标志**（怎么知道这步过了）/ **失败怎么办**（不过怎么办）」。**任何一步和本单写的不一样，就停下把串口原文贴回来，不要猜。**
> **本单日期**：2026-10-19。引用的文件路径与体积都是当天逐个 `ls` 核过的（清单见 §6.3）。

**时间预算**（不含装 DevEco Studio 的 30–60 分钟）：

## 0. 开工前先认这三件事

### 0.1 兜底顺序（硬件缺件、时间不够，就按这个顺序做）

**先用纯软件跑通，再逐渐接硬件**；每一档都能单独撑起一段演示：

1. **服务器**（§2）——只依赖电脑，不依赖板子。
2. **App 纯 Mock**（§3 第 2 步）——`MOCK_MODE = true` 是默认值，**不发任何网络请求**，断网也能演完五个页面。
3. **一块节点真机**（§1 第 1 步 + `NODE_MOCK.fwpkg` 或 `NODE_M1.fwpkg`）。
4. **汇聚 + 网关连起来**（§1 第 2、3 步）——节点事件才有机会上云。
5. **433 SOS**（§4）——最后做；模块没到货就走 §4 的降级路径。

> **板子数量现实**：仓库记录（2026-10-17）手上是 **2 块 WS63 + 1 块小凌派 RK2206**，用户已决定再买 2 块 WS63 凑成 4 块。
> 只有 2 块 WS63 时：**板 1 烧汇聚 `HUB_HUB.fwpkg`、板 2 在 `NODE_M1/M2/M4` 之间轮换**（一次只演一个节点），
> 或者用 `NODE_MOCK.fwpkg` 顶一个节点位。板子到齐后才是「1 汇聚 + 3 节点」同时在线。

### 0.2 术语最小集

| 词 | 一句话 |
|---|---|
| 固件 / `.fwpkg` | 烧进板子里的程序包，`.fwpkg` 是 WS63 的打包格式 |
| 烧录 | 把固件写进板子；**只写 app 分区，不擦整片**，所以烧坏也能再烧回来 |

| 「待实测」 | 本机（写这份单子的机器）**没有对应的硬件/设备**，没法替你确认；请把串口原文或截图回传 |

## 1. 板子（3 步）

### 第 1 步：烧节点板（厨房 M1 / 卧室 M2 / 门厅 M4）

**做什么**

1. 板子用 Type-C 线插电脑（插**板子的 Type-C 口**；插上后电脑会多出一个 `COMxx`）。
2. 认清 COM 号（**两台 WS63 同时在插时最容易认错**，按下面任一种方法）：

   ```bash
   # 方法 A（WSL 里跑，列出串口设备；注意：CH340 有时不出现在这个列表里，别只信它）
   powershell.exe -NoProfile -Command "[System.IO.Ports.SerialPort]::GetPortNames()"
   # 方法 B（推荐）：看设备管理器 → 端口(COM 和 LPT)，或按驱动找
   powershell.exe -NoProfile -Command "Get-CimInstance Win32_PnPEntity | Where-Object {$_.DeviceID -like '*VID_1A86*'} | Select-Object Name,DeviceID"
   # 方法 C（最稳）：拔掉一块板 → 再看列表 → 插回去 → 新多出来的那个 COM 就是它
   ```

3. 烧固件（**一次只插一块板**，`app` = 只写 app 分区；每块约 2.5 分钟）：

   ```bash
   cd <仓库根>     # WSL 形态：/mnt/c/Users/<本机用户>/Desktop/HMProgram
   ./tools/ws63flash-port.exe \
     'C:\Users\<本机用户>\Desktop\HMProgram\ws63-firmware\out\NODE_M1.fwpkg' app COM15 \
     'C:\Users\<本机用户>\Desktop\HMProgram\ws63-firmware\out\flash-m1-COM15.txt'
   # 烧 M2 / M4 就换文件名与 COM 号。厨房板换成 NODE_M1、卧室板 NODE_M2、门厅板 NODE_M4。
   # ⚠ 工具只认 Windows 形态的绝对路径（写成 /mnt/c/... 会直接报 System.IO.DirectoryNotFoundException）
   ```

4. 看一眼日志（60 秒，够看到开机行；`-Reset` 是给 WS63 的 EN 脚一个复位脉冲，会看到完整启动）：

   ```bash
   cd <仓库根>
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/serial-capture.ps1 \
     -Port COM15 -Seconds 60 -Out ws63-firmware/out/watch-m1-COM15.log -Reset
   ```

**成功标志**（缺一不算过）

- 烧录命令结束、烧录日志里有 `handshake OK (3 ACKs)` 与 `OK: ws63-liteos-app-sign.bin`（退出码 0）。
- 抓到的日志里出现 `[M1] EC-NODE-ROLE=M1 type=gas fw=…`（**这是判「烧的是哪份固件」最硬的一行**）。
- 用 `NODE_MOCK.fwpkg` 时还应看到 `*** MOCK 模式 ***`，并且**不接任何传感器也每 2 秒出一帧**。

**失败怎么办**

| 现象 | 最可能原因 | 一句话处置 |
|---|---|---|
| 工具报 `port open failed` / 打不开 COM | 别的程序占着这个口（抓日志的窗口没关、上次烧录没退干净） | 关掉所有抓日志/烧录窗口，等 5 秒，重试；还不行就拔插 USB |
| 烧完串口第一行还是旧内容 | 烧进去的不是这份（或没真正重启） | 抓日志时**加 `-Reset`**；仍不对就把 `NODE_MOCK.fwpkg` 烧一遍对照 |
| 串口**什么都没有** | 抓 RTS 把板子按在复位态 / COM 选错 / 波特率不是 115200 | 换 `-Reset`；重新用「插拔对照法」认 COM；波特率写 115200 |
| 板子反复重启、打几条就断 | USB 供电不足 | 换 USB 口或带供电的 HUB |
| 板子彻底起不来 | 固件/分区状态坏了 | 烧回退包 `ws63-firmware/output/WS63-XF_AT-2.0.1-alpha.fwpkg`（同样 `app` 分区） |

**传感器接线速查**（想让节点报真实数据才需要接；**全部待实测**，细节以 `docs/技术/引脚与接线表.md` 为准）

| 节点 | 接什么 | 关键点 |
|---|---|---|
| `M1` 厨房 | MQ-2（AO→`IO09`，**5 V 供电 + 1:1 分压**）+ AHT20（I2C `23/24` 脚，3.3 V） | 串口看到 `i2c scan: found 0x38`、`temp/humi` 不是 0 |
| `M2` 卧室 | LD6002C 雷达（7/8 脚→`IO07/IO08`，4 脚 TX2→`IO06`，**3 脚必须接 GND**，**独立 3.3 V/1 A**） | 帧类型 `0E02` 计数增长；站到雷达下 15–20 s 出现 `"fall":1` |
| `M4` 门厅 | 玄关门磁→`IO00`、阳台门磁→`IO02`（裸管 + 内部上拉，门开 = 断开 = 1） | 开关门出现成对的 `{"type":"door",…,"ch":0}` |

### 第 2 步：烧汇聚 H1 + 接三根线到网关

**做什么**

1. 烧汇聚（同第 1 步的命令，换包与 COM）：

   ```bash
   cd <仓库根>
   ./tools/ws63flash-port.exe \
     'C:\Users\<本机用户>\Desktop\HMProgram\ws63-firmware\out\HUB_HUB.fwpkg' app COM14 \
     'C:\Users\<本机用户>\Desktop\HMProgram\ws63-firmware\out\flash-hub-COM14.txt'
   ```

2. 接三根杜邦线（**汇聚 ↔ 网关 UART0**，交叉接，别忘共地）；汇聚排针 `23/24` 脚就是它的 U1TX/U1RX：

   | 网关侧（小凌派 `E53` 座） | 汇聚 H1 排针 | 线色建议 | 注意 |
   |---|---|---|---|
   | `E53_UART0_TX_M0` | 排针 **24**（`U1RX`） | 黄 | 3.3 V 直连，不分压 |
   | `E53_UART0_RX_M0` | 排针 **23**（`U1TX`） | 绿 | 3.3 V 直连 |
   | `E53` 座 `GND` | 排针 **15/26/29/30** 任一 `GND` | 黑 | **必接**，串口三线缺它必失败 |

3. 汇聚与网关都上电，抓汇聚日志 60 秒（同第 1 步的 `serial-capture.ps1`）。

**成功标志**

- 汇聚串口出现 `HUB-ROLE=CENTRAL sn=H1 fw=0.1.0 mock=0 (uart1 115200)`。
- 节点上电后，汇聚侧开始出现收帧/轮询日志（节点与汇聚之间走**星闪**，不需要任何线）。
- 网关串口出现 `[gw] 任务已启动：UART0=115200 8N1，等待汇聚帧…`，随后能解析到汇聚帧（不是 `UART0 初始化失败`）。

**失败怎么办**

| 现象 | 最可能原因 | 一句话处置 |
|---|---|---|
| 网关打 `[gw] UART0 初始化失败：与汇聚的链路不可用` | 线接错/没共地/没接 | 按上表重接，**先量 GND 通不通** |
| 网关串口出现乱码或与日志互相污染 | 把汇聚接到了 RK2206 的 `UART1_RXD_M1/TXD_M1`（那是底板调试串口 CH340E） | **绝不可接那两个脚**，改接 `E53_UART0` |
| 汇聚日志有，但网关一直「等待汇聚帧」 | TX/RX 没交叉（两根线接反了） | 把 `23/24` 两根线对调再试 |
| 汇聚完全没有启动行 | 烧录没成功或 COM 认错 | 回第 1 步重烧、用「插拔对照法」认 COM |

### 第 3 步：烧网关 RK2206（RKDevTool）

**做什么**

1. 装一次驱动：跑原厂 `DriverAssitant` 里的 `DriverInstall.exe`（SDK 里 `device/rockchip/tools/windows/DriverAssitant/` 下也有一份），然后打开 `RKDevTool.exe`（2.86 / 2.96 都行）。
2. 进 MaskRom：USB 线插板子的 **USB-OTG（烧录口）** → **长按 `MaskRom` 键不松** → 点一下 `Reset` 键 → **约 5 秒后松开 `MaskRom`**
   （丝印有的批次写 `BOOT`）。
3. 切到「**下载镜像**」页，**只留两行**（其余行取消勾选或删掉）：

   | 行名 | 选哪个文件 | 地址列 |
   |---|---|---|
   | `LoaderToDDR`（loader） | `rk2206_db_loader.bin`（桌面原厂桌面包里那份最保险，35093 B） | 不用填 |
   | `firmware` | **我们的** `<仓库根>\rk2206-gateway\out\gateway-Firmware.img`（2097152 B） | `0x00000000` |

   > ⚠️ **必须删掉指向 `C:\Users\xiexi\Downloads\u-boot.itb` 的那一行**。
   > 那是原厂 `config.cfg` 里**原厂打包机上的路径**，你这台电脑没有这个文件；那一行若被勾着点「执行」，
   > 会直接弹 **`u-boot.itb下载项不存在,停止执行!`**。处置：删掉/取消勾选该行 —— 只留上表两行即可。

4. 点 **`执行`**，等进度条到 **`下载完成`**。烧完把 USB 线改插板子的 **UART（调试串口）** 口，抓 70 秒日志（**不要加 `-Reset`**），
   抓的时候按一下板子的 `Reset` 键：

   ```bash
   cd <仓库根>
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/serial-capture.ps1 \
     -Port COM16 -Seconds 70 -Out rk2206-gateway/out/boot-COM16.log
   ```

**成功标志**

- 进对 MaskRom：工具状态栏出现 **`发现一个MASKROM设备`**（或 `发现一个LOADER设备`）。
- 烧录成功：**`下载完成`**；中途可能提示 `正在下载 …(%d%%)`。
- 串口出现 **`[gw] ---- RK2206 网关 M0 启动 ELDERCARE-GW-M0-v1.2 (契约 v1.2) ----`** 与 `[gw] 任务已启动：UART0=115200 8N1，等待汇聚帧…`。
  （**只有 ROM/U-Boot 几行而没有这两行 = 烧进去的不是我们的固件**。）

**失败怎么办**（原文照抄，报错可直接对号）

| 现象 | 最可能原因 | 一句话处置 |
|---|---|---|
| 状态栏 `没有发现设备` | 没进 MaskRom / 线插的是调试口 / 驱动没装 | 换烧录口、按第 2 条重来、跑一次 `DriverInstall.exe` |
| 执行报 `u-boot.itb下载项不存在,停止执行!` | 用了原厂 `config.cfg` 里那条指向原厂作者机器的行 | 删掉/取消勾选那一行（见上面 ⚠️） |
| 执行报 `没有勾选下载项,停止执行!` | 两行都没勾 | 勾上 `LoaderToDDR` 与 `firmware` |
| 执行报 `写LBA前必须完成下载Boot!` | loader 行没勾或路径不对 | `LoaderToDDR` 指向 `rk2206_db_loader.bin` |
| 串口一片空白 | 插了烧录口 / 波特率不是 115200 / COM 选错 | 换调试口、115200、用「插拔对照法」认 COM |
| 只有 ROM/U-Boot 几行就停住 | 板子还在 MaskRom（烧完没重启） | 断电重上电，或按 `Reset` |

**网关怎么联网**（两条路，二选一；**都待实测**）

- **路 A（推荐，开机自动连）**：家里的 Wi-Fi 账密写死在**板级 SDK 的 `config_network.h`**（不在本仓库的网关源码里，所以换网要重编板级配置）——板子已联网时，串口会出现
  `[gw] 取时成功(HTTP) epoch=…` 与 `[gw] IoTDA 已连接 clientId=<设备ID>_0_0_<YYYYMMDDHH>`。
- **路 B（现场换网，不用重编）**：用一根杜邦线做配对键 —— 一头 `GND`、另一头 `EX_GPIO_A3`，**长按 3 秒**进配网窗口，
  手机连上热点 `ElderCare-XXXX`，浏览器打开 `http://<串口首行打印的 AP 地址>/`（占位 `192.168.4.1`，
  **实际网段由板级驱动决定，待上板实测**：CAL-12），填家里 Wi-Fi 的 SSID 与口令。
  串口会打 `[PROV] enter AP mode ssid=ElderCare-XXXX …`、`[PROV] Wi-Fi 已连接 ssid=…`、`[PROV] SoftAP 已关闭，网关进入 STA 模式（mode=sta）`。
  详细步骤见 `rk2206-gateway/施工单-配网上板与本地API验证.md`。

## 2. 服务器（3 步）

> 全部命令在**仓库根**下依次粘贴即可（`server/` 里有 compose 文件，脚本自己会 `cd`）。

### 第 1 步：起容器

**做什么**

```bash
cd <仓库根>/server
docker compose up -d --build     # 起 db + api；首次会建库建表
docker compose ps                # 看两个容器是不是都是 healthy
curl -s http://127.0.0.1:3000/api/health     # 应返回一段 JSON（不是 connection refused）
```

**成功标志**：`docker compose ps` 里 `db` 与 `api` 都是 `healthy`；`curl` 有 JSON 返回。
（端口按项目规约**只绑 `127.0.0.1`**：api = 3000，MySQL = 3306。）

**失败怎么办**

| 现象 | 最可能原因 | 一句话处置 |
|---|---|---|
| `docker: command not found` / `Cannot connect to the Docker daemon` | Docker Desktop 没起（WSL 睡过一觉后引擎会掉线） | 先启动 Docker Desktop，等托盘图标稳定，再 `docker info` 确认 |
| 端口被占（`port is already allocated`） | 3000/3306 已被别的项目用了 | `API_PORT=13000 DB_PORT_HOST=13306 docker compose up -d`，后面命令里的 3000 换成 13000 |
| 容器起不来、日志里 MySQL 报错 | 数据卷里的旧数据与初始化脚本冲突 | `docker compose down -v` 后重来（**会清库**，只在自己机器上做） |

**做什么**


**成功标志**：命令正常结束（幂等，可反复跑）。它会**清空业务表**再灌成确定状态：60 天活动、10 条覆盖 7 类告警（含已处置）、
燃气/跌倒/门磁过程读数、断网补传样本；时刻锚定固定钟点，**凌晨跑与晚上跑结果相同**（报表数字可复算）。

**失败怎么办**

| 现象 | 最可能原因 | 一句话处置 |
|---|---|---|
| 报 `--demo 被拒绝` | `.env` 里 `APP_ENV=prod`（生产口径不允许清库） | 改成 dev（或删掉这行）后重跑 |

### 第 3 步：自检（判据 = 全绿退出码 0）

**做什么**

**失败怎么办**

| 现象 | 最可能原因 | 一句话处置 |

| 退出码 1、某几条红 | 数据不是 `--demo` 那份（被别的操作改过） | 回第 2 步重灌，再跑本步 |

## 4. 433 紧急按钮（3 步）

> **现状**：433 学习型套装（EV1527 接收模块 + 遥控器）用户已决定购买，**到货与接线均为待实测**；
> 接线口径见 `docs/技术/引脚与接线表.md` §2.2。**没到货就直接跳到本节末尾的降级路径。**

### 第 1 步：接线（接收模块 → 网关，三根线）

**做什么**：接收模块 `VCC` → 网关 `E53` 座 **3V3**；`GND` → `E53` 座 `GND`；`DO` → **`E53_GPIO_A2`**。

| 信号 | 网关侧 | 接收模块侧 | 注意 |
|---|---|---|---|
| 数据 | `E53_GPIO_A2`（内部上拉，下降沿触发） | `DO` / 继电器干接点 | 触发 = **拉低** |
| 电源 | `E53` 座 `3V3` | `VCC` | **不要接 5 V**（接收板多为 3.3 V） |
| 地 | `E53` 座 `GND` | `GND` | 必接 |

**成功标志**：网关串口**没有**出现 `[gw] ⚠ 433 中断注册失败：仅剩 UART 链路`（出现这行 = 中断没挂上，先查接线与引脚）。

**失败怎么办**：模块型号/极性未确认（CAL-W-07）→ 先量静态电平，按下时应由高变低；若相反，换接法并记录到接线表。

### 第 2 步：对码（学习型接收模块只需一次）

**做什么**：按接收模块上的学习键（多为轻触键，指示灯亮）→ 在灯亮期间按一次遥控器按键 → 灯闪/灭表示学到了。

**成功标志**：之后每按一次遥控器，接收模块的 `DO` 都会跳变（可用万用表或串口日志观察）。

**失败怎么办**：对不上 → 靠近一点重来；接收模块与遥控器必须配套（同编码芯片）；距离与误触率按 `引脚与接线表` CAL-W-07 记录。

### 第 3 步：试按一次（判据在网关串口）

**做什么**：按一次遥控器，同时看网关串口与声光模块。

**成功标志**（**这是 433 段的唯一硬判据**）

- 网关串口出现 **`[gw] 事件 M0-… type=sos level=2`**（事件源 `source=button`，契约 §6.12/§6.13）。
- 声光模块同响（本地报警，**不依赖网络**）。

**失败怎么办**

| 现象 | 最可能原因 | 一句话处置 |
|---|---|---|
| 串口没有任何 `[gw] 事件` | `DO` 没接到 `E53_GPIO_A2` / 极性反了 / 没对码 | 回第 1、2 步 |
| 有事件但 App 没收到 | App 在 Mock 模式（不发网络请求），或云侧链路没通 | 走 §3 第 3 步的在线服务器路径，或按下面的降级路径讲 |
| 声光不响 | 声光模块没接（`E53_GPIO_A5`，高电平触发） | 接上再试；只演 App 侧也能讲 |

**降级路径（模块没到货/对不上码）**：App → 设置 Tab →「演示与调试」→ **紧急求助** → 触发一次。
这条路径 `source=app`，与 433 的 `source=button` 是**两条不同的路径**，旁白不要混（口径见 `docs/参赛材料/16-录屏执行包.md` §5.1）。

## 6. 本单的边界（老实说在这）

### 6.1 哪些是「待实测」

- 本机（出这份单子的机器）**没有 RK2206 上板记录**、**没有 433 模块**、**没有 hdc 设备/模拟器**，所以：
