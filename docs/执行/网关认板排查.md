# 网关认板排查（一张纸）：RK2206 插上电脑认不出来，先照这张单走

> 面向：没做过单片机烧录的人。每一步都写清「**我到底该看到什么**」，看不到就照「失败怎么办」往下走。
> 本单**只解决「电脑能不能认出这块板」**，不解决烧进去之后能不能上网（那是 `rk2206-gateway/施工单-网关上板与上云验证.md` 的事）。
> **认板失败不阻塞其余准备**：服务器、App、433、两块 WS63 节点都能独立推进（见 §6），别以为全线卡住。
> 路径里的 `<本机用户>` = 你的 Windows 用户目录名（打开 `C:\Users\` 就能看到那个文件夹）；本单刻意不把本机用户名写进仓库。

## 0. 一句话结论（先看这条）

**本机实测（2026-10-19 09:3x）：Rockchip 驱动其实已经装好了，而且这块板子以前被认出来过**（历史记录见 §3 分支 5）。
所以现在最该做的**不是**再装一遍驱动，而是：**拔掉 → 换一根能传数据的线 → 直插机箱后面板 USB 口 → 按住 `MaskRom` 再点 `Reset`、约 5 秒后松手**。

## 1. 认板成功长什么样（先记住这 3 行）

| 在哪看 | 认板成功的原文 |
|---|---|
| RKDevTool 状态栏 | `发现一个MASKROM设备`（或 `发现一个LOADER设备`） |
| 设备管理器 | 多出一个 `Rockusb Device`（归类就是「Rockusb Device」类；有些系统显示在「通用串行总线设备」下）。属性 → 详细信息 → 硬件 ID 应是 `USB\VID_2207&PID_220A&...` |
| 设备管理器 →「端口(COM 和 LPT)」 | 认板**不会**新增 COM 口（COM 口是**调试串口**那条线的事，见 §4 末条） |

> 状态栏这三句原文是从本机 `RKDevTool` 的语言文件里核对出来的：`Language\Chinese.ini` 里 `IDS_FOUNDONEDEVICE=发现一个%s设备`、`IDS_FOUNDNODEVICE=没有发现设备`、`INFO_DOWNLOAD_IMAGE_OK=下载完成`；2.86 与 2.96 两份内容一致。

## 2. 症状表（照你现在的现象对号）

| 你看到的现象 | 它在说什么 | 先做哪一步 |
|---|---|---|
| 设备管理器有一条 `未知 USB 设备(端口重置失败)`，硬件 ID `USB\VID_0000&PID_0001\...` | 设备**没回答**枚举请求（属性里问题代码 = 43 / `CM_PROB_FAILED_POST_START`）。**不是驱动装错**，是这条路根本没通 | §3 分支 1–3 |
| 那条设备的「驱动程序」页显示 `usb.inf`（Microsoft 通用） | 还没轮到 Rockchip 驱动匹配（因为设备没报出 `VID_2207`） | §3 分支 1–2 |
| 「端口(COM 和 LPT)」没有新增 COM 口 | **正常**：认板走 USB-OTG，不产生 COM 口 | 继续 §3 |
| RKDevTool 状态栏 `没有发现设备` | 没进 MaskRom / 线插错口 / 线只供电 | §3 分支 2–4 |
| 设备管理器里能看到「Rockusb Device」但是灰的/幽灵条目 | 曾经插过、现在不在线，不代表这次认到了 | §3 分支 5 |
| 本机现在有 3 个 CH340：COM14、COM15、**COM17**（实测 2026-10-19 09:3x） | 多出来的 `COM17` 是 10-19 08:15 新插上的（COM14 是 10-17、COM15 是 10-18 插上的）——它**很可能就是网关板的调试口**，但本次只读实测**不能确认**，详见 §2.1 | §2.1 |

### 2.1 COM17 是不是网关板的调试口？（2026-10-19 只读实测，结论：**不能确认**）

**① 它是什么设备、跟那条报错设备是不是同一个**

- COM17 = `USB-SERIAL CH340`，硬件 ID **`USB\VID_1A86&PID_7523\8&162F3E69&0&1`**（父设备 `USB\VID_1A40&PID_0101\7&27c58f36&0&2`）。
- 本单 §2 第 1 行那条报错设备是 **`USB\VID_0000&PID_0001\7&26253362&0&1`**（父设备 `USB\VID_05E3&PID_0625\6&72fcec3&0&4`）——**两者是不同的设备、挂在不同 PC 口上**（硬件 ID、父设备都不同），不是同一个东西的两副面孔。

**② 三档波特率的逐字记录（8N1，各 15 s，被动监听：脚本自报 `rts=low reset=False`，即不复位）**

| 波特率 | 采集脚本控制台首行（逐字） | 日志文件里的内容（逐字） |
|---|---|---|
| 115200 | `# OPEN ok COM17 @ 115200 8N1 seconds=15 rts=low reset=False` | `# EOF port=COM17 seconds=15 lines=0` |
| 921600 | `# OPEN ok COM17 @ 921600 8N1 seconds=15 rts=low reset=False` | 同上（逐字相同） |
| 1500000 | `# OPEN ok COM17 @ 1500000 8N1 seconds=15 rts=low reset=False` | 同上（逐字相同） |

⇒ **三档都是「无输出」**：15 s 里一行数据都没有（`lines=0`）。三份日志各 **37 字节**、内容逐字相同（`sha256 ad4958f0333ca25153ef30b3025321cac0e088f8aa6bf9a8d8ae4d479c8e4f00`），文件里只有那一条 EOF 行（`# OPEN ok …` 是脚本打到**控制台**的，不落文件）。原始日志（不入库，`ws63-firmware/spike/logs/` 被 `.gitignore:24` 忽略）：`t116-com17-115200.txt`、`t116-com17-921600.txt`、`t116-com17-1500000.txt`。

**③ 判定与证据等级**

| 判据 | 本次结果 |
|---|---|
| **有启动横幅/周期日志 ⇒ 确认** | 未出现（三档 0 行） |
| **无输出 ⇒ 不能确认**（也不能排除） | **适用**：板子若在 08:15 换口前就已启动过，横幅只在**启动那一刻**输出；15 s 被动窗口看不到是正常的 |
| 间接旁证（本机 PnP 记录，只读） | 支持「是调试口」但**不构成直接证据**：① `CH340 (COM16)` 在 10-19 **08:15:34 消失**，`COM17` 在 **08:15:45 出现**（隔 11 秒）⇒ 像同一根线**换了个 USB 口重新插**；② 10-13 那次成功烧录时，与 `Rockusb Device` **同一父 hub** 下也出现过一条 CH340（`COM11`，13:37:20–13:37:52）⇒ 网关板历来会以「Rockusb + CH340」两种身份出现 |

**留给用户的终判（本单不做，属"动板子"）**：用**插拔对照法**——拔掉 COM17 那根线看它是否从端口列表消失、插回来是否恢复（消失/恢复 ⇒ 就是这根线对应的板子）；或给板子复位一次看是否出横幅（复位=写板动作，本单不做）。在确认之前，**认板步骤仍按 §3 走**——那条报错设备与 COM17 无关，即使 COM17 是调试口，USB-OTG 烧录链路的问题也依旧存在。

## 3. 六个分支（每支只做 3 件事）

> 用法：先按 §2 对号找到该做哪一支，**命中即停、不必依次做完**。每支都有自己的「成功标志」和「失败怎么办」，看不到成功标志就往下一支走。

### 分支 1：拔下来，停 10 秒，再插回去（装完驱动这一条必做）

1. 把网关板的 USB 线**从电脑上拔掉**（板子那头也拔），数到 10。
2. 插回去——**直插机箱后面板**的 USB 口，中间不要接 Hub / 扩展坞 / 延长线。
3. 同时在设备管理器里按 `F5` 刷新，看 §1 那三行有没有变。

**成功标志**：那条 `未知 USB 设备(端口重置失败)` 消失，换成 `Rockusb Device`；或 RKDevTool 状态栏出现 `发现一个MASKROM设备`。
**失败怎么办**：本机实测这条报错设备**从 2026-10-18 08:28 插上后一直没拔过**（Windows 的 PnP 记录：`LastArrivalDate`），而驱动是后来才装的——**装完驱动不重新插拔，Windows 不会重新枚举**。这一步必须先做完，再往下走。

### 分支 2：换一根「能传数据」的 USB 线

1. 换一根**确定能传数据**的线（手机传文件用过的那根、或开发板原装线）。
2. 排除「只供电」的线：那种线插上，Windows 报的正是 `VID_0000&PID_0001` / 端口重置失败。
3. 换完仍按分支 1 拔插一次并刷新。

**成功标志**：同分支 1。
**失败怎么办**：手上只有一根线 → 先用分支 6「换机验证」把线排除掉，再回来做分支 3。

### 分支 3：换插口 + 保证供电

1. 直插**机箱后面板**的 USB 2.0 口（黑色那种）；前面板、Type-C 集线器一律先不用。
2. 板子若还有**另一个供电口**，按「USB 5 V / 2 A」补上（`docs/技术/引脚与接线表.md:111`），再试。
3. 再按分支 1 拔插刷新。

**成功标志**：同分支 1。
**失败怎么办**：本机历史记录显示，这块板**以前是在另一个 USB 宿主上被认出来的**（`USB\VID_2207&PID_220A\7&27C58F36&0&1`，2026-10-13 13:35），而这次报错的挂在 `7&26253362` 这个**不同的宿主**上——**换回直插口值得先试**。仍不行 → 分支 4。

### 分支 4：进 MaskRom（烧录模式）

1. USB 线插板子的 **USB-OTG 口（烧录口）**——不是调试串口那个 Type-C 口（两个口是分开的，见 `docs/技术笔记/引脚与开发环境.md:102-104`）。
2. **按住 `MaskRom` 键不要松**（有的批次丝印写 `BOOT`）→ 点一下 `Reset` 键（按下即松，`MaskRom` 继续按住）→ **数到 5 秒再松开 `MaskRom`**。
3. 打开 `RKDevTool.exe`，看它状态栏（右下角/底部那条）。

**成功标志**：状态栏 **`发现一个MASKROM设备`**。
**失败怎么办**：显示 `没有发现设备` → 回分支 1 重来。**时机很重要**：松手早于 5 秒、或把 `Reset` 也按成了长按，都进不去。仍不行 → 分支 5。

### 分支 5：驱动装没装、有没有绑定（本机已经装好）

1. **本机实测（2026-10-19 09:3x）**：驱动包 `oem58.inf`（原始名 `rockusb.inf`，提供者 `Fuzhou Rockchip`，版本 `5.14.0.0`，Microsoft WHCP 签名）**已安装**，并且**曾经绑定成功过**：历史设备 `Rockusb Device`，硬件 ID `USB\VID_2207&PID_220A\7&27C58F36&0&1`（出现在 2026-10-13 13:35:58）——那天正是成功烧录的那次。
2. 自己看一眼：设备管理器 →「查看 → 显示隐藏的设备」→ 找 `Rockusb Device` → 右键「属性 → 驱动程序」，提供者应为 `Fuzhou Rockchip`。
3. 只有在**上面这条幽灵记录都没有**时，才重装：**以管理员身份运行**
   `C:\Users\<本机用户>\Downloads\DriverAssitant_v5.14\DriverAssitant_v5.14\DriverInstall.exe` → 点「驱动安装」→ 装完**重新插拔**板子（回到分支 1）。

**成功标志**：幽灵记录里能看到 `Fuzhou Rockchip` 的驱动（本机现状就是这样）。
**失败怎么办**：装完仍无记录 → 走分支 6。原路径的文件不在了也没关系，SDK 里还有一份：`device/rockchip/tools/windows/DriverAssitant/DriverInstall.exe`。

### 分支 6：换机 / 换口，作为终判

1. 把板子 + 线拿到**另一台电脑**（或同一台机器的另一个 USB 口），做分支 1、4。
2. 对照：**另一台能认出来** ⇒ 本机 USB 口/系统侧的问题；**两台都不认** ⇒ 板子/线/手法的问题（手法先按分支 4 对一遍）。
3. 把结果（设备管理器截图 + RKDevTool 状态栏原文）贴回来就行，不用自己猜。

**成功标志**：至少一处出现 §1 的 `Rockusb Device` / `发现一个MASKROM设备`。
**失败怎么办**：两台都不认时**别再反复装驱动**；直接回报「两台都不认 + 现象原文」，这条链路改按「板子 USB-OTG 口 / 线材 / 供电」方向查。

## 4. 认出板子之后接着做什么（不是本单范围，给个衔接）

- 认到 `发现一个MASKROM设备` 后：切「下载镜像」页，**只留两行**——`LoaderToDDR → rk2206_db_loader.bin`、`firmware → <仓库根>\rk2206-gateway\out\gateway-Firmware.img`（地址 `0x00000000`）→ 点「执行」→ 等到 `下载完成`。
  必须删掉原厂 `config.cfg` 里指向 `C:\Users\xiexi\Downloads\u-boot.itb` 的那一行，否则会弹 `u-boot.itb下载项不存在,停止执行!`。
- 逐条步骤与判据：`docs/执行/演示环境搭建执行单.md` §1 第 3 步（即 §1.3「烧网关 RK2206（RKDevTool）」，第 174–230 行）、`rk2206-gateway/施工单-网关上板与上云验证.md` §1.3 与 §3。
- 烧完把线改插**调试串口**那条 Type-C，波特率 **115200**，按一下 `Reset`，应看到
  `[gw] ---- RK2206 网关 M0 启动 ELDERCARE-GW-M0-v1.2 (契约 v1.2) ----`。
  **只有这一步才会新增 COM 口**：用「插拔对照法」认号——拔掉串口线看端口列表，插上再看，新多出来的那个就是它。（现场已有一个待认的 CH340：COM17，见 §2.1。）

## 7. 本单的边界（老实说在这）

- **待实测**：本单的判断路径基于 ①本机 Windows PnP 记录（2026-10-19 09:3x：报错设备 `USB\VID_0000&PID_0001\7&26253362&0&1`、问题代码 43、驱动 `oem58.inf` 已装且有 2026-10-13 的成功绑定记录）②仓库里已有的板级手册转述（`施工单-网关上板与上云验证.md` §1.2/§1.3、`docs/技术笔记/引脚与开发环境.md:102-104`）。**「拔插 / 换线 / 换口 / 进 MaskRom」这几步是否真能让这块板重新认出来，未经实测。**
- 设备管理器里 `Rockusb Device` 的归类与显示名在不同 Windows 版本上有差异，以硬件 ID `USB\VID_2207&PID_220A...` 为准更稳。
- COM17 的三档波特率只读实测（2026-10-19 09:48，115200/921600/1500000 各 15 s）**均为无输出**，故「COM17 是网关板调试口」未获直接证据，只有 §2.1 的 PnP 旁证。
- 本单不覆盖：烧录过程中的报错处置（在 `施工单` §6）、烧完的联网/上云（同单 §4 起）、配网（`rk2206-gateway/施工单-配网上板与本地API验证.md`）。
