# IoTDA 三件套：厂商侧一次性配置清单（10 分钟）

> ⛔ **本文仅厂商 / 维护使用，不进用户手册、不进提交包。**
> 里面有控制台路径、凭据占位与串口命令，给用户看只会让他以为"要自己建云"。
>
> **定案口径（2026-10-21）**：华为云 IoTDA 与自建服务器都由**厂商侧**运营。
> **用户不建产品、不注册设备、不填任何云端凭据**；用户侧只有「连家里 Wi-Fi → 开始使用」两步
> （见 `rk2206-gateway/施工单-配网上板与本地API验证.md` §4.5）。
>
> **本文的读者**：拿得到华为云账号、要给出厂网关写一次凭据的运维/产线同学。
> 详细物模型与故障排查在 `docs/执行/IoTDA建产品与设备指引.md`（同一批文档，仅厂商侧）。

---

## 0. 一句话：谁、在哪、配完用户看到什么

| 问题 | 答案 |
|---|---|
| 谁配 | 厂商运维 / 产线（有华为云控制台账号的人）。**用户全程不参与** |
| 在哪配 | ① 华为云控制台建产品/设备/转发规则 ② 网关调试串口 `gwkv set`（**最高优先级**）或页面「厂商维护」面板兜底 |
| 配完用户侧看到什么 | 配网页**没有**任何华为云字段；状态卡只有一行「云端服务：**已配置**」。用户只填家里 Wi-Fi |

> 用户侧验收只有一句：**打开配网页 → 状态卡「云端服务：已配置」→ 只填 Wi-Fi 就能用**。

## 一、建产品（一次，2 分钟）

1. <https://console.huaweicloud.com/iotdm/> → 左上角地区 **华北-北京四** → 首次进入按提示开通
   「设备接入 IoTDA」，**标准版 / 按需**（不选包年包月）。
2. 左侧「设备接入」→「产品」→ 右上「创建产品」，填：

   | 字段 | 填什么 |
   |---|---|
   | 产品名称 | `elderly-care-gateway` |
   | 协议类型 | **MQTT** |
   | 数据格式 | **JSON** |
   | 设备类型 | `gateway`（随便填） |
   | 其余 | 默认 |

3. **物模型照 `docs/执行/IoTDA建产品与设备指引.md` §3 建一次**（服务 `gateway` + 14 属性 + 6 命令）。
   不建也能转发原始 JSON，但控制台「设备影子」看不到属性、命令下发也没有界面可选——
   **售后排障全靠这两块，别省**。

**看到什么**：产品列表出现 `elderly-care-gateway`，协议 MQTT、数据格式 JSON。

---

## 二、注册网关设备（一次，2 分钟）

> **只注册 1 台**（网关 M0）。节点不直连云。

1. 左侧「设备」→「所有设备」→ 右上「注册设备」。
2. 选刚建的产品；**设备标识码**填网关 SN（`GW_DEVICE_SN`，形如 `M0-3F1A2B`）；
   设备 ID 留空（平台按 `产品ID_设备标识码` 生成）；认证类型 **密钥**。
3. 点「确定」→ 弹窗显示 **设备 ID** 与**设备密钥**（密钥**只显示这一次**，丢了只能「重置密钥」）。

**看到什么**：设备列表里这台设备**未激活**（还没连过），状态列是灰的。

> 这两个值是凭据，**不进仓库、不进群**。写进网关后只回传"已写入、指纹 XXXXXXXX"。

---

## 三、取接入地址（1 分钟）

左侧「总览」→ 实例基本信息里的「**接入信息**」→ 抄 **MQTT 接入地址**（形如
`xxxxxx.iot-mqtts.cn-north-4.myhuaweicloud.com`；IP 形式也照抄）+ 端口 **1883**（明文，不用 8883）。

---

## 四、写进网关（二选一，串口优先）

| 路径 | 谁用 | 怎么用 |
|---|---|---|
| **串口 `gwkv set`**（最高优先级） | 出厂 / 产线 | 调试串口 115200 8-N-1，敲下面这条 |
| 页面「厂商维护」面板 | 售后 / 现场返修 | 配网页连点标题 **5 次** → 出现面板 → 填三件套 → 保存（`POST /api/config`） |

```
gwkv set host=<接入地址> port=1883 device=<设备ID> secret=<设备密钥> time=192.168.1.100 timeport=8000
gwkv show
```

- `time=`/`timeport=` 不给就走公网 NTP；给了就用家里那台服务器取时（默认 `192.168.1.100:8000`，`gw_config.h:154-155`）。
- **看到什么**：`[kvcfg] OK：已写入 Flash KV …（读回逐字节一致）`，`gwkv show` 里
  `接入地址 / 设备 ID / 时间服务器` 三行有值、密钥显示 `N 字节（指纹 XXXXXXXX，不回显）`。

---

## 五、数据转发到服务器（一次，3 分钟）

控制台「规则」→「数据转发」→「创建规则」：

- 数据来源：**设备属性**（`properties/report`）与 **设备消息**（`messages/up`）各建一条；
  ⚠️ **没有「设备事件」这个来源**，事件只能走 `messages/up` 的 topic 过滤（详见指引 §6.0）。
- 转发目标：**第三方应用服务（HTTP 推送）** → URL
  `http://<服务器地址>/api/iotda/webhook?token=<webhook_token>` → Token 与服务器 `.env` 的
  `WEBHOOK_TOKEN` 一致。
- 建完点「**启动**」→ 目标列表里点「**测试**」→「连通性测试」应回 **200**。

**看到什么**：规则状态「已启动」；通道详情里「推送速率」随属性上报跳动、积压量保持 0。

> 本机联调**没有公网 IP** 时不要硬配这一条：先只在控制台「设备影子/消息跟踪」观察，
> 需要真转发就用内网穿透（两种做法的代价见指引 §6.2）。

---

## 六、配完自检（3 条，全过才算配好）

| # | 在哪看 | 判据 |
|---|---|---|
| 1 | 控制台「设备 > 所有设备」 | 网关重启 30–60 s 后状态变**在线**；串口有 `[gw] IoTDA 已连接 clientId=<设备ID>_0_1_<YYYYMMDDHH>` |
| 2 | 控制台「设备影子」 | 60 s 内「上报值」刷新出 14 个属性（`presence`/`temp`/`alarm_state` …） |
| 3 | 配网页（手机） | 状态卡「云端服务：**已配置**」，页面**搜不到**「接入地址 / 设备 ID / 设备密钥」 |

三条都过 → 这台网关可以出厂。任何一条不过 → 转 `docs/执行/IoTDA建产品与设备指引.md` §7（认证失败 0x02/0x04、取时链、QoS2）。
