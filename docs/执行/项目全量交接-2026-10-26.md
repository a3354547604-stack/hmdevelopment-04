## 3. 产品形态与技术架构

```
传感器 ──► WS63 节点 ×3 ──星闪(SLE, 星形, 最多 8 连接)──► WS63 汇聚 ×1
                                                              │ UART 115200 8N1
                                                              ▼
                                            RK2206 网关（OpenHarmony 3.0 LTS）
                                              │ 本地规则 / 阈值下发 / 断网缓存
                                              │ MQTT 明文 1883（一机一密 HMAC）
                                              ▼
                                    华为云 IoTDA（设备接入 + 数据转发规则）
                                              │ HTTP 转发（webhook + token）
                                              ▼
                            自建服务器 123.206.99.28（FastAPI + MySQL8 + nginx）
                                              ▲
                                              │ REST（JWT）
                                              │
                                    鸿蒙 App（ArkTS）/ 安卓 App（Kotlin，现场演示用）
```

**关键取舍（都有决策记录）**：

- **汇聚只收发不处理**：WS63 汇聚按契约把节点 JSON 原样透传给网关；规则、阈值、上云都在网关（用户 m00228 明确"这不是网关吗"）。
- **配网走网关的 SoftAP + 手机浏览器 H5**（不是 App 内配网）：因为 RK2206 没有蓝牙，而 H5 是唯一"手机能开、不用装 App 也能配"的方案；App 内配网页记为 P1。
- **Wi-Fi 口令与 IoTDA 三件套都不写死在固件**：网关 Flash KV 可改，配网页可填。
- **MQ-2 保留、MQ-5/MQ-7/LED/蜂鸣器/声光/蓝牙/PIR/电量/4G/语音播报 → 全部 r5 删除或降 P1**（用户逐条拍板）。

### 4.3 网关 ↔ 汇聚 接线（**当前卡点，未通**）

| 网关侧 | 汇聚侧 | 备注 |
|---|---|---|
| `E53_UART0_TX_M0`（E53 座，丝印 `UART_TX`） | `RX1`（排针 24） | 必须交叉 |
| `E53_UART0_RX_M0`（丝印 `UART_RX`） | `TX1`（排针 23） | |
| `GND` | `GND` | 必须共地 |

- 两侧都是 **115200 8N1 无流控**。
- 汇聚固件：`uapi_pin_set_mode(IO15=TX, IO16=RX, MUX)`；网关固件：`PinctrlSet(GPIO0_PB6=TX, GPIO0_PB7=RX, MUX_FUNC2)`（【实测】用户万用表通断 2026-10-27；`rk2206-gateway/src/gw_config.h:25-26`）。**注意**：`samples/b6_uart0/uart_example.c:46-47` 的注释写 PB6=RX，已由该实测证伪，只算线索。
- **实测结论（2026-10-26）**：网关 `uinfo` 显示 `last_write_rc=74 last_write_len=74`（写出了 74 字节）；汇聚 `STAT ub=N` 能看到字节在进（曾到 591），但 `rx=0`（解析不出帧）→ 字节有、帧不成形。**下一步是给汇聚刷带"首 32 字节 hex 打印"的诊断固件**（源码已改，未构建）。

## 6. 云端：IoTDA + 公网服务器

### 6.1 华为云 IoTDA（厂商侧，用户看不到）

- 区域：华东-上海一；接入地址 `f26ec94a9c.st1.iotda-device.cn-east-3.myhuaweicloud.com`（解析 `124.70.218.131`），端口 **1883 明文**（8883 也可用）。
- 产品 `elderly-care-gateway`，设备标识码 `M0`，设备 ID `6ad8e0bae094d615927b7777_10-dc-b6-91-00-00`。
- **鉴权（关键）**：`clientId = {设备ID}_0_{0|1}_{YYYYMMDDHH(UTC)}`、`username = 设备ID`、`password = Base64(HMAC-SHA256(key=时间戳字符串, message=设备密钥))`。
  - **这是踩了很久的坑：HMAC 的 key 是"时间戳"，message 才是"密钥"**，反过来会一直 `CONNACK rc=4`。
  - 报文体必须是 QoS0 或 QoS1；我们用 **QoS0**（QoS1 等 PUBACK 会超时断连）。
- **数据转发规则 2 条**（服务器收数据的前提）：
  1. 属性：数据来源=设备属性 → 事件"属性上报" → 转发到 `http://123.206.99.28/api/webhook/iotda`（Token 见服务器 `.env` 的 `WEBHOOK_TOKEN`）。
  2. 事件：数据来源=设备消息 → 事件"消息上报" → 同一地址（用于 alarm/fall 事件）。
- 物模型：服务 `env`/`gas`/`fall`/`alarm`/`heartbeat`，属性名与契约 §5 一致。

### 6.2 公网服务器

- `ssh qinyixiang@123.206.99.28`（口令与 sudo 口令由用户保管，**不写进仓库**）。
- 栈：Docker Compose（db=MySQL8、api=FastAPI、proxy=nginx），对外只开 80；**db 不发布端口，api 只绑 127.0.0.1**。
- 部署路径 `/home/qinyixiang/HMProgram/server`；更新：`git pull && docker compose -f docker-compose.prod.yml up -d --build api`。
- 健康检查：`curl http://123.206.99.28/api/health` → `{"db":"ok"}`。
- Webhook token 在 `server/.env` 的 `WEBHOOK_TOKEN`（600 权限）；`IOTDA_DISPATCH_MODE=mock`（当 IoTDA 还没配好时，服务器用合成数据跑通链路）。

- **网关**：烧录（RKDevTool 反复崩溃 → 自建 usbipd + SDK `flash.x86_64` 的 Linux 链路，最终由用户刷成功）。
- **按键 K1–K4**：从 ADC ch5 悬空 → 定位到基线判据写错（满量程被当"无按键"）→ 修好（实测 6/554/1063/1669 mV）。
- **联网**：`netif_default` 恒 NULL（SDK 从不设默认网卡）→ `connect()` 直接 EHOSTUNREACH → 修 `netifapi_netif_set_default`。
- **取时**：服务器 `/api/time` 返回 `utc_epoch`，固件只认 `server_time|epoch|ts|unix` → 服务器加 `epoch` 别名。
- **IoTDA 鉴权**：`rc=4` 折腾多轮 → 最后发现 **HMAC 参数顺序反了**（key=时间戳、msg=密钥）。
- **QoS1 断连**：等 PUBACK 超时导致 34 s 一断 → 改 QoS0。
- **数据落地**：首次在服务器 `sensor_readings` 看到真实遥测。

### 阶段 4（10/23–26）：多板联调 + 文档治理
- 汇聚 ↔ 网关 UART：先发现"判据写反"（`uapi_uart_write` 返回"已写字节数"，却被当失败），修好后又发现**汇聚收不到字节**（`ub=0`）→ 换线后 `ub` 涨到 591 但 `rx=0`（帧不成形）。

## 11. 踩过的坑（按"最值钱"排序）

### 技术坑
1. **华为云 HMAC 参数顺序**：`HMAC(key=时间戳, msg=密钥)`，反了永远 `rc=4`。
2. **`uapi_uart_write` 返回"已写字节数"**，不是 0/负数；用"负数才算成功"会把每条成功都判失败。
3. **`netif_default` 为 NULL**：SDK 不自动设默认网卡，`connect()` 直接 `EHOSTUNREACH`（表现为"packets 一个都不发"）。
4. **SLE `conn_id` 首条就是 0x0**：不能拿 `conn_id==0` 当"未连接"哨兵。
5. **SLE 发现回调必须按 `structure_result->type` 分支**，否则自我重入（12 Hz 死循环）。
6. **CCCD 句柄是 `prop_handle`（0x11）+ type 0x02**，不是 `prop_handle+1`；`write cfm` 恒 0x7，不能当成功判据。
7. **QoS1 等 PUBACK 超时**会让 paho 关会话（34 s 一断）；IoTDA 上报用 QoS0 稳。
8. **LD6002C 灵敏度 10 时需持续跌倒 15–20 s** 才报；顶装 2.2–3.0 m。
9. **RK2206 Flash KV 读在 Flash 初始化之前会失败**（`E_FLASH`）→ 必须先 `FlashInit` 再读。
10. **`SetWifiModeOn()` 用的是 SDK 自己的 SSID**（不写 `VENDOR_ID_WIFI_ROUTE_SSID` 就连不上），且 `wifi_send_cmd` 失败分支会**死循环重发**。
11. **构建并发会互相污染** `custom/` 目录（曾把别人的源文件带进镜像）；必须一把锁串行。
12. **hvigor 默认 8 GB 堆**在 7.4 GB 的 WSL 上会 thrash（load 134）。

### 协作坑
1. **Agent Teams 调度器不看角色**：未认领的卡会被随机派给任何人 → 每张卡必须显式指定 owner。
2. **被移除的成员名不能复用**（"already been used"）→ 重建时用 `-op`/`-2` 后缀。
3. **`edit_plan` 在成员被移除后会失效**，只能靠 `reassign_task` 逐张救。
4. **质量卡 inScope 必须文件级**，目录级会报 `is undeclared` 结不了卡。
5. **口头结论会丢**：用户反复强调"写进文档"，因此有 `项目章程.md`/`接口契约.md`/`停机恢复检查点.md` 三个锚点。

## 13. 下一步行动清单

**A. 打通汇聚↔网关（最高优先，1 小时级）**
1. 构建带诊断的汇聚固件：`bash tools/build-lock.sh bash ws63-firmware/scripts/node-build.sh hub`
2. 烧到汇聚：`tools\ws63flash-port.exe <HUB_HUB.fwpkg> app COM<汇聚口> <log>`
3. 抓汇聚日志，看 `[HUB] RXFIRST n=… XX XX …`
   - 若是 `00 00 00…` 或 `FF FF…` → 电平/接线问题
   - 若是 `AA 55 …` 但帧头不对 → 协议/长度字段问题
   - 若什么都没有 → 引脚不对，换 UART 或换脚
4. 通了以后：网关敲 `uart` → 汇聚回 `0x21`；再发 `0x22` 绑定 M2 → 汇聚连节点 → 数据上云。

**B. 补齐硬件（用户做，30 分钟）**
- 另两块 WS63 烧 M1/M4 并上电；433 接收模块接 `E53_GPIO_A2`。

**D. 收尾**
