# 新购两块 WS63 板验收 + AT 指令支持度摸底

> 2026-10-22 写。对象：用户今天新买的两块 WS63 板（一块**润和/hihope**、一块**如般微**），插在电脑上 = `COM19` / `COM20`。
> 全部结论来自**实测串口日志**，没做任何烧录、没做 bootloader 握手、没发 `AT+RESTORE`。原始日志路径见 §9（仓库外，不入库）。
> 一句话：**两块板都是好的，都能用；`COM19`=`如般微`（原厂 XF_AT 完好），`COM20`=`润和`（出厂 SDK 示例固件，带雷达 AT）。润和板可以直接当第 4/5 块节点候选，但要等烧录窗口实测才敢签字。**

## 一、结论速览

| 项 | `COM19` | `COM20` |
|---|---|---|
| 板子 | **如般微 E528H-WS63** | **润和（HiHope NearLink WS63E 系）** |
| 板载 USB 转串口 | CH340（`PID_7523`） | CH340K（`PID_7522`） |
| 当前固件 | **厂商 AT 固件** `XF_AT-V2.1.13-d`（编译于 2025-12-23 15:18:01） | **海思 SDK 原生示例固件**（`ws63_liteos_application` + `at_plt` + `at_radar`），**无厂商品牌串** |
| 启动横幅 | `>> XF AT <<`（8 行，静默） | 无横幅；40 行完整启动链，到 `rf cali OK. time cost:24, ret:0` |
| 串口参数 | 115200 8N1 | 115200 8N1 |
| 换行符 | **只认 `\r\n`**（`\r` 挂起、`\n` 回 ERROR） | `\r\n` / `\r` / `\n` **三种都认**，且会回显 |
| 健康判定 | ✅ 通过（AT 层 13 条查询全部有确定响应） | ✅ 通过（启动链完整、射频校准 ret=0、芯片温度 45 ℃） |
| 能否作节点/汇聚 | ✅ **能**，且是"同型号第 3/4 块"——我方 `.fwpkg` 已在同型板实证跑通 | ⚠️ **大概率能**，SDK 自带该板构建目标；但需烧录窗口实测 flash/下载模式/引脚 |

## 二、方法与边界（做之前先说清做了什么、没做什么）

| 做了 | 没做 |
|---|---|
| `AT` 层只读探测 + `AT+RST`（firmware 自身复位，等于热启动） | ❌ 没烧录、没碰 `tools/ws63flash-port.exe` |
| 三种换行符矩阵（`\r\n` / `\r` / `\n`）逐板实测 | ❌ 没做 bootloader 握手（会把板子留在半砖） |
| 打码类查询：`AT+SWINFO` / `AT+CSV` / `AT+MAC?` / `AT+RDTEMP` / 雷达 GET | ❌ 没发 `AT+RESTORE`（恢复出厂，红线） |
| 自建 `at-probe.ps1`，**DTR/RTS 一律保持 false 且从不断言** | ❌ 没开 WiFi/星闪（`AT+STASTART` 属状态变更，超出"只读"边界） |
| 用完释放端口并留证据（§10） | ❌ 没改 `ws63-firmware/`，没动在跑的服务 |

> 为什么 RTS 必须保持 false：本机 `docs/技术笔记/串口查看与日志判读.md` 有实测记录——WS63 板的 RTS→EN 低有效，程序一把 RTS 拉高板子就装死，而且这个状态**跨 `Close()` 保持**。本次探测全程 DTR/RTS=false，所以两块板都正常应答，不可能被我方脚本按在复位里。

## 四、判定依据链（为什么不是猜的）

### 4.1 `COM19` = 如般微：**逐字命中仓库里的历史记录**

`AT+SWINFO` 原始回显：

```
SDK Version:XF_AT-V2.1.13-d
SW Desc:
SW ID:
SW Create by:X
Compiled:[Dec 23 2025]-[15:18:01]

OK
```

翻转复位后的第一行横幅是 `>> XF AT <<`。

仓库里 10-14 那次（用户原来那两块如般微 E528H-WS63，**刷我方固件之前**）留下的记录是（`docs/决策记录/通宵自研固件-任务红线与过程记录.md:32-33,49`）：

| 记录项 | 历史值（10-14，已知如般微板） | 今日 `COM19` | 是否一致 |
|---|---|---|---|
| 版本串 | `XF_AT-V2.1.13-d` | `XF_AT-V2.1.13-d` | ✅ 逐字 |
| 编译时间 | `2025-12-23 15:18:01` | `[Dec 23 2025]-[15:18:01]` | ✅ 逐字 |
| 复位横幅 | `>> XF AT <<` | `>> XF AT <<` | ✅ 逐字 |
| 底层 SDK | `ws63_1.10.106` | （XF_AT 无 CSV 命令，本轮未直接读到） | — |

另外 `ws63-firmware/doc/6-板子身份指纹与区分方法.md` 早就把 `>> XF AT <<` 当作"如般微原厂固件的身份指纹"（我方自研固件打的是 `---- round N ----`）。

⇒ **不是排除法，是正面指纹命中**。`COM19` = 如般微。

### 4.2 `COM20` = 润和：命令集指纹 + SDK 线索 + 排除法

`COM20` **没有任何厂商品牌串**（无横幅、`AT+SWINFO`→ERROR、`AT+IPR?`→ERROR、`AT+CFG?`→ERROR），但它把自己的出处暴露得很清楚（①~④ 里的 SDK 源码路径都相对本地 SDK 根 `~/ws63/fbb_ws63-master/`，**不在本仓库**）：

1. **启动日志里两行注册打印**：
   ```
   los_at_plt_cmd_register EXCUTE
   los_at_radar_cmd_register EXCUTE
   ```
   前者由 SDK 自己的 `src/middleware/utils/at/at_plt_cmd/at/at_plt.c:132` 打出（不是厂家自定义打印）；后者对应 `src/application/ws63/ws63_liteos_application/main.c:163` 的 `weakref("at_radar_cmd_register")` + `main.c:550-551` 的按需调用。
2. **周期日志 `at_recv %u`** 来自 `ws63_liteos_application/main.c:256` 的 `at_uart_get_rcv_cnt()` —— 即**海思 SDK 自带应用示例**的 main，不是厂家应用。
3. **AT 命令集与 SDK 模块一一对应**：`at_plt`（MAC/RST/HELP/CSV/DATE/DIEID/RDTEMP…）全在，`at_radar` 在，`at_ip` 只漏了一点（`AT+IFCFG` 有响应但只显示 `lo` 回环），`at_wifi` / `at_bt` / `at_sle` 全不在（`AT+SWINFO`/`AT+IPR?`/`AT+CFG?`/`AT+SLENAME?`/`AT+BLEENABLE?`/`AT+STASTATE` 一律 ERROR）。⇒ 这是一个"plt + 雷达"的最小 SDK 示例镜像。
4. **雷达是这块板的卖点**：`AT+RADARGETST` / `AT+RADARGETISO` / `AT+RADARGETDLY` 三条 GET 全部有正常响应（见 §7）。而本地 SDK 的 `README.md:44` 明写：
   > 模组：WS63E星闪模组 —— **润和软件的星闪模组，基于 WS63E 的解决方案，支持雷达人体活动感知**
   
   `docs/评审与验证/南向可行性复核-2026-10-15.md:193` 也记：润和 HiHope NearLink_DK_WS63E **就是** `fbb_ws63` 里 `vendor/HiHope_NearLink_DK_WS63E_V03` 的目标板（该 vendor 目录里就挂着 `demo/radar_led`）。
5. **排除法**：用户两块板一润和一如般微；`COM19` 已由正面指纹锁定为如般微，且 `COM20` **不是** XF_AT（没有 `XF_AT` 版本串、没有 `AT+SWINFO`、SLE 设备名不是 `XF_SLE`）⇒ `COM20` = 润和。

⚠️ **唯一未闭环**：PCB 丝印/模组丝印没法从串口读出来，只能人眼看。**请用户顺手确认 `COM20` 那块板丝印是不是 `HiHope` / `WS63E` / `HopeRun`**——如果丝印写的是别的（比如也是如般微但雷达版），只需改本文件 §1 的"板子"一行，其余结论（支持度、能否当节点）不受影响。

两块板都打 `Flash Init Fail! ret = 0x80001341`。这是 **WS63 平台普遍现象**，我方自己的固件也照打：

## 五、冷启动日志（原样）

### 5.1 `COM19`（如般微 / XF_AT）：8 行，然后静默

```
boot.
Flash Init Fail! ret = 0x80001341
verify_public_rootkey secure verify disable!
verify_params_key_area secure verify disable!
verify_params_area_info secure verify disable!
verify_image_key_area secure verify disable!
verify_image_code_info secure verify disable!
>> XF AT <<
```

- 触发方式：`AT+RST`；抓取窗口给了 **4 s**，之后无任何新增字节 ⇒ 这 8 行就是 XF_AT 的全部启动打印。
- 首次开端口那次抓到的是同一批行（开头多一个残字节 `?`），说明开端口前启动已经开始（CH340 的 DTR/RTS 释放顺带复位了一下板子）。
- **未见** MAC、未见 `app version`、未见射频校准行 ⇒ XF_AT 把启动期调试日志基本关掉了。这是该固件的行为，不是板子问题（同型板历史日志一致）。

## 七、换行符矩阵（很多 AT 固件只认 CRLF，实测确实如此，但只对数一家）

发 `AT` + 不同行尾，看有没有应答：

| 行尾 | `COM19`（XF_AT） | `COM20`（SDK 示例） |
|---|---|---|
| `\r\n`（CRLF） | `\r\nOK\r\n` ✅ | `AT\r\nOK\r\n` ✅（带回显） |
| `\r`（CR） | **一个字节都不回**（解析器在等 LF，挂起） ❌ | `AT\r` + `OK\r\n` ✅ |
| `\n`（LF） | `\r\nERROR\r\n` ❌ | `AT\n` + `OK\r\n` ✅ |

**操作结论**：以后任何脚本/网关要跟这两块板说 AT，**统一用 CRLF**。对 XF_AT 若只发 `\r`，对面会静默挂起（很容易被误判成"板子死了"）；只发 `\n` 会被当错误帧。

## 十一、这两块板能不能进项目（对照我方 `fbb_ws63` 自研固件）

前提：**我方节点/汇聚都跑自研 C 固件**（`ws63-firmware/`，构建目标 `ws63-liteos-app`，产物 `HUB_HUB.fwpkg` 1474152 B / `NODE_M1.fwpkg` 1468136 B / `NODE_M2.fwpkg` 1468072 B / `NODE_M4.fwpkg` 1463592 B，2026-10-19 00:34-00:36 构建）。所以上面那张 AT 支持度表**不构成项目门槛**——它只决定"能不能拿 AT 当现成外设用"。

### 11.1 `COM19` 如般微：✅ 直接可用，几乎零风险

| 检查项 | 结论 |
|---|---|
| 芯片/平台 | WS63，与我方现有两块节点板**同型号**（E528H-WS63） |
| 能否烧我方固件 | ✅ **已实证**：同型板跑过 `NODE_M*` / `HUB_HUB`，证据 = `ws63-firmware/doc/3-SLE启动日志-2026-10-16.txt`、`5-WiFi扫描日志-2026-10-16.txt`、`7-TX2与ADC修正-启动日志-2026-10-16.txt`、`8-LD6002C首帧解析成功-2026-10-16.txt`、`9-跌倒阈值下发与恢复-2026-10-16.txt` |
| 回滚基线 | 现在这块板上的 `XF_AT-V2.1.13-d` 就是厂家原版固件；我方已有救砖包 `C:\Users\Administrator\ws63-tools\fw\xfat-rescue.fwpkg` |
| 缺什么 | 不缺平台侧的东西。**注意**：这块板一旦刷了自研固件，AT 就没了（会被覆盖），要 AT 就别刷、要传感器就刷 |
| 建议用途 | **汇聚**或**节点**都行；考虑到它已经有 SLE/WiFi 全量 AT 固件，当"AT 对照板/回滚基线"也有价值 |

### 11.2 `COM20` 润和：⚠️ 大概率可用，**必须在烧录窗口实测**

| 检查项 | 结论 | 依据/缺口 |
|---|---|---|
| 芯片/平台 | WS63 系（`AT+CSV` → `SDK Version:1.10.100`） | ✅ 串口已证实 |
| 是否 WS63**E**（雷达版） | **未证实** | 串口只能读出 SDK 版本；需要看丝印/规格书。雷达功能对 P0 **不是必需**（P0 只要 SLE + UART） |
| SDK 是否有该板构建目标 | ✅ 有 | `~/ws63/fbb_ws63-master/vendor/HiHope_NearLink_DK_WS63E_V03/build_config.json`：`chip=WS63`、`buildTarget=ws63-liteos-app` —— **与我方同一个构建目标**；`README.md:56` 记该板 = 润和 HiHope NearLink_DK3863E_V03 |
| flash 容量/分区 | ⚠️ **未验证** | 我方 app 从 `0x230000` 起（SDK 根下 `src/build/config/target_config/ws63/sign_encry/packet_allinone.py:48`），镜像 ~1.47 MB ⇒ 推算需 **≥ 4 MB flash**（0x230000=2,293,760 B + 1,474,152 B ≈ 3.59 MiB）。若该模组只有 2 MB，得改分区表 |

| 建议用途 | **节点候选**（第 4/5 块），烧录窗口内先做"最小冒烟"：烧 `NODE_M4.fwpkg` → 看是否起来、SLE 能不能连汇聚 → 再决定当节点还是当雷达加分项 | |

### 11.3 给 PM 的一句话建议

- **可以收下这两块板**，都属于平台同族、都能进项目。
- `COM19` 当"即插即用备件/AT 对照板"；`COM20` 安排进下一次**烧录窗口**做最小冒烟（用户在场、同一张卡）。
- 若想让 `COM20` 以 AT 模式先跑起来看效果，只用 `AT+RADARGETST`/`AT+RDTEMP`/`AT+MAC?` 这三条就够，**别发 `AT+RESTORE`、别发 `AT+RADAR*SET*`**（会写 NV/改算法参数）。
