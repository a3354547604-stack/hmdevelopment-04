## 2. RK2206 → 华为云 IoTDA 的接入方式

**2.1 官方样例路径（重要更正）**

- 华为云/`$oc` 主题样例：`vendor/lockzhiner/rk2206/samples/d8_iot_cloud_TH`（同目录另有 d2~d7 云样例：智能井盖/智慧路灯/智慧车检/人体感应/手势/智慧农业）。
- **本仓库不存在名为 `oc_mqtt` 的样例**：Gitee API 列 `domains/iot/link/` 只有 `demolink/ libbuild/ BUILD.gn LICENSE README.md README_zh.md`；官方 MQTT 实现走 `third_party/paho_mqtt`（`MQTTClient-C/src/MQTTClient.h` 与 `MQTTClient-C/src/liteOS/MQTTLiteOS.h`）→ **「官方 oc_mqtt 样例」= 未证实/在本仓库不存在**。

**2.2 d8 样例的实际接法（一手：样例 README 与源码片段）**
- `NetworkConnect(&network, HOST_ADDR, 1883)` → **明文 1883，无 TLS、无证书**
- 认证：`clientId = DEVICE_ID`、`userName = DEVICE_ID`、`password = <设备密钥明文>`、`MQTTVersion = 4`、`keepAliveInterval = 60`、`cleansession = 1`
- 主题：上报 `$oc/devices/{device_id}/sys/properties/report`；payload 用 cJSON `{"services":[{"service_id":"server","properties":{...}}]}`；命令 `$oc/devices/{device_id}/sys/commands/request_id=...`，响应 `$oc/devices/{device_id}/sys/commands/response/request_id=...`
- 该样例平台地址指向 `117.78.16.25`（通鸿 IoT，OceanConnect 兼容），README 同时称"华为云"。

**2.3 华为云官方要求（一手文档）**
- 连接鉴权 https://support.huaweicloud.com/api-iothub/iot_06_v5_3009.html （更新 2026-09-24）：
  - `ClientId` = **设备ID + "_" + 设备身份标识类型(固定 0) + "_" + 密码签名类型(0=HMACSHA256不校验时间戳 / 1=校验时间戳) + "_" + 时间戳(UTC，YYYYMMDDHH)**，下划线分隔
  - `UserName` = 设备ID；`Password` = **hmacsha256(secret, 时间戳)**，64 位十六进制（工具：https://iot-tool.obs-website.cn-north-4.myhuaweicloud.com/ ）
  - 返回码：0x00 成功；0x02 无效客户端标识符；**0x04 用户名或密码错误**
  - → **d8 样例"password 直接填密钥"不满足 IoTDA 一机一密摘要要求**，网关必须自行实现 HMACSHA256 + clientId 拼装。
- 端口 / 是否支持明文 https://support.huaweicloud.com/bestpractice-iothub/iot_bp_00016.html （更新 2026-10-10）：MQTT.fx 参数表原文 **「Broker Port 默认为1883」**，接入地址取控制台"平台对接信息" → **公网 IoTDA 支持 1883 明文**；同页「用户可以选择设备侧建链时是否为SSL加密」。
- TLS 与限制 https://support.huaweicloud.com/usermanual-iothub/iot_01_0128.html （更新 2026-09-16）：支持 TCP + TLS(TLSv1/1.1/1.2/1.3)，平台**推荐** TLS，明文"数据没有加密，建议使用 MQTTS"；**不支持 QoS2**；**不支持 will 和 retain**；心跳 **30–1200 秒**（推荐 120）；单设备同一时间连接数 = 1；单连接每秒最大上行 50 条；单条消息 ≤1MB；自定义 Topic ≤128 字节。
  - → **d1 样例用 QoS2 + `keepAliveInterval = 0`，直连 IoTDA 会被拒**（QoS2 不支持；心跳超出 30–1200s 会返回 0x02）。这是照抄样例最典型的坑。
- 端口二次佐证（**仅华为云Stack 私有云，非公网行为**）：support.huawei.com/enterprise/zh/doc/EDOC1100329965/3fc8834a 「IoT设备接入只有8883端口默认是开的，1883端口是默认关闭状态」。
- **落地结论：1883 明文可用、TLS 非强制；TLS 走 8883 需匹配对应证书（https://support.huaweicloud.com/devg-iothub/iot_02_1004.html ）。**

## 5. MQ 系列气体传感器：预热/老化、加热电压、3.3V 与 ADC

**5.1 MQ-2（郑州炜盛《MQ-2 Manual Ver1.4》，https://www.winsen-sensor.com/d/files/PDF/Semiconductor%20Gas%20Sensor/MQ-2%20(Ver1.4)%20-%20Manual.pdf ）**
- 标准电路条件：Loop Voltage `Vc ≤ 24V DC`；**Heater Voltage `VH = 5.0V ± 0.1V`（AC 或 DC）**；**Load Resistance `RL` 可调**（datasheet 未给推荐值）
- Heater Resistance `RH = 29Ω ± 3Ω`（室温）；**Heater consumption `PH ≤ 950mW`**
- 灵敏度 `S = Ro(空气中)/Rs(2000ppm C3H8) ≥ 5`；输出 `Vs = 2.5V ~ 4.0V`（2000ppm C3H8）
- 标准测试电路：`Vc: 5.0V±0.1V`、`VH: 5.0V±0.1V`；**Preheat time: Over 48 hours（预热 >48 小时）**
- 老化（Cautions 小节原文）：**存放 <1 个月 → 老化不少于 48 小时；1~6 个月 → 不少于 72 小时；超过 6 个月 → 不少于 168 小时**
- 禁忌：**有机硅蒸汽**环境会使灵敏度永久不可恢复

**5.2 MQ-7B（郑州炜盛《MQ-7B Manual Ver1.4》，https://www.winsen-sensor.com/d/files/PDF/Semiconductor%20Gas%20Sensor/MQ-7B%20(Ver1.4)%20-%20Manual.pdf ）**
- 检测范围 10~500ppm CO；`Vc ≤ 10V DC`
- **Heater Voltage `VH`：高温 `5.0V ± 0.1V` / 低温 `1.5V ± 0.1V`（AC 或 DC）**
- **Heater Time `TL`：高温 `60S ± 1S` / 低温 `90S ± 1S`** → 加热必须**高低温循环**：低温 1.5V 时检测 CO，高温 5V 时清洗低温段吸附的其他气体
- `RH = 29Ω ± 3Ω`；**`PH ≤ 900mW`**；`RL` 可调
- **Preheat time: Over 48 hours**；老化时间同 MQ-2（48 / 72 / 168 小时）
- 注：官网**没有 MQ-7（非 B）型号的 Manual**；检索到的「MQ-7 Ver1.3」只出现在 Scribd / SparkFun 等二手镜像 → **MQ-7 非 B 型号的一手 datasheet = 未证实**，本节以 MQ-7B 为准。

**5.3 3.3V 供电与 ADC 分压（数值为原文，其余明确标注为推断）**
- 一手事实：两款传感器的 VH 规格都是 `5.0V ± 0.1V`（MQ-7B 还需 `1.5V ± 0.1V`），**没有任何一款支持 3.3V 直接加热**。
- 以下为**工程推断（非 datasheet 原文）**：若 WS63 节点只有 3.3V 轨，必须另配 5V（升压或独立 5V）＋低边 MOS 开关驱动加热丝；信号侧 `Vs` 最高 4.0V，**超过 3.3V ADC 量程，必须分压**，且分压电阻会与 `RL` 并联改变等效负载（datasheet 仅写"RL 可调"）→ **"3.3V 直连 MQ 传感器"电气上不成立，且无一手依据**。
- 排期相关的一手约束：**预热 >48 小时、老化 48~168 小时是不可压缩的日历时间**，且老化期间传感器不应长期断电（原文：long time storage but no electrify, they need long galvanical aging time for stability before using）。

## 6. 对 20 天排期的风险排序

1. **MQ 传感器的预热/老化是 48~168 小时硬日历时间**，必须在 D1 就通电开始老化，否则提交日拿到的仍是漂移读数（MQ-2/MQ-7B Manual：「Preheat time Over 48 hours」+ 老化表 48/72/168 小时）。
2. **华为云 IoTDA 一机一密需要 HMACSHA256(secret, 时间戳) 与 4 段 clientId，而小凌派官方 d8 样例只把密钥明文当 password**，网关必须自写摘要逻辑，否则只会拿到返回码 0x04 —— 这是最可能烧掉 2~3 天的集成坑。
3. **照抄 d1/d8 样例会连不上 IoTDA**：样例用 QoS2 + `keepAliveInterval = 0`，而 IoTDA 明确不支持 QoS2、心跳须在 30~1200 秒，移植时必须改成 QoS0/1 + keepAlive 120。
4. **SLE 侧不是"有没有样例"的风险，而是"20 天内能否把星型组网与掉线重连调稳"的风险**：官方 `sle_speed_client` 已含扫描/连接/服务发现/读写全链路，文档亦写明支持 8 路星闪连接，技术前提成立。
5. **60GHz 雷达的中国合规状态无一手依据**（52 号公告八类目录未见 60GHz 条目），应立刻向厂商索取 SRRC 型号核准证；同时顶装 2.2~3.0m、跌倒默认迟滞 15~20s、覆盖仅 3×3m 单人，会直接压缩"应急辅助"的可演示时长。
