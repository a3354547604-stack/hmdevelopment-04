# 节点编号：已知限制与今晚演示口径（2026-11-01）

> 状态：**问题已定位、代码已改、真机未验**。今晚演示按本文口径执行，不在现场尝试修复。

## 1. 现象

同一个网关下，**同型号的两块节点不能同时在线**：后接入的那块会把先接入的顶掉，或者干脆不显示。
跨型号（M1 厨房 + M2 卧室）此前也只能各上一块。

## 2. 根因（已定位）

| 层 | 位置 | 问题 |
|---|---|---|
| 固件 | `ws63-firmware/src/node_cfg.h` | SN 与 MAC 是**编译期常量**，同型号烧同一份固件 → 两块板身份完全相同 |
| 汇聚 | `ws63-firmware/src/hub_agg.c` | 按 MAC 索引聚合，命中第一个就返回；白名单未命中时 `return -1` 且**无日志**（静默失败） |
| 服务端 | `server/app/services/telemetry.py` | `_NODE_SN_RE` 只认 `^[HM]\d{1,2}$`，不认带后缀的派生 SN |

## 3. 已做的修改（代码层面）

- **t176（`64e8d95`）**：节点上电读 5 字节 eFuse Die ID → `SN=<型号>-<4位hex>`（例 `M1-3F7A`）、`MAC=11:22:33:<die0>:<die1>:<role>`；efuse 读不到时回落到旧值并打 `[CFG] die_id fail, fallback legacy`。汇聚改为按「型号段」匹配（`M1` 命中 `M1-3F7A`、不命中 `M12`），预绑定占位就地升级，白名单未命中改为打 `[BIND] WARN`。
- **t177（`4c6889e`）**：契约升 v1.6，把上面这套口径写死（§2.7 派生规则、§3.4 白名单匹配 7 条规则）。
- **t178（`8d667b9`）**：出正式包 `HUB_HUB_PROD.fwpkg`（预绑定钩子编译期关掉）。
- **t179（`80af778`）**：服务端正则放宽为 `^[HM][0-9](-[0-9A-F]{4})?$`，容器内 pytest 148 passed。

## 4. 还没验证的（今晚不做）

1. **efuse 真机取值**：从没在任何一块板上看到过 `[CFG] die=… sn=…` 这一行。
2. **两块同型号同时在线**：手上只有 2 块 WS63（一块雷达节点、一块汇聚），物理上凑不出两块同型号节点。
3. **MAC 撞号空间**：MAC 只用了 die 的 2 字节（65536 空间），理论会撞；已钉成断言，量产要扩到 4 字节。
