## 4. 工作流与质量门

### 4.1 任务卡（每张卡必须包含）

1. 目标（一句话，可验收）
2. 允许修改的文件/目录（inScope）
3. 禁止修改的范围（outOfScope）
4. 依赖的契约版本与章节
5. 验收标准（可检查）
6. 验证命令（能复现）
7. 不依赖硬件的 mock/自测方式
8. 交付物（文件路径 + 证据路径）
9. 风险与回退方案

### 4.2 目录 ownership

- `ws63-firmware/`：WS63 节点与汇聚固件
- `rk2206-gateway/`：RK2206 网关应用
- `server/`：云端对接 + 自建服务器 + 数据库
- `harmony-app/`：HarmonyOS App
- `tools/`：构建、烧录、测试脚本
- `docs/`：我维护；员工只在任务指定文件写入

**同一文件同时只有一个 owner。** 跨目录改动先在任务里说明理由，由 PM 裁决。

### 4.3 契约冻结与变更

- 《接口契约》v1 冻结后，字段、topic、端口、阈值、表结构任何变更都必须走 PM；员工不得各自发明。
- 契约变更要同步改三处：契约文档、实现、验收脚本；缺一视为未完成。

### 4.4 独立验收

- 每个实现任务完成后，由**另一名员工**创建/执行 `review` 任务；verdict 只有 `pass` 才算通过。
- 硬件相关验收：用户按施工单操作并留下证据（串口日志、照片、视频），验收员工逐条核对，不由实现者自证。
- 验收不通过 → 生成 `repair` 任务 → 再验收；连续两轮不过，PM 介入裁决。

### 4.5 集成节奏

- **内部不设固定日期**；用户按自己的时间安排联调，PM 提前 24 小时给施工单。
- 代码侧先完成、先自测；用户有空时再上板联调。
- 外部截止日期（报名 10/30、提交 11/06、路演 11/13–14）是事实约束，不是内部排期。
- 每次集成前，员工必须提交“自测通过”的证据；没有证据不进入集成。

### 4.6 Git 纪律

- 动结构前先提交干净基线；每个任务完成即提交，提交信息写任务 ID。
- 不提交密钥、账号、证书、学校信息。
- 大文件（视频、固件包）放 `dist/` 并加入 `.gitignore`，用外部网盘交付。

### 4.7 Docker 隔离

- 容器/网络/卷统一 `hmprogram-` 前缀，Compose 项目名 `hmprogram`；不碰其它项目的容器。
- 不用 `--network host`、不用 `--privileged`（除非任务写明理由）；端口只绑 `127.0.0.1`，避免占用全局端口。
- 构建容器用 `--rm`；任务结束清理自己的容器，不执行 `docker system prune`。
- 数据库只在本项目网络内暴露；需要宿主访问时映射到非默认端口（如 3307）。

### 7.1 配网与绑定流程（用户要求，写入契约）

1. RK2206 上电；长按配对键进入配网模式：启动 SoftAP（SSID `ElderCare-XXXX`）+ 本地 HTTP 服务；蓝牙作为 P1（官方 BLE 支持待验证）。
2. 手机 App：注册/登录 → 添加主设备（扫码/输入设备 ID）→ 选择 Wi-Fi 配网（P0）/蓝牙（P1）→ 扫描附近 Wi-Fi → 连接设备热点 → 提交家庭 Wi-Fi SSID/密码。
3. 网关保存 Wi-Fi 到 KV，重启进 STA，连 IoTDA/服务器；App 通过服务器 API 完成设备与账号绑定。
4. App 触发“扫描星闪节点”：网关经 UART 命令汇聚节点扫描；节点上电即 SLE 广播；汇聚返回节点列表（sn/信号/状态），App 显示并绑定。
5. 绑定关系存服务器；网关/汇聚保存白名单；未绑定节点不产生告警。

**P0 范围**：Wi-Fi 热点配网 + 节点扫描/绑定；蓝牙、二维码配网放 P1。安卓 App 只做配网/绑定，不做实时监测。

范围变更必须由用户拍板，并记入第 11 节。
