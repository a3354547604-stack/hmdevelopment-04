# 文档优先协议（v1.0，2026-10-27）

一句话：**别人会照着做的外部事实，必须带 10 秒能打开的来源；没有来源就标【待验证】，且只写条件句。**

> 立规起因（真实）：
> 1. 回答华为云 IoTDA 建产品/设备时凭空编造了一个界面上不存在的配置项，用户找不到才发现；
> 2. 把 SDK 示例注释（`PB6=UART0_RX`）与自己两周前写的接线表（「E53 第 20 脚 = TX」）当事实，实际原理图与实测是 `B6↔UART_TX、B7↔UART_RX`、19 脚 → 用户接错线，返工数小时。

## 1 适用范围

两问都「是」才走协议：

- **Q1 会被照着做吗**：结论会变成动作（接线／改配置／烧录／点界面）或判定（验收 pass/fail、选型、排障方向）。
- **Q2 现在能当场复现吗**：依据能用一条本地命令跑出，或一个 URL／行号 10 秒打开。

Q1 是 + Q2 否 → **必走**；Q2 是 → 直接贴命令与输出。

**必走清单**（命中即走）：

| 类别 | 例子（本项目真实踩过） |
|---|---|
| 第三方界面的字段/配置项/API 参数/报错码 | 华为云 IoTDA 建产品、设备密钥、clientId 四段、`rc=4` 含义 |
| 引脚、复用（MUX）、TX/RX 方向、波特率、电平、电源 | `E53_UART0_TX_M0` 到底哪个脚、`MODE1` 还是 `MODE2`、是否需要分压 |
| 版本、价格、时限、标准号 | ESP-IDF/OpenHarmony 版本、CE/SRRC 标准、赛题截止日期 |
| 要写进 `docs/` 或验收报告的结论 | 契约字段、验收判据、材料数字 |

**免走清单**：仓库内文件行号；前提已带来源的纯推演；用户刚回传的实测。

## 2 四步

### 2.1 查 —— 判据：候选清单非空，或明确写「未命中」

顺序固定：

1. `rg -n "<关键词>" docs/ <目录>`（仓库内既有资料）
2. 官方文档落到**当前版本页**，记 URL + 小节标题
3. 实测：命令 + 时间 + 输出片段

**只算线索、不进结论**：SDK 示例注释、旧版仓库文档、自己写过的表、AI 记忆。

### 2.2 引 —— 判据：每条会被执行的事实，恰好一个来源字段

- 【实测】`命令` + 时间 + 输出片段
- 【原理图】网络名 → `器件.pin`（例 `E53_UART0_TX_M0 → U6.19`）
- 【官方文档】URL + 小节标题（带锚点）或 `路径:行号`

来源必须「点开就落在那一句」；「文档里有」不算。

### 2.3 冲突 —— 判据：落到用户 2 分钟做得完的单变量实验

两源不一致，写三行，**不选边**：

```
说法A：<内容>【来源】
说法B：<内容>【来源】
判定实验：<通断／短接／单脚拉低／打印一行日志>，看 <哪个数字>；得 X 则 A 立，得 Y 则 B 立。
```

### 2.4 答 —— 判据：第二个人能逐条指出来源

四段固定：

1. **结论**：每条带 `[已核实]` / `[待验证]` / `[仅线索]`
2. **依据**：与结论一一对应
3. **未核实项**：附「不要照此改配置」
4. **下一步**：一条命令或实验，写清看什么

`[待验证]`、`[仅线索]` 只写条件句（「若 U6.19 与 E53 第 20 脚导通，则…」）。

## 3 降级三句（查不到时怎么说）

- 「已查 A、B，没有能支撑这个结论的来源；下面是推测，标 `[待验证]`，不要据此改配置。」
- 「我只能确认到 <边界>：<已核实部分>；再往后需你跑 `<命令>` 或看一眼 <界面位置> 回传。」
- 「官方文档只覆盖 <版本/型号>，你的 <版本> 无对应说明；先做 <单变量实验>，再决定。」

## 4 落库方式

- 本文件 = 唯一真相源：`docs/协议/文档优先协议.md`
- `AGENTS.md` 常驻**三行指针**（只放触发条件，不放全文）：
  > 回答「别人会照着做」的外部事实（第三方界面字段、API 参数、引脚/电平、版本/价格/标准号）前，先读 `docs/协议/文档优先协议.md`，按「查→引→冲突→答」作答；无来源标【待验证】。
- 任务卡加必填行：`来源字段：<逐条列；无外部事实写「无」>`

理由：协议只在「外部事实」分支触发，属抽样路径；全文进 `AGENTS.md` 会每轮吃上下文，还会被构建窗口、并发、硬件核查规则淹没。指针管触发，正文管细节，任务卡字段让它成为**产物**（缺字段=报告不合格）。不设简化版，两份必然分叉。

## 5 自检（交付前 30 秒）

1. `grep -c "【实测】\|【原理图】\|【官方文档】" 报告.md` ≥ 会被执行的结论条数
2. 抽最关键 1 条来源点开，确认「那句话真的在」；不在 → 整份打回
3. `grep -nE "应该|通常|一般|大概"` 每行须同行有来源或 `[待验证]`
4. 冲突项是否配「看哪个数字」的实验；没有 → 退回
5. `[待验证]`／`[仅线索]` 段出现祈使句（「请把…接到…」）→ 改条件句

**防形式化**：来源做成表格独立列（空列肉眼可见）；验收抽查 1 条来源，失败即 `needs_revision`；verdict 绑定 commit，被引来源字节变了即失效重核。

## 6 记忆的定位（补充）

AI 的「记忆」——包括我写过的文档、之前说过的结论、压缩后的摘要——**只是指针，不是证据**。
任何来自记忆的论断，必须回到 §2.1 的三条路重新取一次来源；取不到就标 `[待验证]`。

## 8 触发条件（命中即走协议）

1. 用户问「怎么配 / 填什么 / 接哪根」——要动手的操作题。
2. 仓库只有网名或样例注释，缺引脚号/字段名（契约留白），最容易被记忆填坑。
3. 排障已到鉴权/帧格式，而前面的物理层假设从未证实。
4. 文档自身已冲突（新表 vs 旧表、样例注释 vs 契约）。
5. 领域「有惯例可套」（HMAC、云控制台字段、SDK 返回值）——越像常识越危险。

## 9 回归清单（出结论前逐条自问）

1. 云平台字段/菜单路径：先抓官方文档对应章节，带 URL + 小节号；抓不到写「待核」，禁给「大概叫…」。
2. 引脚号/方向：先查原理图网名 + 连接器脚号，同行打【实测】/【原理图】/【官方文档】；样例注释只算线索。
3. 要用户照做的硬件动作：先给一条能一次判定的物理实验（通断/单脚拉低），不许二选一让用户试。
4. 字段名/参数：先 grep 契约对应小节并引行号；契约未覆盖→写「未覆盖，按 X 实现待裁定」，不自造别名。
5. 落笔前 grep 同一事实在契约/接线表/代码/交接文档的全部出现处，冲突并列再定。
6. SDK 返回值/错误码：读头文件或样例判据原文，引 `路径:行号`；禁按「一般返回 0」推断。
7. 移植示例：注释与行为冲突时以运行日志为准，同处留 TODO 标「未验证」。
8. 排障顺序固定：线通→脚对→波特率→帧格式→业务；违反顺序的结论标「未证实」。
9. 每轮只改一个变量，回复写「看哪行日志/哪个数字」。
10. 修完一处事实错误，grep 反查旧说法是否仍在注释/旧文档，一并清掉并列出「扩散检查结果」。

## 10 机制出处（为什么是这几条）

- **指针化引用**：Anthropic Citations（`cited_text` 为原文精确片段、保证含有效指针，https://docs.claude.com/en/docs/build-with-claude/citations ）；OpenAI file_search 返回 `annotations[{type:"file_citation"}]`（https://platform.openai.com/docs/guides/tools-file-search ）。
- **允许弃答**：GopherCite, arXiv 2203.11147——弃掉最不确定的 1/3 后高质量率 80%→90%。
- **确定性门禁而非提示词**：Anthropic 官方原文——提示词/skill 都是 non-deterministic，"there's no guarantee that it'll follow your instructions"；"If you keep adding emphasis … that's a sign the line belongs in a hook"（https://www.anthropic.com/engineering/claude-code-best-practices ）。
- **AGENTS.md 只放「去哪查」**：官方备忘——"Longer files consume more context and reduce adherence"（https://docs.claude.com/en/docs/claude-code/memory ）。
- **引用质量必须机器测**：ALCE, arXiv 2305.14627——ELI5 上最好模型也有 50% 引用支持不完整；Self-RAG（2310.11511）说明「自我核查」是训练出来的能力，提示词给不出来。

**反模式**：①只写「必须查文档」不设门禁；②要求标注来源却允许自然语言（会写「根据官方文档」）；③把事实值抄进 AGENTS.md 当缓存（会过期且更低遵从）；④规则放错位置静默失效；⑤用自我核查清单代替外部校验；⑥只测「有没有引用」不测「引用是否支持结论」。
