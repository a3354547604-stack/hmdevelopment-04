## 2. 按场景分组的录制顺序（6 组，减少重录与插拔）

**为什么分组**：真机段的成本在「接线 + 上电 + 等联网」，不在录制本身。把**同一套接线/同一台设备**的镜头排在一组，一次拍完；纯 App 段（不需要硬件）随时可补。

| 组 | 组名 | 含哪些镜头/素材 | 需要的硬件状态 | 预计用时 | 为什么排在这 |
|---|---|---|---|---|---|
| **G1** | 纯 App（不动硬件） | 镜头 14–16（D3 阈值）、20–22（D5 网关卡）、27–29（D7 报表）+ 片头 1–2 与片尾 30–31 的字幕板 | 手机 + App（Mock 即可） | 30 min | 零接线、可随时重录；先把最稳的拍完，心里有底 |
| **G2** | 网关 + 手机（插网线） | 镜头 3–5（配网 A）、23–26（D6 断网补传） | 网关已烧录、能进 SoftAP 与 STA | 40 min | 两者都要动网关与网线，一次插拔拍完；D6 要拔网线，排在配网之后 |
| **G3** | 厨房节点（放气） | 镜头 6–10（D1 燃气 + 处置闭环） | M1 上电、MQ-2 就绪、网关在线 | 40 min | 打火机放气只能短时进行，单独一组、一次多拍几条备选 |
| **G4** | 卧室雷达 | 镜头 11–13（D2 跌倒） | M2 上电、雷达接线完成 | 30 min | 与 G3 同属节点，但**换了板子与位置**，单独一组避免来回搬 |
| **G5** | 433 遥控 | 镜头 17–19（D4 SOS） | 433 接收模块 + 遥控器就绪 | 20 min | 只在网关侧接线，最后做；没到货就走降级 |
| **G6** | 命令行证据（本机） | E01–E04 静帧（片尾可选 5 s） | 本机 + Docker | 20 min | 与硬件无关，随时可做；建议**先做**（它也是 S/V 素材的图注依据） |

**建议顺序**：G6 → G1 → G2 → G3 → G4 → G5。
（G6/G1 先做，是为了尽早拿到「34/34、971362 B、116 passed」这些图注数字；G2 之后按「节点距离」由近到远。）

**每组开拍前的 60 秒动作**：① 按 §1.2 第 8 项重启 App；② 确认数据源标签与本组口径一致；③ 手机开勿扰；④ 录屏开始后**先静默 2 s**（给剪辑留头）；⑤ 每段录完立刻回看 10 s，不合格马上重录（别攒到最后）。

### 5.2 判「该重录」的四个信号

1. **画面里出现了不该出现的东西**：通知栏、聊天窗口、桌面文件名、串口窗口标题里的用户名/路径、未打码的口令。
2. **数据源标签与旁白口径矛盾**：Mock 段却显示「在线服务器」（或反过来）。
3. **成功标志没入镜**：例如 D1 只拍了列表、没拍首页横幅与处置记录；D6 只拍了断网、没拍恢复后的新条目。
4. **现场声缺失或爆音**：放气/按键那几秒没有声音（观众听不出真实设备在动作）。

### 5.3 重录时的最小操作（别整套重来）

| 情况 | 最小重录范围 |

```bash
ffprobe -v error -show_entries format=duration,size -of default=nw=1 演示视频.mp4   # duration ≤ 300、size ≤ 104857600
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name -of csv=p=0 演示视频.mp4   # h264
```
