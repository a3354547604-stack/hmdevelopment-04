## 第 1 章 作品设计思路

### 1.1 背景与问题

独居老人在家中发生跌倒、突发疾病或燃气泄漏时，最大的风险不是事件本身，而是**没有人知道**。子女不在身边，邻居不一定能听到，老人自己也常常来不及、或者已经没有能力去拨电话。赛题把这一场景归纳为「居家安全监测与应急辅助」（**主办方通知（不入库，见赛事附件）**·赛题四正文）。

现有方案主要有两类，各有明显短板：

1. **穿戴式设备**（手环、呼叫器）：需要老人每天佩戴、按时充电，实际使用中「不戴」是常态；跌倒检测算法在手腕上误报率高。
2. **摄像头方案**：能看见，但在卧室、卫生间这类私密空间无法接受，老人的抵触情绪比技术问题更难解决。

本作品选择第三条路：**非接触感知 + 本地优先报警 + 子女端闭环**。感知设备装在房间里而不是老人身上；报警先在本地响（不依赖网络）；子女在手机上看得到、点得动、留得下记录。

### 1.2 设计目标与范围（P0 / P1 边界）

**P0（本次交付、现场演示的范围）**：**1 个汇聚节点 + 3 个感知节点**的完整闭环——厨房（燃气 MQ-2 + 温湿度 AHT20）、卧室（LD6002C 毫米波雷达）、门厅（干簧管门磁 ×2）；数据经星闪（SLE）自组网汇到 WS63 汇聚节点，再经串口到 RK2206 网关；网关本地判定并驱动声光报警，同时经 Wi-Fi 上华为云 IoTDA，由自建服务器落库，鸿蒙 App 展示与处置（`docs/项目章程.md` §7；`docs/执行/待确认问题.md:34`）。

### 1.3 总体设计思路

三条主线贯穿整个系统：

1. **非接触感知**：毫米波雷达（LD6002C）判跌倒、门磁判出入与活动、燃气传感器判泄漏、温湿度看环境。老人不需要佩戴任何东西，也不需要被摄像头盯着（`docs/技术笔记/雷达LD6002C-接线与实测.md`）。
2. **本地优先**：报警的第一现场是**网关**而不是云。异常经星闪汇总到网关后，网关用自己的规则引擎判定并直接驱动声光报警器；网络断了，本地照样响（`rk2206-gateway/src/gw_alarm.c`、`gw_rules.c`）。
3. **云侧闭环**：网关经 Wi-Fi 上华为云 IoTDA，服务器接收 webhook、落 MySQL，App 拉取展示；子女在 App 里**确认预警并填写处置结果**（已电话联系 / 已上门查看 / 误报 / 其它），形成居家安全日志（`server/app/routers/alerts.py`、`harmony-app/entry/src/main/ets/pages/AlertDetailPage.ets`）。

### 1.4 关键取舍（为什么这么设计）

**取舍一：配网交给网关自带的 H5 页面，App 内不做配网页。**
手机端在鸿蒙上直接操作 SoftAP 配网需要额外权限与适配成本，而「手机浏览器打开网关热点页面填 Wi-Fi」这条路径**零安装、跨平台、可复现**。因此 P0 的配网入口是网关上的单文件 H5 页面（`rk2206-gateway/src/gw_h5.h`，契约 §12.11 要求单文件内联、无 CDN、全离线），App 内配网降为 P1（`docs/决策记录/ADR-0001-配网方案.md`）。

**取舍二：告警用「未确认队列 + 分级重推」，不用长连接。**
服务器预算只有 2 核 2G，长连接（WebSocket/MQTT 常驻）在内存与连接数上都不划算。契约 §8.5 定义的做法是：告警落库即进未确认队列，带 `retry_count` / `next_retry_at`，按级别决定重推节奏；App 侧用**轮询**（首页 10 s、告警页 5 s）拉取（`docs/技术/接口契约.md` §8.5；`harmony-app/entry/src/main/ets/common/AppConfig.ets`）。

**取舍三：阈值下发要区分「投递」与「生效」。**
App 改了阈值，服务器只负责把命令下发到网关，**真正生效**要看设备侧回报。所以设置页同时显示「设置生效状态」与「设置更新于」，避免「点了保存就以为生效」（契约 §6.10、§4.5；`harmony-app/entry/src/main/ets/pages/SettingsPage.ets`）。

**取舍四：门磁没有演示事件，缺硬件时用 SOS 注入顶一条。**
契约 §6.12 的 `demo_trigger` 只接受 `gas`/`fall`/`sos` 三种（非法值回 `1206`），App 设置页据此收敛为三项（PM 裁定 D8，`docs/执行/待确认问题.md:52`）。现场门磁演示走真实干簧管；若硬件没到，用「紧急求助」注入并**口头说明这一条实际由门磁产生**，不冒充。

### 1.5 合规与隐私

- **无摄像头、无穿戴**：视频与雷达都不采集人脸/图像，雷达只输出「有人/无人/跌倒状态」这类布尔与计数信息。
- **数据只在自有链路内**：传感器 → 网关 → 华为云 IoTDA → 自建服务器（MySQL）。服务器仅绑 `127.0.0.1`（生产编排另配），Docker 网络与卷统一 `hmprogram-` 前缀（`server/docker-compose.yml`、`AGENTS.md`）。
- **账号隔离**：设备绑定关系区分 `owner` 与 `family` 角色，非绑定账号访问设备接口返回 `1104`（契约 §6.6；`server/app/routers/devices.py:101-126`）。
- **不落敏感信息**：配网口令不进日志、不回显、不落仓库；服务器密钥以 `.env` 注入，仓库只留 `.env.example` 占位符，生产环境用占位符会拒绝启动（`server/app/config.py:12-18,136`）。

## 第 2 章 功能实现逻辑

本章按赛题「主要功能 5 项 + 创新拓展 4 项」逐条写**触发 → 链路 → 表现 → 证据**（**主办方通知（不入库，见赛事附件）**·赛题四正文）。

### 2.1 南向数据采集与控制（赛题①）

**触发**：厨房节点周期采 MQ-2 分压后的 ADC 值并读 AHT20 温湿度；门厅节点检测干簧管跳变；卧室节点解析 LD6002C 雷达帧。

**链路**：节点本地按基础阈值算法判定异常 → 通过星闪（SLE）上报汇聚 → 汇聚按 UART 帧格式（契约 §3，含 CRC）转给 RK2206 网关 → 网关按本地规则再判一次（避免单点误报）→ 需要上报时经 IoTDA 到服务器。

**表现**：App 首页「四张传感器卡 + 网关卡」实时显示活动、门磁、燃气、温湿度与在线状态（契约 §6.7、§4.3）。

**证据**：
- 节点固件编译自检 **41 个（目标 × 文件）编译、失败 0**（含 SDK `-Werror` 级别警告）【出处：`ws63-firmware/doc/12-汇聚H1-SLE客户端与UART帧.md:67`；独立复核 `docs/评审与验证/复核-t2-节点固件骨架-2026-10-18.md:35`】
- 雷达链路板级实测：解析帧 `bad=0`、`drop=0`，首个抓包 113,927 **字节**（≈1.1 万帧）无校验错；`0x0E02` 真实上报速率 **19.85 帧/s**（墙钟口径）【出处：`docs/技术笔记/雷达LD6002C-接线与实测.md:22,70,85-90`】
- 燃气 ADC 分压修正与启动日志【出处：`ws63-firmware/doc/7-TX2与ADC修正-启动日志-2026-10-16.txt`】
- **待实测（节点侧）**：燃气传感器**数值标定**（多少 ADC 对应多少 ppm）尚未做——谁测：节点负责人在用户授权串口窗口内上板；怎么测：打火机定量放气 + 记录 ADC 序列；判据：给出至少 3 个浓度档的 ADC 区间并写进 `docs/技术/引脚与接线表.md`。当前 P0 用**相对阈值**（分压后 ADC 越限即报警），不宣称 ppm 精度。

### 2.2 本地声光预警与自助求助（赛题②）

**触发**：① 网关本地规则判定异常（燃气越限、门久开、无活动、跌倒）；② 老人按下 433 遥控器。

**链路**：异常 → 网关 GPIO 直接驱动声光报警器（**不经过网络**）；433 按键 → 网关接收 → 生成 `source=button` 的 `sos` 告警，同时本地声光。

**表现**：现场立刻听到蜂鸣、看到闪灯；App 侧随后出现「紧急求助」告警（最高等级）。

**证据**：`rk2206-gateway/src/gw_alarm.c`、`gw_433.c`；App 端演示事件按类型渲染（`sos` → H1 节点 / lv2 / 「收到紧急求助」）【出处：`harmony-app/deliverables/02-无设备自检日志.txt` 自检 #27（t42 提交 `94d3c59`）】。

**语音播报（D9）**：赛题②点名「语音模块播放预设求助语音（如『我需要帮助』）」。**这是扩展设计，本原型未实现**——设计上可在网关侧接 DFPlayer TF 卡语音模块，由同一条告警触发链路驱动播报；本原型以**声光报警 + App 推送**替代该功能【出处：`docs/执行/待确认问题.md:53-56`（D9）】。

### 2.4 事件闭环管理（赛题④）

**触发**：告警产生后，子女打开告警详情。

**链路**：详情页四个处置动作（已电话联系 / 已上门查看 / 这是误报 / 其它情况）→ `POST /api/alerts/{id}/disposition` → 写入 `alert_dispositions` 表（契约 §7.8）→ 告警状态转 `confirmed`；重复处置返回 `409 / 1301`，避免重复响应。

**表现**：处置记录列表按时间倒序显示（动作、备注、处置人、时间）；列表页可按「待处置 / 已读 / 已处置」筛选（`status=confirmed` 等）。

**证据**：`server/app/routers/alerts.py`、契约 §6.13–§6.15、§7.8；App 侧详情页与 `Formatter.dispositionText()` 文案（`harmony-app/entry/src/main/ets/pages/AlertDetailPage.ets`）；告警详情 `data` 平铺与 `dispositions` 元素字段经独立复核【出处：`docs/评审与验证/复核-t5-服务器骨架与模拟API-2026-10-17.md`】。

### 2.5 数据统计分析（赛题⑤）

**触发**：进入报表页，切换「今日 / 本周 / 本月」。

**链路**：`GET /api/reports/activity|trend|summary` → 服务器按活动读数聚合。

**表现**：今日活动量 + 按小时分布（0–23 点）；近 N 天告警/活动趋势，含「今日活动频次较昨日下降 N%」这类对比文案；本月汇总（活动 / 告警 / 环境均值）。

**证据（算法是真实实现，不是画图）**：`server/app/summary.py`（`TREND_TITLE='今日活动频次'`、半进位取整 `_round_half_up`、昨日为 0 时不出趋势）；`server/app/services/reports.py:86-105` 按 `delta_pct`/`text` 是否为 `None` 决定是否写入；契约 §6.17 规定 `compare.title` 必现、`yesterday/delta_pct/text` 可选，无基线时只回 `title/today` 且 App 显示「暂无对比数据」【出处：`docs/技术/接口契约.md:1034-1042`（`compare` 字段表；无基线规则行 `:1044-1045`，契约 v1.3 提交 `4c0f759`）；App 侧解析与渲染 t62 提交 `67bc315`，自检 #29/#30 覆盖两种数据形态】。

**诚实说明**：演示用的活动读数是**种子数据**（`server/app/seed.py` 注入），趋势算法本身对真实数据同样成立。

### 2.6 创新拓展① 多维度监测

在赛题要求的「人体活动 / 门窗磁 / 温湿度」之外，增加**燃气（MQ-2）**维度，并预留烟雾传感器接口。燃气与温湿度组合判断（浓度上升 + 温度异常）比单一指标更接近真实风险【出处：**主办方通知（不入库，见赛事附件）**·创新拓展①；`ws63-firmware/src/`（节点传感器采集）、`docs/技术/引脚与接线表.md`】。烟雾传感器本原型未装，材料中只作为规划。

### 2.7 创新拓展② 星闪自组网（SLE）

用 WS63 的星闪 SLE 做主从自组网：3 个节点作为从端周期广播/上报，汇聚节点作为主端接收，替代「每个节点各连一次 Wi-Fi」的方案——解决老旧住宅 Wi-Fi 覆盖不全、节点功耗与配网成本问题。

**证据（板级实测）**：
- 双板长跑 **659.9 s**：主端 649 帧 seq 连续、`notify FAILED=0`；从端 653 帧 `GAP=0`、`lost=0`，速率 0.990 帧/s；到达间隔抖动 **P50 = 1007.0 ms / P95 = 1036.0 ms / 最坏 = 1066.0 ms**（标称 1000 ms，判据 P95 ≤ 1.2×、最坏 ≤ 2× 均通过）【出处：`docs/技术笔记/星闪双板测试.md:380-391`（t53，提交 `d2070ef`）】
- SLE 启动与汇聚 UART 帧格式【出处：`ws63-firmware/doc/3-SLE启动日志-2026-10-16.txt`、`ws63-firmware/doc/12-汇聚H1-SLE客户端与UART帧.md`】

### 2.8 创新拓展③ 远程告警推送

**链路**：网关经 Wi-Fi（`oc_mqtt`）上华为云 IoTDA → IoTDA 回调服务器 webhook（契约 §5，`POST /api/iotda/webhook`，带鉴权与 `event_id` 幂等）→ 服务器落库 → App 轮询可见；推送注册接口 `POST /api/push/register` 已实现（契约 §6.19）。

**诚实边界**：
- **4G 模组回传：扩展设计，本原型未实现**——设计上可选 Cat.1 模组（SIM + APN + 断线重连）作为断宽带时的备用上行，本原型未采购、未接线【出处：`docs/执行/待确认问题.md:53-56`（D9）】。

### 3.5 告警送达与容错

- **未确认队列 + 分级重推**：告警落库即入队，`retry_count` / `next_retry_at` 控制节奏；App 未确认前反复出现（契约 §8.5）。
- **断网本地报警 + 补传**：网络断时网关本地报警照响，数据缓存在本地，恢复后补传（`rk2206-gateway/src/gw_store.c`、`gw_rules.c`）。
- **幂等**：webhook 按 `event_id` 去重，重投不产生重复告警。
- **App 侧错误处理**：网络失败 `-1`、鉴权过期 `1101`（清令牌回登录页）；服务器把机器可读明细放在响应体 `data`（`field`/`allowed`/`missing`/`key`），App 解析后拼进提示，例如「参数超出允许范围（服务器：参数超出允许范围；field=gas_t2_mv allowed=[2001,5000] note=必须大于 gas_t1_mv）」【出处：`harmony-app/entry/src/main/ets/model/Result.ets`、`service/HttpApiService.ets`；自检 #31–#34，t65 提交 `4424608`/证据日志 `e0fa17b`；口径见 `docs/执行/待确认问题.md` D14】
