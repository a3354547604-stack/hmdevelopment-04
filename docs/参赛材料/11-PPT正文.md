### P02 问题与目标（30 s）

**标题**：问题与目标

**要点**
1. 独居老人跌倒 / 突发疾病 / 燃气泄漏时，最大的风险是**没有人知道**
2. 穿戴设备（不戴、要充电）与摄像头（隐私、抵触）两条老路都走不通
3. 我们的路线：非接触感知 + 本地优先报警 + 子女端处置闭环

**配图**：图 1-1 风险与响应链路

**讲者备注**：只讲痛点与目标，不展开技术；**不承诺赛题之外的功能**（PIR、烟雾、语音、4G 都不在这页出现）。

---

### P03 系统总体架构（50 s）

**标题**：系统总体架构

**要点**
1. 五层：3 个感知节点 → 汇聚 → 网关 → 云（IoTDA + 服务器 + MySQL）→ 鸿蒙 App
2. P0 交付范围：**1 汇聚 + 3 节点**的完整闭环（厨房燃气/温湿度、卧室雷达、门厅门磁）
3. 端到端：传感器 → 本地阈值 → 星闪 SLE → 网关规则 → 云 → 手机

**配图**：图 3-1（全屏主图）

**讲者备注**：这页是全场骨架，讲清「谁和谁说话」；强调**网关是唯一上云出口**，节点不直连云。

### P04 软硬件选型（40 s）

**标题**：软硬件选型

**要点**
1. 硬件：RK2206 小凌派（网关）+ WS63 节点/汇聚 + MQ-2 / AHT20 / LD6002C 雷达 / 干簧管门磁 / 433 遥控 / 声光报警
2. 软件：OpenHarmony + ArkTS（API 12）· FastAPI + MySQL 8 + Docker Compose · 华为云 IoTDA
3. 选型理由：星闪低功耗自组网解决 Wi-Fi 覆盖不全；2 核 2G 服务器预算决定不用常驻长连接

**配图**：图 4-1 硬件拓扑 + 表 4-1（精简到 6 行内，**不写价格**）

**讲者备注**：只讲**实际采购/实际使用**的型号；**语音模块与 4G 模组不进「已选型」**（D9，只在 P06/P12 各提一句「扩展设计」）。被问价格就答「以实购为准」。

### P05 南向：数据采集与星闪自组网（50 s）

**标题**：南向：数据采集与星闪自组网

**要点**
1. 节点实时采集 + 基础阈值算法识别异常（燃气 ADC 分压、门磁跳变、雷达帧解析）
2. 星闪 SLE 自组网：节点上报 + 汇聚接收，替代「每节点各连 Wi-Fi」
3. 板级实测：节点/汇聚编译 **41 组合 0 失败**；双板长跑 **659.9 s、lost=0、P95 抖动 1036 ms**

**配图**：节点与汇聚实物照；SLE 启动日志截图；雷达首帧日志截图

**讲者备注**：这是「真做过」的部分，可以讲实；**只报有记录的结论**（编译组合数、长跑时长与抖动），燃气**数值标定尚未做**——若被问 ppm 精度，直接说「P0 用相对阈值，标定列为待实测」。

### P06 本地预警与自助求助（40 s）

**标题**：本地预警与自助求助

**要点**
1. 异常 → 网关 GPIO 直接驱动声光报警：**断网也能报**
2. 433 实体按键求助：不依赖手机、不依赖网络，触发即最高等级 `sos`
3. **扩展设计（本原型未实现）**：可接 DFPlayer TF 卡语音模块播报预设求助语；本原型以**声光 + App 推送**替代

**配图**：声光报警器与 433 实物照；S04（App 首页紧急态）

**讲者备注**：强调「给不会用手机的老人一个实体按键」；**App 内没有一键呼救按钮**，别说错；语音按 D9 口径只说「扩展设计」，**不说已实现/待实测**。
