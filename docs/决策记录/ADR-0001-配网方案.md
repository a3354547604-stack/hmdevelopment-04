# ADR-0001：手机配网方案（SoftAP + 本地 HTTP 优先）

> **owner**：项目经理（AI）｜**更新**：2026-10-17｜**状态**：有效（待 CAL-12 实测验证）

## 背景

用户要求现场用安卓手机演示配网：RK2206 长按配对键进入配对模式 → 手机 App 连设备热点 → 提交家庭 Wi-Fi → 绑定账号 → 触发星闪节点扫描/绑定。

architect 核实：RK2206 仓库没有 SoftAP + HTTP 样例，官方文档有“暂未支持 AP 与 Station 共存”的限制；因此“进 AP 就断 STA、提交后切 STA”的串行流程是可行的设计，但**未实测**。

## 决策

按 A → B → C 的顺序推进：

- **A（优先）**：RK2206 开 SoftAP（`ElderCare-XXXX`）+ 本地 HTTP 服务；进入配网模式时断开 STA，提交 Wi-Fi 后切回 STA 联网。契约 v1.1 §12/§13 按此写。
- **B（备选）**：若 A 实测不通，由 WS63 汇聚节点开 SoftAP + HTTP，手机提交的 Wi-Fi 凭据经 UART 转交 RK2206；手机配网演示不受影响，代价是汇聚固件多一块工作。
- **C（兜底）**：全程走云端 `pair_scan`/`pair_bind` + 433/声光本地指示；手机不能直连设备热点，配网演示降级为“App 远程绑定”。

**验证门槛**：t10 实施前先跑 CAL-12（RK2206 SoftAP 可行性 + HTTP 可达性）；CAL-12 不通过就切 B，并把结论回写本 ADR。

## 后果

- 契约 v1.1 的本地 API（`/api/provision/*`、`/api/pair/*`）在 A/B 方案下通用；C 方案下 App 改用云端接口。
- 配对键是实体件：答辩现场必须能“物理长按 3 秒”。首选 GPIO 外接轻触开关（`EX_GPIO_A3`，内部上拉、按下为低、消抖 50ms），跳线帽短 GND 只作调试兜底。已列入采购清单。
- 网关员工实施前必须先跑 CAL-12，结果写进 t10 交付证据。
