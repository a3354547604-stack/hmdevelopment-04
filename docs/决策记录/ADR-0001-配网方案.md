# ADR-0001：手机配网方案（网关 SoftAP + 内置 H5 页面为 P0 主路径）

> **owner**：项目经理（AI）｜**更新**：2026-10-18（t69 r3 同步 CAL-12）｜**状态**：有效（A 路线已定向为「RK2206 SoftAP + 单文件 H5 页面」；CAL-12 已定位为「**地址由板级驱动决定**」，**上板实测仍待做** —— 见下「前提与风险（CAL-12）」）

## 背景

用户要求现场用手机演示配网：长按配对键进入配网模式 → 手机连设备热点 → 提交家庭 Wi-Fi → 扫描/绑定星闪节点 → 绑定账号 → 看数据。

architect 核实：RK2206 仓库没有 SoftAP + HTTP 样例，官方文档有「暂未支持 AP 与 Station 共存」的限制；因此「进 AP 就断 STA、提交后切 STA」的串行流程是可行设计，但**未实测**。

F-02（verifier 复核 t6 提出）：契约 §12 的 5 个本地配网接口在鸿蒙 App 侧完全没有实现，而 §13.2 步骤表把「谁」列写成 App —— 这是 P0 端到端演示路径上的缺口，必须裁决「配网页由谁承担」。

## 决策（2026-10-17，PM 裁定 F-02）

**路线固定为 A → B → C；A 路线的载体由「手机 App」改为「网关内置的单文件 H5 页面」。**

- **A（P0 主路径，已选）**：RK2206 开 SoftAP（`ElderCare-XXXX`，**占位** `192.168.4.1/24`——实际地址与 DHCP 池**由板级驱动决定**，见下「前提与风险（CAL-12）」）+ 本地 HTTP 服务，**由网关内置的单文件 H5 页面承担 P0 开场演示**：手机浏览器直接打开 `http://192.168.4.1/`，同源、零安装，任何手机都能开。进入配网模式时断开 STA，提交 Wi-Fi 后切回 STA 联网。
  - 页面必须满足的 6 条约束见**契约 §12.11**（单文件内联、全离线无 CDN、只调 §12 的 5 个本地接口、不做账号绑定/不存不显口令、每请求 3 s 超时 + `1600`–`1606` 文案表、入口必须 HTTP 同源 `http://192.168.4.1/`）。本 ADR 只引用，不复制约束表——技术事实源是契约。
  - 消费方口径见**契约 §13.2**：步骤表「谁」列写**手机浏览器**的步骤由 §12.11 页面完成；写 **App** 的步骤（注册/绑定账号、看数据等需要账号与系统 Wi-Fi 能力的）在 P0 用服务器自带调试脚本或 `curl` 代替（§13.5 验收脚本）。安卓/鸿蒙 App 的配网页降为 **P1 消费者**，字段不变、同一套 HTTP 契约。
  - 实现归属：`rk2206-gateway/`（t10）；契约 §12.11 只定约束，不定页面实现。
- **B（备选，触发条件：A 的 CAL-12 结论为不成立）**：若 RK2206 的 SoftAP 起不来、或 AP 模式下 HTTP 不可达、或「关 STA→开 AP→提交后切回 STA」的串行切换在实机上不成立，则由 **WS63 汇聚节点**开 SoftAP + HTTP，手机提交的 Wi-Fi 凭据经 UART 转交 RK2206。手机侧演示流程不变（仍是浏览器打开 H5），代价是汇聚固件多一块工作、且汇聚与网关要有新的一条凭据转发约定（届时须先改契约 §12/§13 再实现）。
- **C（兜底，触发条件：A 与 B 都不可用，现场完全没有 AP 能力）**：配网全程走云端 `pair_scan`/`pair_bind`（契约 §4.5）+ 433/声光本地指示；手机不能直连设备热点，开场演示降级为「App/脚本远程绑定」，现场「长按 → 连热点 → 提交 Wi-Fi」这一段取消。

**验证门槛不变**：t10 实施前先跑 CAL-12（RK2206 SoftAP 可行性 + HTTP 可达性 + AP/STA 串行切换）；CAL-12 不通过就切 B，并把结论回写本 ADR。

## 前提与风险（CAL-12，2026-10-18 t69 r3 同步）

A 路线（RK2206 SoftAP + 内置 H5 页面）**仍然成立、不需要切 B/C**——B/C 的触发条件（SoftAP 起不来、HTTP 不可达、串行切换不成立）目前都没有出现。但 v1.1 写下的两个前提已被 t10 的实现证据**证伪/收窄**，因此契约 §12/§13 按 r3 改了口径（本 ADR 只同步前提与风险，不复制字段表）：

| # | 前提（v1.1 写的） | 实测/证据后的现实 | 已落地的口径 |
|---|---|---|---|
| 1 | SoftAP 网段固定 `192.168.4.1/24`、DHCP 池 `100–199` | **驱动决定，应用层改不了**：`WifiConfigAP(ssid,psk,channel)` 只收三个参数（`libhardware.a` 里带 DHCP 服务）；候选值 `192.168.237.1`（库内常量串）/`192.168.2.1`（官方 b14 样例实测）/`192.168.5.1`（adapter 死代码）——**仓库内读不到确定值** | 契约 §12.1/§12.3/§12.11/§13 的地址一律「**由板级驱动决定，上板实测后回填；占位 `192.168.4.1`**」；H5 页面必须用相对路径；串口首行打印实际地址；**演示物料/施工单不得写死地址** |
| 2 | 「最多 1 个客户端」可硬限制 | **做不到**：`GetStationList()`/`DisassociateSta()` 在 RK2206 adapter 是空壳 | 契约 §12.3 改成「**建议只连 1 台**」，并写明驱动不提供强制手段 |
| 3 | 服务只 bind `192.168.4.1`，不 bind 全局 | 地址取不到时实现**退化为绑 `0.0.0.0`** 并打告警（`gw_main.c` 有重试上限） | 契约 §12.1 边界 3 写明这条退化路径**是已登记弱点**（该退化下 STA 侧也可达），并保留「窗口期 + AP 口令 + 幂等接口」三条兜底 |
| 4 | 不假设 AP 与 STA 并发 | 仍未实测：实现按**串行**设计（进 AP 断 STA；提交 Wi-Fi 后切 STA；`settle_s=90 s` 后关 AP），`mode=ap_sta` 只是过渡态 | 契约 §12.5 的 `mode` 枚举保留 `ap_sta`，但**不把它当已验证能力**（CAL-12 待上板实测） |

> **待上板实测（唯一必须上板才能收口的一项）**：从串口首行读出实际 AP 地址/DHCP 网段并回填契约 §12.3，同时确认「关 STA→开 AP→提交后切回 STA」在实机上成立。施工单 `rk2206-gateway/施工单-配网上板与本地API验证.md` §0.1 已写清「从哪一行读地址」。

## 裁定理由

- **没有鸿蒙真机**：鸿蒙 App 这条路在答辩现场无法保证能装上、能跑起来；P0 演示必须「当场必然可用」。
- **安卓 APK 依赖用户环境**：`android-app/` 能编出 debug APK，但装不装、能不能装、签名与机型适配都取决于现场环境，不能压 P0 的开场演示。
- **浏览器零依赖**：手机浏览器是唯一不需要安装、不需要权限、不需要适配的消费方；同源 `http://{AP 口地址}/`（占位 `http://192.168.4.1/`）还能免掉鉴权与 CORS（与 §12.1 的四条安全边界一致）。

| 对象 | 影响 |

## 后果

- 契约 §12 的本地 API（`/api/provision/*`、`/api/pair/*`）在 A/B 方案下通用；C 方案下改用云端接口。
- 配对键是实体件：答辩现场必须能「物理长按 3 秒」。首选 GPIO 外接轻触开关（`EX_GPIO_A3`，内部上拉、按下为低、消抖 50 ms），跳线帽短 GND 只作调试兜底。已列入采购清单。
- 网关员工实施前必须先跑 CAL-12，结果写进 t10 交付证据。
- 「连 AP 时手机提示无法访问互联网」是正常现象（§12.11 约束 2、§9 排查表），演示讲解必须提前说明，否则会被当成故障。
