## 0.0 v2.1 修订说明（2026-10-14）

配套评审报告：[docs/评审与验证/计划评审与可行性核查-2026-10-14.md](docs/评审与验证/计划评审与可行性核查-2026-10-14.md)（每条结论附官方依据 URL）。
上机实验步骤：[docs/评审与验证/WS63串口上电自检与AT实验步骤.md](docs/评审与验证/WS63串口上电自检与AT实验步骤.md)（串口没反应的四查表 + `AT+HELP`／一主多从逐步指令 + 结论判定表）。

本次已落实（均为离线可查证的硬事实）：

1. **赛题原文误引已修正**：原 §1/§2 引用的"开发板通过 GPIO/I2C 采集"出自 **赛题三**；赛题四原文只有"开发板实时采集各传感器数据"。§1 那段对账论证已删除。
2. **"强制人大金仓"疑虑已删除**：通知附件 1 明确"可采用本地离线存储方案，云端存储……仅作为创新加分项，不做强制要求" → **MySQL 8 定版**。
3. **华为云接入路线已改正**：小凌派仓库里**没有** `huaweicloud_iotlink`（连 `src/` 目录都没有），实际用 `d2~d7` 自带的 `oc_mqtt`；且样例是**明文 1883、无 TLS**。`IoTMainTaskEntry` 那条坑出自 BearPi Hi3861 文档，不适用，已删。
4. **Push Kit 事实已改正**：官方明确**支持模拟器**；未申请自分类权益时按资讯营销类限**每设备每天 2~5 条** → 申请「服务与通讯」权益由"做不做再说"改为**必做**。
5. **老化时间线已改为 10/30 前上电**（原写 11/10，与 11/02~11/04 录像、11/06 提交冲突）。
6. **串口分配已修正**：UART1 是底板 CH340E 调试串口 → 星闪汇聚改用空闲的 **E53_UART0**；I2C1 引脚矛盾已标注待实物核对。
7. **60GHz 合规措辞、MQ-7 循环电路、USB Host 表述、样例编号（d8 是通鸿非华为云）** 均按官方口径改正。
8. **范围重排**：§3 与 §12 增补 P0/P1/P2 优先级（赛题明确"高阶技术为创新加分项，不做强制要求"）。

## 0.0b v2.2 修订说明（2026-10-16 · 南向架构已定版关闭）

**触发**：2026-10-15 夜 ~ 10-16 上午，在真机（如般微 **E528H-WS63**）上完成了**自研固件的编译、烧录与四项能力验证**。
**证据**：[ws63-firmware/doc/0-通宵成果汇报-2026-10-16.md](ws63-firmware/doc/0-通宵成果汇报-2026-10-16.md) + 同目录 5 份原始串口日志。

### 结论：**总体架构不变（RK2206 网关 + WS63 节点），变的只是"WS63 节点侧固件"**

> 🔴 **重要更正（2026-10-16 10:30）**：本条 v2.2 初稿曾写"南向主控改为 WS63、RK2206 降为可选第二节点、上云改由 WS63 直连"——**这是错的，已全部改回**。
> **架构不变**：传感器接 WS63 节点 → 星闪 SLE → WS63 汇聚 → UART → **RK2206 网关** → 华为云（§6.5、§9.1 原文有效）。
> **真正变的只有一件事**：WS63 **节点侧**从"厂家 XF_AT 固件 + AT 指令"改为 **自研固件**——因为 XF_AT 没有 ADC/I2C 指令，节点读不到传感器。
> WS63 直连华为云（`libmqtt.a` + 官方 demo）**降级为备选/加分项**，不作为定版。

**本轮真机实测的边界（同一份固件、同一次上电，内存 used 103 KB / free 259 KB）**：

> ⚠️ **这些是"外设基元"，不是"传感器"**。逐传感器验证状态见 §1 的表格 —— **一个真实传感器都还没验证过**。

| 能力 | 实测证据（原始日志可查） |
|---|---|
| ADC 6 路采集 | `uapi_adc_init ret=0`，每 2 s 打印 6 路 mV |
| GPIO 读取 | GPIO_00~06 电平打印 |
| 星闪 SLE **服务端** | `sle enable cbk in, result:0` → `server_id:0x1` → `sle announce enable id:0x01, state:0x00` |
| WiFi 协议栈 | 真扫到 6 个热点（`HSIPC-F184B4` / `1702`），含 RSSI/信道/BSSID |
| WiFi 与星闪**共存** | 同一份日志里两者交替输出，互不干扰 |
| MQTT 客户端库 | `libmqtt.a` 随默认构建产出，39 个 `MQTTClient_*` 符号；SDK 自带官方直连华为云 IoTDA 的 demo |

### 由此产生的 8 项修订

1. **总体架构不变**：**RK2206 仍是网关与唯一上云出口**（§6.5、§9.1 原文有效）。**唯一变化是 WS63 节点侧固件**：从"厂家 XF_AT + AT 指令"改为**自研固件**——这才是原阻断问题的解法，**不是把云功能搬到 WS63**。
2. **星闪节点不再依赖 XF_AT 的 AT 指令**：节点与汇聚都跑自研固件，SLE 服务端/客户端都在我们自己的代码里 → §9.2「XF_AT 一主多从官方无文档」的风险**直接消失**（不再靠 AT 拼装）。
3. **上云路径不变**：WS63 汇聚 → UART → **RK2206** → `oc_mqtt` → 华为云（资料已更正为**明文 1883**，见 §6.5）。
   > 旁证（备选/加分，**不定版**）：WS63 SDK 自带官方华为云 IoTDA demo，`libmqtt.a` 已随构建产出（39 个 `MQTTClient_*`）→ 若 RK2206 侧出问题可作退路。
4. **§6.5 已补注**：**RK2206 + oc_mqtt 仍是主路径**（原文保留），仅在开头加注"WS63 直连为备选/加分"。
5. **W0.7 闸门收窄后关闭**：真正待决的"**WS63 节点侧固件路线**"已定（自研固件）；**架构与上云出口不变**。
   ⚠️ 但"真实传感器能不能采"**仍未验证** → 新增 **W0.11（传感器逐一验证）**，见 §1 与 §11。
6. **风险表第 13 条**（XF_AT 读不到传感器）→ **在"固件路线"上已解除**；但**新增风险 21**：真实传感器一个都没验证过。
7. **新增可做项**：AHT20 温湿度（I2C，官方驱动现成）、HC-SR501 人体（GPIO）、干簧管门窗磁（GPIO）、PWM 蜂鸣器（官方驱动现成）。
8. **新增风险 18~21**：星闪无第二对端；MQTT 未实测；XF_AT 被覆盖（救砖包已留）；**真实传感器全部未验证**。

> ⚠️ **仍未验证的边界（不得写成已实现）**：① **I2C / PWM / UART 读 / GPIO 中断 在固件里调用次数均为 0** → AHT20、蜂鸣器、LD6002、433 按键**全部未验证**；② ADC/GPIO 只验过外设本身（引脚悬空），**没接过真实传感器**；③ 星闪只验到"注册+广播"，**从未真正发出过数据**（无第二块板）；④ MQTT 上云未做（本轮**没有**改 RK2206 侧）。
