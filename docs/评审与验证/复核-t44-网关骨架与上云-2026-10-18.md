### F-02（low，契约措辞 vs 实现细节）
§12.9 写「本地 HTTP 侧仍是 `409 code=1605`（App 从 `message` 与网关串口日志区分子原因）」。
实现里 result=10/11（白名单满 / MAC 被占用）在**本地 HTTP** 路径回的是同一个
`409 / 1605 / message="hub_offline"`（`rk2206-gateway/src/gw_prov.c:1073-1098`），响应体内两者不可区分；
能区分的是串口日志与 `gw_prov_last_bind_result()`（`gw_prov.c:1118-1121`）。
**云端命令路径是对的**：`gw_prov.c:1291-1305` 把 `res==10 → GW_PROV_RES_WL_FULL`、`res==11 → GW_PROV_RES_MAC_TAKEN`
分列上抛（v1.3 偏差 #9 的实质要求已满足）。
**要求（二选一，PM/architect 定）**：① 契约改成「本地 HTTP 只保证 1605 大类，子原因看串口日志/云端 `result_code`」；
② 本地错误体 `data` 里补 `hub_result`。P0 演示不受影响（现场只可能撞到 10）。
