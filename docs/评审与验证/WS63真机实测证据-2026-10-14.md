# 证据 · 如般微 E528H-WS63 真机实测（COM14，2026-10-14）

> 这是把「南向架构能不能走星闪节点路线」从"文档推断"升级为"真机实测"的记录。复现脚本在 `ws63-firmware/scripts/`。
> 操作均未写入 flash 配置（没有 `AT+CFGSAVE` 落盘、没有改波特率），只有 `AT+RST` 复位与 RAM 内的 SLE 对象增删。

## 0. 设备身份（实测）

| 项 | 实测值 |
|---|---|
| Windows 端口 | `COM14` = `USB-SERIAL CH340`（另有一个 `COM11` 同名设备但未枚举为可用串口） |
| 波特率 | `AT+IPR?` → `INFO:type:1,speed:115200` ✅ 与官方默认一致 |
| 固件 | `AT+SWINFO` → **`SDK Version:XF_AT-V2.1.13-d`**，`Compiled:[Dec 23 2025]-[15:18:01]` |
| 连接方式 | Type-C 供电+数据 → 板载 CH340 → Windows 串口，115200 8N1 无流控，**CR+LF** 行尾 |

## 1. 实验 0：串口连通性与启动日志

- **复位/上电瞬间会有启动日志**，原文（按 `AT+RST` 抓取）：
  ```
  boot.
  Flash Init Fail! ret = 0x80001341
  verify_public_rootkey secure verify disable!
  verify_params_key_area secure verify disable!
  verify_params_area_info secure verify disable!
  verify_image_key_area secure verify disable!
  verify_image_code_info secure verify disable!
  >> XF AT <<
  ```
  → **`>> XF AT <<` 就是"串口通了 + 固件在跑"的最快判据**：按一下 RST 键，能看到这几行就说明线、驱动、参数都没问题。
  → 更正此前说法：固件**不是"完全不打印"**，而是**只在启动瞬间打印**；进入工作态后不主动输出（与官方文档一致）。
- ⚠️ **待查的异常**：每次复位都出现 `Flash Init Fail! ret = 0x80001341`。原因未定（可能是配置分区未初始化/无保存配置）。**结论不下**，但建议下一步实测 `AT+CFGSAVE=1 → AT+CFG=... → AT+CFGSAVE=0 → AT+RST` 看配置能否持久化。

## 2. 实验 1（关键）：`AT+HELP` 真实指令表

`AT+HELP` 返回 **74 条**指令（去重后）：

```
AT+HELP AT+RST AT+ECHO AT+SWINFO AT+IPR
AT+GPIOCFG AT+GPIORD AT+GPIOWR AT+DBGIO          ← GPIO 只有这三条（数字电平）
AT+SLEENABLE AT+SLEOBJ AT+SLECONNIO AT+SLEADDR AT+SLENAME AT+SLEADV
AT+SLEADVDATASET AT+SLEADVDATAGET AT+SLECONNGET AT+SLECONNSET AT+SLEUUID
AT+SLECONNBYNAME AT+SLESCAN AT+SLESEND AT+SLERECV AT+SLETRAN AT+SLETEST
AT+CFG AT+CFGSAVE
AT+STASTART AT+STASTOP AT+STASCAN AT+STASCANRESULT AT+STACLEARSCANRESULT
AT+STACONN AT+STADISCONN AT+STASTATE
AT+APSTART AT+APSTOP AT+APSHOWSTA AT+APDEAUTHSTA
AT+DNS AT+IFCFG AT+DHCP AT+DHCPS AT+IPERF AT+PING
AT+IPSTART AT+IPSEND AT+IPLISTEN AT+IPCLOSE AT+IPLINKSTATE AT+IPDOMAIN
AT+BLEENABLE AT+BLEOBJ AT+BLEADDR AT+BLENAME AT+BLEADV AT+BLEADVDATASET
AT+BLEADVDATAGET AT+BLECONNGET AT+BLECONNSET AT+BLECONNBYNAME AT+BLESCAN
AT+BLESEND AT+BLERECV
```

**关键词计数（对整张表做全文匹配）：**

| 关键词 | 命中次数 | 含义 |
|---|---|---|
| `ADC` | **0** | 读不了模拟量 → MQ-2/MQ-5/MQ-7 在节点上无法采集 |
| `I2C` | **0** | 读不了 I2C → AHT20 温湿度在节点上无法采集 |
| `PWM` | **0** | 不能调光/驱动无源蜂鸣器 |
| `UART2` / 第二串口 | **0** | 读不了第二路串口 → LD6002B/C 雷达在节点上无法采集 |
| `MQTT` | **0** | 不能直连华为云（与官方结论一致） |
| `SPI` / `DAC` | **0 / 0** | 无 |
| `GPIO` | 7 | 只有 `GPIOCFG/GPIORD/GPIOWR`（数字电平）+ `DBGIO` |

→ **实测结论（不再是文档推断）：XF_AT 节点侧没有 ADC / I2C / PWM / 第二串口 / MQTT 能力。**
→ 计划 §9.2「M1 气体节点走 ADC+I2C、M2/M3/M5 雷达走 UART2、RK2206 远程 `AT+GPIORD` 轮询」**在真机上不成立**；必做传感器（温湿度、气体）应直接接 **RK2206**（路线 A）。
（另一半原因仍来自官方文档：透传期间「暂停指令的解析」，所以也不存在"主机远程给节点发 AT"的通道。）

## 3. 实验 2：SLE 对象容量（一主多从的"对象层"可行性）

**正确的操作顺序（实测得出）**：① `AT+SLEENABLE=1` → ② `AT+SLEOBJ=1,<role>`（0=Slave，1=Master）。

干净状态（复位后）实测结果：

| 步骤 | 命令 | 响应 |
|---|---|---|
| 1 | `AT+SLEENABLE=1` | `OK` |
| 2 | `AT+SLEOBJ=1,1`（Master #1） | `INFO:ID:0` + `OK` |
| 3 | `AT+SLEOBJ=1,1`（Master #2） | `INFO:ID:1` + `OK` |
| 4 | `AT+SLEOBJ=1,1`（Master #3） | `INFO:ID:2` + `OK` |
| 5 | `AT+SLEOBJ=1,0`（Slave #1） | `INFO:ID:3` + `OK` |
| 6 | `AT+SLEOBJ=-1`（删除全部） | `OK` |

补充实测：

- **对象上限 = 8**：超出后返回 `ERR:MAX CNT:8`。
- **SLE 未使能时创建对象 → 普通 `ERROR`**（所以必须先 `AT+SLEENABLE=1`）。
- **对象是 RAM 状态**：`AT+RST` 后清空；复位前 `AT+SLEADDR=<id>`（id 0~7）都返回本机地址 `0,00:01:09:40:E1:4A`，**不能用它判断对象是否存在**（id≥8 才返回 `ERR:INVALID ID`）。
- 踩坑记录：我先在"表已被占满/异常"的状态下连试，得到持续 `ERR:MAX CNT:8` 且 `AT+SLEOBJ=-1` 返回 `ERROR`，**只有 `AT+RST` 能清干净**。

> ⚠️ **更正**：我一度把那条 `ERR:MAX CNT:8` 解读为"固件只允许一个主机对象"。**这个解读是错的**——干净状态下连续 3 个 Master 对象都创建成功。**对象层面，"1 个汇聚板做 Central"没有障碍。**

## 4. 对项目的净结论

| 问题 | 实测答案 |
|---|---|
| 串口/MobaXterm 没显示，是坏了？ | **不是**。板子、CH340、驱动、参数全正常；"没显示"＝(a) 启动日志已滚动过去，(b) 回显默认关闭，(c) 行尾不是 CR+LF |
| 节点能采气体/温湿度/雷达吗？ | **不能**（无 ADC/I2C/UART2）→ 走**路线 A**：传感器接 RK2206 |
| 星闪"1 汇聚 + N 节点"在对象层可行吗？ | **可行**（多 Master 对象实测可建，上限 8） |
| 那星闪还能做加分项吗？ | **能，但每个节点仍需"有人给它发 AT"**：加小 MCU（每个节点一颗），或用**串口自输出传感器 + 节点预先进入循环透传**做 2 板演示（节点断电/复位后要重新配置） |

## 6. 让 WS63"自己读传感器"：三条路 + 两条走不通的路（2026-10-14 联网核实）

### ✅ 路 1：自研 C 固件（真让 WS63 读）

- 芯片硬件够：**ADC=12bit / 6 通道(0~5) / 量程 0.3~3.3V**、**I2C=2 路（仅 Master）**、**UART=3 路**、**GPIO=19**（[海思 ADC](https://docs.hisilicon.com/projects/fbb_ws63/master/hardware-guide/datasheet/peripherals/ADC.html)、[I2C](https://docs.hisilicon.com/projects/fbb_ws63/master/hardware-guide/datasheet/peripherals/I2C.html)、[UART](https://docs.hisilicon.com/projects/fbb_ws63/master/hardware-guide/datasheet/peripherals/UART.html)、[GPIO](https://docs.hisilicon.com/projects/fbb_ws63/master/hardware-guide/datasheet/peripherals/GPIO.html)）；如般微模组规格书也写 3 UART / 2 I2C / 6 ADC。
- SDK：**`fbb_ws63`，Apache-2.0**（Gitee 已迁至 [GitCode](https://gitcode.com/HiSpark/fbb_ws63)），含 `samples/peripheral/adc/adc_demo_inc.c`、`i2c/i2c_master_demo.c`、`samples/bt/sle/`（sle_hello、**sle_sensor_report**、sle_uart、多连接…）；官方明确 **8 路并发、conn_id 0~7、仅星形、不支持 Mesh**，官方网关示例是 1 主连 3 从。
- 环境/烧录（官方口径）：Windows + VS Code + HiSpark Studio 插件（自动装 Python3.11.4 + RISC-V 工具链），`fbb build ws63-liteos-app` → `output/ws63/fwpkg/.../<target>_all.fwpkg`，BurnTool 串口烧写（921600，按 RST 进打断）。
- ⚠️ 风险（必须认）：**SDK 的 vendor 目录里没有如般微/天工聚创这块板**；如般微官方明确"不再对 SDK 提供支持，仅对 XF_AT"；**全网查不到有人在这块板上烧过自研固件**。另需确认：模组 flash 容量与分区（现有资料未写）、`Flash Init Fail! ret = 0x80001341` 的影响、ADC/I2C 是否已引出（DIP-30 规格书显示 IO07~IO12=ADC0~5、23/24 脚=I2C1，**已引出**）。
- 工时判断：2~3 周做出"1 汇聚 + 1~2 节点"**约 40~50% 把握**。**硬闸门：3 天内能否在这块板上烧进一个自编译 helloworld**；做不到立即退回路 2。

### ✅ 路 2：每个节点加一颗小 MCU，WS63 只当"无线串口电台"（**最稳、最快、不改 WS63 固件**）

- 结构：`传感器 → MCU(ADC/I2C/UART) → 串口 → WS63(透传) → 汇聚 → RK2206`。
- MCU 建议：**合宙 Air001**（12bit ADC + 2×USART + I2C，开发板 10 元级，资料最全）；或 **CH32V003**（<0.5 元/片）；ESP32-C3 芯片 ¥7.26。
- 关键工程点：**MCU 不能与板载 CH340 抢同一路串口**。推荐用 `AT+CFG` 把 AT 数据通道切到 **UART1（板子 23/24 脚）** 并 `AT+CFGSAVE` 存盘，之后 MCU 独占 UART1、UART0+CH340 留给电脑调试（乐鑫官方就是"UART0 下载/日志、UART1 走 AT"这种分工）。备选：跳线/0Ω 断开 CH340、TX 串二极管或 1k 串阻。
- 透传时序有成熟范式可抄：进入循环透传后**暂停 AT 解析**，退出必须单独发 `+++`（乐鑫官方给了静默时序要求：`+++` 前后各 ≥20ms 静默，退出后 ≥1s 再发 AT）。

### ✅ 路 3：不改固件、不加 MCU —— 让 WS63 只当"无线串口延长线"（**仅适合 2 板演示**）

- 用**自带串口输出**的传感器，字节流原样透传到 RK2206 解析：海凌科 **LD2410C**（24G 人体存在，UART TTL，¥21）、**LD6002/LD6002B**（60G，UART，¥58~77）、Winsen **MH-Z19C**（CO₂）、**ZE07-CO**（CO，¥66）。
- 限制：节点仍需"有人把它配置进循环透传"——只能在台面上用电脑配一次，**断电/复位后要重配**，因此只适合演示，不适合当系统。

### ❌ 走不通的两条（别再等）

1. **指望"带 ADC/I2C 的 AT 固件"**：XF_AT 实测 74 条指令中 ADC/I2C/PWM/UART2 命中 0；**海思官方 WS63V100 AT 固件也没有** ADC/I2C（只有 `AT+SETIOMODE/GETIOMODE/GPIODIR/WTGPIO/RDGPIO`、`AT+SETUART`），且**没有 GPIO/ADC 自动上报**配置项。→ 等固件升级解决不了。
2. **指望"主机远程发 AT 指令让节点读引脚"**：透传期间固件「暂停指令的解析」，没有这条通道（官方 AT 指南原文）。
