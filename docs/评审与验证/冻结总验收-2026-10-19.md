## 1. 一键命令

```bash
bash tools/freeze-check.sh --quick     # 日常：不构建、不起容器（24.8 s）
bash tools/freeze-check.sh --full      # 冻结前：含构建与容器（261.7 s）
```

退出码：`0` 没有硬项失败（skip 不计失败）／`1` 有硬项失败（末行列出失败项）／`2` 用法或环境错误。
汇总口径（t119 起）：**有硬项被跳过时不再打印「所有硬项通过」**，改为逐条列出「硬项未跑 N 个：项名 + 原因」，
再写清「其余 M 个硬项通过」；环境门跳过会额外提示「必须补跑后才可当冻结依据」，`--quick` 的模式差异跳过
则提示「冻结前用 `--full` 覆盖」。rc 语义不变（跳过仍不算失败）。
`--list` 只打印计划；`--only id,id` 只跑指定项；`--no-cleanup` 跑完不停容器。

## 2. 两种模式差异

| | `--quick` | `--full` |
|---|---|---|
| 定位 | 日常自检（改完代码随手跑） | 冻结/提交前 |
| 是否构建 | 否 | 是（网关镜像、鸿蒙 HAP） |
| 是否起容器 | 否 | 是（`server/` 的 db+api，跑 pytest；结束自动 `docker compose stop`） |
| `e2e` 项 | `run_e2e_host.sh --dry`（只验装配） | 真跑端到端（起 mock + 服务器容器） |
| `pack` 项 | `--selftest`（打包器正/负向自证） | 真打一个试跑包 + 对包 `--check-only` 复扫 |
| 实测耗时 | **24.8 s** | **261.7 s** |
| 项数 | 8 跑 + 5「本模式不跑」 | 15 全跑 |

两种模式共用同一份 `ITEMS` 表（每项带 `quick`/`full` 两组命令），不存在两套逻辑。

## 5. 已知环境门（会记 SKIP 而不是 FAIL）

- 本机 **没有** `gcc`/`clang`/`ffprobe`/`rar`/`unrar`/`zip`/`7z`；`hvigorw` 不在 PATH（但 DevEco CLT 可用，
  `build-hap.sh`/`run-selfcheck.sh` 实测能跑通 → 鸿蒙两项在 full 里是**真跑**，不是环境门）。
- 网关两项（`gw_host`/`gw_compile`）走构建容器 `hmprogram-rk2206-build`；容器没起时脚本打印
  「容器 … 没在运行：docker start …」并 rc=2 → freeze 判 **SKIP**（环境门），不算失败。
- Docker 守护进程掉线（WSL 休眠后常见）→ 命中 `Cannot connect to the Docker daemon` → 同样记 SKIP。
- 冻结前若出现 SKIP，**要人工确认能不能接受**（末行会写「跳过 N 项」）。

## 6. 实现过程中发现并修掉的三个问题（自证价值）

1. **`--check-only` 参数顺序**：打包器的 `--check-only` 是「取一个值」的开关（`--check-only ARCHIVE`），
   写成 `--check-only --allow-missing-materials <包>` 会把包路径当成多余位置参数 →
   `unrecognized arguments`、rc=2。修成 `--check-only <包> --allow-missing-materials`。
2. **产物写进仓库会自我污染**：freeze 的日志/JSON 原本写在 `tools/test/reports/`，而同一轮里的
   `repo_health` 会扫到这些日志（含身份字样）→ 体检计数 460 → 3410（自我指涉：`repo_health` 的日志
   还包含它自己的扫描结果）。改为默认写 `/tmp/hm-freeze/`，计数回到 460。
3. **收尾步骤签名不匹配**：`cleanup` 项用 4 个位置参数调 `_run_steps`（该函数只收 3 个）→ 首次
   `--full` 在最后一步 `TypeError` 崩掉（所有验收项其实已跑完，只有收尾没执行）。
   修好后重跑即 rc=0。

> 这三个都是「第一次真跑才暴露」的问题——正是「一条命令」相对「6 个脚本各跑一遍」的价值：
> 顺序、收尾、产物落点都变成可复现的一件事。
