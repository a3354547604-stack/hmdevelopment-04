## 5. NOTES（不构成缺陷）

- **N-01｜卡面"未灌数据 `1/7 rc=1`"口径仍与实际不符**：干净卷实测是 **`0/7` rc=1**（整库清空 → 登录即失败）。`server/README.md:99` 已如实写明"条数取决于库里还剩什么：整库清空 → `0/7`；只清业务数据、账号与设备仍在 → `0/7`；只删读数与活动、告警还在 → `2/7`。别把它当固定值" → **建议改卡面口径，实现侧无需动**（与 t89 N-01 同一条）。
- **N-02｜`demo-check.sh` 与 compose 项目名耦合**（t49/t88 未涉及，属工具使用面）：脚本用 `docker compose -f docker-compose.yml ps -q api` 定位容器、且不接受 `-p`/`-f` 追加参数；配合 `server/docker-compose.yml` 的 `name: hmprogram` + 硬编码 `container_name`，**非默认项目的隔离复核**必须显式给 `COMPOSE_PROJECT_NAME` + 环境变量（本轮做法），否则会得到 `rc=3「api 容器没在跑」`——这是环境耦合，不是缺陷。现场按文档 `cd server && docker compose up -d` 走不受影响。
- **N-03｜冻结钟复现要点**：`up -d --force-recreate api` 之后再 `docker cp` 插件、再 `restart`（顺序错了插件会随旧容器一起消失，本轮踩过一次：`/api/time` 仍回真实钟）；插件只在设置了 `T89_FAKE_NOW_MS` 时生效，用 `/api/time` 自证生效后再采信后续证据。
