## 4. Findings

### F-01（medium）施工单/前置清单的自检命令照抄即报错，用户无法得到「无输出」这个成功标志

- `server/deploy/部署施工单.md:86`：`docker compose -f docker-compose.prod.yml port db        # 应无输出（没有映射）`
- `server/deploy/IoTDA回调前置清单.md:16`（「MySQL 不外露」行的验证方法）：`docker compose -f docker-compose.prod.yml port db` 无输出
- 实测：该命令缺 `PRIVATE_PORT` 参数 → `EXIT=1` + `requires at least 2 arg(s), only received 1`；补成 `port db 3306` 后输出是 **`:0`**（不是空）。
- 修正（两处一起改，给用户可直接粘贴的形态）：
  ```bash
  docker compose -f docker-compose.prod.yml port db 3306   # 期望输出 :0（= 没有宿主机映射）
  docker compose -f docker-compose.prod.yml ps db          # PORTS 只有 "3306/tcp"，没有 0.0.0.0:/127.0.0.1: 前缀
  ss -ltn | grep 3306                                      # 无输出 ✓（这条原样就对）
  ```

### F-02（medium）db healthcheck 不校验凭据，凭据类故障时 db 仍报 healthy，与施工单的排查顺序矛盾

- `server/docker-compose.prod.yml`（db.healthcheck）：`mysqladmin ping -uroot -p"$MYSQL_ROOT_PASSWORD" --silent` ——`mysqladmin ping` 只要服务端有响应就返回 0，**口令错也判 healthy**。
- 实测（隔离探针栈）：把 `.env` 的 `MYSQL_ROOT_PASSWORD` 改成与卷内不一致的值并重建 db → `docker inspect` 仍是 `health=healthy`；同时 api 侧凭据错误会 `(1045, "Access denied for user 'eldercare'@…")` 反复重启。
- 与文档的冲突：`部署施工单.md:77` 的失败对策是「`api` 一直 starting / `/api/health` 里 `db:"down"` → 先看 db 是否 healthy」。凭据不匹配时 **db 显示 healthy、api 起不来**，这条指引会把人带偏（§3.5 的坑 1 正好落在这个组合里）。
- 修正建议（二选一）：① healthcheck 改为带鉴权的探测，例如 `test: ["CMD-SHELL", "mysql -uroot -p\"$MYSQL_ROOT_PASSWORD\" -e 'SELECT 1' --silent"]`（凭据错 → unhealthy → api 不会启动）；② 或在施工单 §3 的失败对策里补一句「db healthy 只说明 MySQL 起来了，不代表 api 的凭据对；出现 1045 时按下面第 4 条处理」。

### F-03（low）在线清库恢复期间若有写入，行数比对会把「真恢复成功」判成不一致

- `server/tools/db-restore.sh` 的 `compare_rows` 是恢复后立刻比对；prod compose 的 `SCHEDULER_ENABLED` 默认 1、webhook 也可能在窗口内写入 → 比对可能多出几行而退出码 4。
- 我的实测窗口内没有漂移（20 s 内 417 → 417），所以无法主动复现；属 robustness 提示。
- 修正建议：施工单 §5/§7 的演练命令前加一条 `docker compose -f docker-compose.prod.yml stop api`（演练完 `up -d`），或在 `db-restore.sh` 里加 `--quiesce`（停 api → 恢复 → 比对 → 起 api）。

### F-04（low）`.env.example` 说「部署机必填 5 项」但编号只列了 4 项

- `server/.env.example:5-10`：编号 1) `MYSQL_ROOT_PASSWORD / DB_PASSWORD`、2) `JWT_SECRET`、3) `WEBHOOK_TOKEN`、4) `PUBLIC_HTTP_PORT` —— 标题写 5 项。修正：拆成 5 条编号（两个口令各占一条），或在标题后注明「（第 1 条含两个口令变量）」。

### F-05（info）缺必填变量时，**任何** compose 子命令都报插值错误

- 实测 `docker compose … --env-file <缺 JWT_SECRET 的 env> config` → `EXIT=15`；同理 `ps`/`port` 也一样。用户若先跑 `ps` 会先撞见这条错误。
- 建议在施工单 §3 的开头加一句「本单所有 `docker compose -f docker-compose.prod.yml …` 命令都必须在 `server/` 目录下、且 `.env` 已填好，否则先报 `required variable … is missing a value`」。
